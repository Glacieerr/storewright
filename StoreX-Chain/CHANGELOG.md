### Added · 新增

- **End-to-end supply-chain simulation** of one comprehensive store: ocean freight, an intercontinental block train, air cargo, domestic and cross-border long-haul trucking, regional fresh produce, a central bakery, a distribution center, the delivery fleet and the customers; three generations of the chain compared on the same simulation. · **一家综合店的全链路仿真**：海运、洲际铁路班列、空运、国内和跨境长途公路、区域生鲜、中央面包房、配送中心、配送车队和顾客；三代方案用同一个仿真比较。
- **Dispatch board** sharing the clock with the 3D scene. · **调度台**，和三维场景共用一个时钟。
  - A Gantt chart with one row per resource (berths, port rail shuttles, block trains, flights, long-haul trips, regional fresh inbound, the 38 dock doors of the distribution center, every vehicle, the store's 4 receiving doors, online delivery); drag to retime or reassign. · 甘特图一行一个资源（泊位、港口铁路接驳、洲际班列、航班、长途车次、区域生鲜进货、配送中心的 38 樘月台门、每一辆车、门店的 4 个收货口、线上配送），拖动即改时刻或改派。
  - A solve page that turns door assignment, vehicle dispatch and replenishment batches into optimization problems (branch and bound, with a proof of optimality or a bound), explains the result in plain words, and applies it in one click; shift staffing from hourly workload. · 「求解」页把排门、派车、补货批量变成求解问题（分支定界，证明最优或给出离最优的上限），用大白话说明结果，一键套用；按每小时的作业量排三班的人。
  - A job list with issue detection and one-click fixes or automatic scheduling, an editor for the regular plans with an 18-week re-simulation and comparison, and selection linked with the 3D view. · 作业清单和问题检查（能修的一键修，也可以全部自动排程）；常规计划编辑，改完重新仿真 18 周并逐项比较；选中作业和三维联动。
- **Closed-loop twin**: a minute-step field simulation with disruptions the plan does not know about; the twin sees them only through sensing data, estimates delays, cargo temperatures and store inventory, re-forecasts every five minutes and issues recommendation cards with options for a dispatcher to approve. · **闭环孪生**：一分钟一步的现场仿真会出计划不知道的状况；孪生只通过感知数据知道发生了什么，估计延误、货物温度和门店库存，每 5 分钟推演一次，出建议卡供调度员批准。
- **AI-assisted management**: a duty assistant (rules plus an intent classifier, logistic regression with naive Bayes kept for comparison; no large language model by default), approvals, a layered KPI board, forecasts, daily review with root-cause analysis and anomaly detection, disruption what-if, guards and a grounding policy; an evaluation set (`npm run assistant:eval`) and four blind test sets, each written by a separately launched AI writing agent that never saw the code. · **AI 综合管理**：值班助手（规则加意图分类器：逻辑回归，朴素贝叶斯留作对比；默认不用大语言模型）、审批、分层 KPI 看板、预测、每日复盘（根因分析、异常检测）、突发情况推演、守卫和依据约束；评测集（`npm run assistant:eval`）和四套盲测（各由一个单独启动、没看过代码的 AI 出题代理写）。
- **Optional large-model mode for the duty assistant** ([docs/06-llm-option.md](docs/06-llm-option.md)): off by default; a cloud provider through its official SDK or a local model server with a `/v1/chat/completions`-compatible endpoint, set by environment variables; available in the twin server, on the command line (`npm run assistant -- "问题" --llm`) and through the web panel's engine switch (needs a local twin server started with `--allow-origin`). An optional comparison run (`npm run assistant:eval -- --llm`) writes a separate report. Not yet run against a real model in this project. · **值班助手可选的大模型模式**（[docs/06-llm-option.md](docs/06-llm-option.md)）：默认关；可以接云端提供方（用它的官方 SDK）或本机提供 `/v1/chat/completions` 兼容接口的模型服务，用环境变量设置；孪生服务、命令行（`npm run assistant -- "问题" --llm`）和网页面板的「引擎」切换都能用（网页要连本机启动、加了 `--allow-origin` 的孪生服务）。模型只调只读的查询工具；提议照样先过规则表、再由人确认；有找不到出处的数字或者出错时退回内置回答；英文问就用英文答。可选的对照评测（`npm run assistant:eval -- --llm`）另写一份报告。还没有在本项目里用真实的模型跑过。

- **Flow planning, the store site and the warehousing centres**: flows by product family; the store's parking lot, instant pickup and receiving yard on a shared truck-yard engine, with a conflict-free car planner; a port (container freight station, bonded and inspection areas, depot, quay waiting lanes), an airport cargo terminal and a logistics park, described by one day plan shared by the 3D view and the assistant. · **货流规划、门店场地和仓储中心**：按商品族规划货流；门店的停车场、即时取货和收货场用共享的卡车场站引擎，车辆按无冲突的计划停放；港口（集装箱货运站、保税和查验区、堆场、岸边等候车道）、机场货站和物流园，用一份三维和助手共用的当日计划描述。

### Changed · 变更

- The part declares its own dependencies (`three`) and development tools in `package.json`, with the version (0.2.0), the Node.js version (22 or later; the repository's `.nvmrc` and CI use 22) and repository links, and is now an npm workspace of the repository: `npm ci` at the root, then `npm run <script> -w StoreX-Chain`. · 依赖（`three`）和开发工具都在 `package.json` 里声明，并写明版本（0.2.0）、Node.js 版本（22 以上；仓库根目录的 `.nvmrc` 和 CI 都用 22）和仓库链接；本部分成为仓库根目录的 npm 工作区：先在根目录 `npm ci`，再 `npm run <脚本> -w StoreX-Chain`。
- CI runs type checking, ESLint, the unit tests, the production build and `docs:check` for this part on every push and pull request. · CI 在每次推送和 pull request 时跑本部分的类型检查、ESLint、单元测试、生产构建和 `docs:check`。

### Security · 安全

- **The twin server is local by default**: it binds 127.0.0.1; a non-loopback `--host` needs `--token` (or `STOREX_TOKEN`), otherwise the server refuses to start unless `--insecure` is given; with a token, approve, reject, command, control and WebSocket commands require it (`Authorization: Bearer`, `x-ingest-token`, or `?token=` on the WebSocket URL / a `token` field); no wildcard CORS (optional `--allow-origin` list) and other browser origins get 403; JSON bodies are capped at 64 KB (413), invalid JSON and non-numeric parameters get 400; `server/client.ts` reads `STOREX_TOKEN`; 5 new security tests. · **孪生服务默认只听本机**：监听 127.0.0.1；`--host` 不是本机时必须设 `--token`（或 `STOREX_TOKEN`），否则拒绝启动，除非加 `--insecure`；设了密钥以后，批准、否决、指令、控制和 WebSocket 指令都要带（`Authorization: Bearer`、`x-ingest-token`，或 WebSocket 网址上的 `?token=` / 消息里的 `token` 字段）；不回通配的跨域头（可选 `--allow-origin` 列表），别的浏览器来源回 403；JSON 请求体上限 64 KB（413），不合法的 JSON 和不是数的参数回 400；`server/client.ts` 读 `STOREX_TOKEN`；新增 5 个安全测试。
