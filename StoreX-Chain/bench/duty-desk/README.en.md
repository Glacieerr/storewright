# Duty-Desk Bench dataset

[中文](README.md) · Method, leaderboard and every wrong answer: [docs/benchmark.en.md](../../docs/benchmark.en.md)

320 Chinese questions to a supply-chain operations duty assistant, in four sets of 80, with the expected intent, main tool, behaviour and the asker's role; plus everything an outside system needs to answer them at the same simulated moment. Synthetic data from a personal open-source portfolio project; not affiliated with any retailer or company.

## Files

| Path | What it is |
|---|---|
| `data/blind1.jsonl` … `data/blind4.jsonl` | The four sets (B01–B80, C01–C80, D01–D80, E01–E80), one item per line. Format: `schema/item.schema.json`. |
| `data/dev.jsonl` | The 176 standard questions used during development (reference only: their fact checks are code, and they use several moments). |
| `schema/item.schema.json` | JSON Schema of an item. |
| `schema/prediction.schema.json` | JSON Schema of one line of a prediction file. |
| `context/tools.json` | The 31 tools the assistant can call: name, description, JSON-Schema parameters, kind (`read`, `compute`, `proposal`). |
| `context/snapshot.json` | Results of the common read-only tools at the evaluation moment (text in Chinese plus structured data). |
| `examples/builtin.predictions.jsonl` | The built-in assistant's own predictions in the submission format (scoring it reproduces the built-in row exactly). |
| `results/*.json` | Scored results of each system (per set, per measure, per item). |
| `site/index.html` | Static bilingual results page, generated from `results/`. |

All files are regenerated by `npm run bench -- export` (data, schemas, context, example) and `npm run bench -- run --all` / `report` (results, page), run from `StoreX-Chain/`.

## Item

```json
{"set":"blind4","id":"E03","question":"M3现在跑哪了","role":"dispatcher","pair":"S1",
 "expect":{"intent":"vehicle","tools":["get_vehicle"],"behavior":"answer"},"note":"M3 = M03."}
```

- `role`: viewer, dispatcher, manager (station manager) or regional (regional manager); it sets what the asker may approve.
- `pair`: items with the same value are asked in order in one conversation.
- `expect.behavior`: `answer`, `clarify` (ask one question back), `decline` (out of scope), `refuse` (refuse to skip confirmation or approval), `proposal` (an approve/reject proposal for a person to confirm).
- `accept`: alternatives the author marked as also fine, kept only where their condition holds at the evaluation moment.
- `note`: the author's note (English).

## Data card

- **Provenance.** Each set was written by a separately started AI writing agent (a general-purpose language-model agent) that worked only from a short written description of the assistant and was not allowed to open the repository, the training corpus, the standard questions or the other sets. Items are verbatim except one neutral wording change in B69.
- **Size and coverage.** 4 × 80 items; each set covers all 36 intents, has 5 two-turn conversations, and mixes roles (roughly 60% dispatcher, 25% station manager, the rest regional manager and viewer) and behaviours (about 53 answers, 10 ask-backs, 8 declines, 4–5 refusals and 3–5 proposals per set).
- **Evaluation moment.** Default region, simulated day 86, 05:01 (one minute after the first lateness card), with synthetic warehousing-hub plans; two recommendation cards are pending, one vehicle is late on the road, and there is no truck M06.
- **Intended use.** Comparing duty assistants (rule-based, small-model, LLM-based) on understanding requests and following approval rules in a logistics operations setting; teaching how to evaluate an assistant honestly.
- **Not for.** Measuring answer prose quality; real operational decisions; any claim about real companies.
- **Contamination.** Sets 1–3 have been studied and are regression sets; set 4 is still blind (its first run is the official score). Now that the data are public, future models may have seen them.
- **Limitations.** Small sets (±10 percentage points per set at 95%), one synthetic moment, Chinese only, labels applied by one maintainer, questions written by language-model agents.
- **Licence.** CC BY 4.0 (questions, schemas, context, results, page). The code that scores them is AGPL-3.0-only.

## Score a prediction file

```bash
npm run bench -- score --pred my.jsonl --name my-bot --save   # prints the table and every miss; saves results/my-bot.json
npm run bench -- report                                         # adds it to docs/benchmark*.md and site/index.html
```
