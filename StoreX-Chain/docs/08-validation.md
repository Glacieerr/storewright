# 对照验证：和理论、精确解、经典算法、同类工具比

[English](08-validation.en.md)

> 本项目与任何零售商、企业无隶属关系；数据全部是合成的，模型没有用真实运营数据校准，不用于真实的生产决策。

这一页回答一个问题：**仿真和调度台里用到的算法、公式，有多可信？** 做法是拿它们去和「答案已知」的东西比：

| 比什么 | 和谁比 | 结论在哪 |
|---|---|---|
| 门店配送线路（节约法，`src/sim/routing.ts`） | 同一个例子的**精确最优解**，以及常见的**最近邻贪心** | 第 1 节 |
| 补货分配的满足率公式（`src/network/allocate.ts`） | **蒙特卡洛模拟**和教科书的**标准正态损失函数**值 | 第 2 节 |
| 调度台的三个求解器、多门店网络规划（都声称精确最优） | **穷举所有可能** | 第 3 节 |
| 值班助手 | 同一套盲测题上的**其他系统**（关键词规则、最近邻检索、朴素贝叶斯，以及用户自己接的大模型） | [值班台基准](benchmark.md) |
| 整体定位 | 12 个**同类开源项目** | 第 5 节 |

## 怎么复现

```bash
cd StoreX-Chain
npm run validate              # 跑全部对照（几秒钟），打印摘要
npm run validate -- --write   # 同时写 bench/validation/ 和本页自动生成的部分
npm run validate -- check bench/validation/cvrp/sx-cvrp-n10-001.vrp 你的解.sol   # 核对别的求解器的结果
```

除了用时，所有数字都是确定的（随机例子的种子固定）。用时是作者电脑上的参考值，每次运行略有不同。

### 验证发现并修正的问题

- **排门求解器多用一樘门**（2026-11-07）：第一次跑这套验证时，「月台门：收发门错用和用门最少」在 200 个例子里有 3 个和穷举不一致——收发门错用一样，但多用了一樘门。原因是有一类门不够时走的「挪车」快路证明不了门数最少，却直接返回了（求解器当时如实标了「不保证最优」）。改成证明不了时继续做精确搜索、取两者中更好的以后，200 个例子全部和穷举一致；真实一天的调度台、值班助手的评测结果都没有变化（默认设施下走的是另一条已证明最优的快路）。

## 6. 还没有验证的（如实写）

- **交通流的精度**：区域里的车流是简化模型（区域按 1/10 压缩），没有和 SUMO 等专业交通仿真对比过。要做的话需要安装 SUMO（下载较大），可以把同一段路网和车流导出后比较通行时间和排队长度。
- **用真实数据校准**：数据是合成的，参数按公开标准取（见各模块的注释和 [docs/01-planning-report.md](01-planning-report.md)）。下一步可以用公开的年度统计数（港口吞吐量、航空货量等）做粗校准并写明方法。
- **和其他路径求解器的实测对比**：第 4 节的例子文件已经是标准格式，但还没有在本机装 VROOM、OR-Tools 等工具跑过（需要额外下载）。
- **可选的大模型模式**：代码和操作指引都在（[docs/06-llm-option.md](06-llm-option.md)），没有用真实的模型账号跑过基准。
