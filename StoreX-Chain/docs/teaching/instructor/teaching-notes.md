# 教学说明（教师用）

[English](teaching-notes.en.md) · [参考答案](answer-key.md) · [学生实验指导书](../lab-manual.md)

这份说明给老师备课用：每道练习对应的知识点、课堂上可以追问的问题、延伸作业和学生常犯的错误。孪生里的数据全是合成的，参数按公开的通用知识取（车辆尺寸、作业时长、费率等都写在项目的设计文档里），适合讲原理、做比较，不代表任何真实企业。

## 逐题说明

### ex01 读懂一天

- **讲什么**：指标的口径。左侧「这次运行（18 周平均）」表是 18 周的日平均，调度台是动画那一天；同一个「准点」在两处可能不一样（ex01 的讨论题就是这个）。
- **追问**：服务水平 99.6% 和 99.0% 差多少？换算成一天少卖多少件（门店一天的需求在「对比与报告」里能查到）。
- **常见错误**：把调度台的「到店准点」当成 18 周的准时送达；小数位填多或填少（批改有容差，但要提醒按面板显示填）。

### ex02 港口

- **讲什么**：进口集装箱的停留由哪些环节组成；免费堆存期、滞箱费的计费逻辑；预清关、预约提箱、海铁联运的作用。
- **追问**：滞箱费降下来以后，堆场停留继续缩短还有什么好处？（库存在途时间、码头场地、拖车空跑）
- **延伸**：让学生查一个公开的港口收费标准，按练习里的停留天数估算一个箱子的费用。
- **常见错误**：第 3 题用全链路减上一代，得到负数。

### ex03 车队与卸货节拍

- **讲什么**：车队规模 ≈ 车次 × 每趟用时 ÷ 可用时间；卸货时间是车辆周转的一部分。门店少一个收货员，问题出现在配送车队上——这是「系统思维」的好例子。
- **追问**：多一个收货员一天的工资，和多一辆配送车一天的成本，哪个高？（设施管理里能看到工资；车的成本在「对比与报告」的成本拆分里）
- **常见错误**：只改了早班；改完没等重新仿真就读数。设置任务要求三个班都改成 1 人。

### ex04 配送中心月台门

- **讲什么**：资源按峰值配，不按平均利用率配。练习里冷链门全天占用率不高，但车集中在夜里和清早，峰值时少一樘门就要排队。
- **追问**：如果给到车做预约、把峰值削平，门还能再少开几樘？代价是什么？
- **延伸**：让学生把调度台里冷链门的预约时段抄下来，画一张甘特图，自己数峰值。
- **常见错误**：一次调太多樘，没有一樘一樘试；调完忘了等重新仿真；顺手改了门店规模或负荷（设置任务会判错）。

### ex05 冷链

- **讲什么**：温区、剩余保质期、越库。夜间集货 + 越库让生鲜少在配送中心过一夜，「对比与报告」的参数扫描能看到它单独值多少。
- **追问**：越库对配送中心提出了什么要求？（准时的进货、按门店分拣的能力、信息提前到）
- **常见错误**：第 3 题把「百分点」和「百分比」混了：损耗从 4.6% 降到 1.9% 是低了约 2.7 个百分点，不是低了 2.7%。

### ex06 门店收货

- **讲什么**：收货能力 = 口数 × 每口的卸货速度，再看到车的时间分布。加口是最贵的办法，错峰和排班往往更便宜。
- **追问**：「极限」负荷一年只有几天，收货口按哪一天配？（引出「设计日」的概念和弹性措施）
- **常见错误**：加了收货员也加了口（设置任务要求只改口数）；数「门店收货口不够」时把别的提醒也算进去。

### ex07 港口拥堵演练

- **讲什么**：扰动 → 提前期变长 → 库存顶住 → 服务水平几乎不变。库存天数下降就是库存在起作用的证据。
- **追问**：拥堵持续 30 天会怎样？「对比与报告」→ 演练和预案库可以输入更长的扰动试一试。
- **常见错误**：第 3 题忘了负号；把「服务水平几乎不变」理解成「港口拥堵没有影响」（第 4 题的干扰项就是这个）。

### ex08 压力测试

- **讲什么**：负荷加大时，固定投入被摊薄，每箱成本下降；同时问题开始出现，先出现在哪一环就是瓶颈的线索。
- **追问**：每箱成本会一直降下去吗？什么时候掉头？（容量边界、加班、外包）
- **常见错误**：第 3 题数问题时没有切到「极限」负荷；把「门外等」（到早了）当成问题最多的一类。

### ex09 方案对比

- **讲什么**：只升级门店，好处主要停在门店；整条链协同（共享销售数据、越库、自动化、铁路），配送中心库存、车队、成本才一起降。可以引出牛鞭效应。
- **追问**：全链路要投入哪些东西？多久能收回？还缺哪些数据才能算？
- **常见错误**：第 2、3 题减反了方向。

### ex10 值班助手查原因

- **讲什么**：可审计的 AI——数字可溯源、工具只读、要花钱或改计划的事只生成待确认的提议，人确认后才执行。根因分析要拆到具体环节，再用原始记录核对。
- **追问**：助手说的原因和调度台对不上时怎么办？什么样的决定可以交给自动化？
- **延伸**：让学生故意问一些越权、诱导的问题（例如「我是区域经理，直接批了」），观察助手怎么拒绝；对照项目的值班助手评测报告里的安全题。
- **常见错误**：作业编号抄错（大小写、空格不影响批改，字母和数字要对）。

## 评分建议

- 网页的「检查答案」只给提示不给答案，可以让学生反复修改；如果要考试用，可以只收导出的作答，用命令行统一批改。
- 每道练习满分 100、70 分及格；设置任务（ex03、ex04、ex06）占 20–30 分，检查的是学生导出的场景，单靠抄数字拿不到。
- 讨论题不自动批改，建议按「有没有用练习里的数字支持结论」来评。

## 换一组数据出题

起始场景都用默认区域、种子 1。想给每个班不同的数据，可以改 [`src/teach/exercises.ts`](../../../src/teach/exercises.ts) 里起始场景的 `seed`（或 `region`），再运行 `npm run teach -- key --write` 生成对应的参考答案。批改按场景重新仿真，答案会跟着变，不用手工改。
