## [0.2.0] - 待发布（首次推送时填写日期）

The first public version of this part (tag `storex-v0.2.0`). It sums up the rounds of work so far; the date is filled in at the first push. · 本部分的首个公开版本（标签 `storex-v0.2.0`），汇总到目前为止几轮工作的内容；日期在首次推送时填写。

### Added · 新增

- **The 2030 store design.** · **面向 2030 年的门店方案。**
  - A goods-to-person cube storage in the backroom for about 3,600 packaged products: robots bring totes to the pick stations. · 后仓的立体货格仓：约 3,600 种包装商品的线上订单由机器人把货箱送到站台。
  - Fresh pickers with smart carts for fresh, frozen and bulky items, merging with the cube-storage items through a conveyor. · 生鲜拣选员推智能推车拣生鲜、冷冻和大件，经输送线和货格仓的商品合流。
  - Locker-loading robots for temperature-zoned pickup lockers, and tote carts to the drive-through pickup window. · 装柜机器人把订单放进分温区自提柜，送框小车把订单送到免下车取货窗口。
  - Smart shelves and inventory robots that detect gaps, and replenishment robots that bring cases to the shelf. · 智能货架和盘点机器人发现缺货，补货机器人把箱子送到货架前。
  - Checkout-free lanes with vision-assisted self-checkout, rooftop solar with storage, AI fresh ordering with dynamic markdowns. · 免排队通道和视觉辅助自助结账；屋顶光伏和储能；生鲜 AI 订货和动态降价。
  - One multi-skilled store operator role, and a store digital twin that forecasts workload, builds schedules and dispatches tasks, with a fallback to floor picking when the cube storage is down. · 一个多技能的门店作业员岗位；门店数字孪生预测工作量、排班、派任务，货格仓停机时降级到卖场拣货。
- **Equipment sized by sweep experiments** (the same days, one change at a time), for opening day and for 2030. · **设备数量用扫描实验确定**（同一组日子，每次只改一项），分开业和 2030 年两档。
- **Comparison with the previous generation** (Storewright) on the same discrete-event simulation engine, with the same orders, customers and products; stress cases for 25% more orders and a two-hour cube-storage outage. · **和上一代（Storewright）逐项对比**：同一个离散事件仿真引擎、同样的订单、顾客和商品；另有订单多 25%、货格仓停机 2 小时两种压力情景。
- **A store simulator in the browser** with a 2D top view and a 3D twin on the same trace and clock: preset views, exterior and cut-away modes, and export of the current store as glTF (.glb). · **浏览器里的门店模拟器**：二维俯视图和三维孪生共用同一份仿真轨迹和时钟；有预设视角、「外观 / 剖面」切换，可以把此刻的门店导出成 glTF（.glb）。
- **Documents**: planning report, generation comparison, business analysis, system design, and all result tables and charts generated by `npm run reports`. · **文档**：规划报告、与上一代对比、商业分析、系统设计，以及 `npm run reports` 生成的全部结果表格和图。
- **Command line** (`npm run sim`, `npm run reports`), unit tests with Vitest and strict TypeScript type checking. · **命令行**（`npm run sim`、`npm run reports`）、Vitest 单元测试和严格模式的 TypeScript 类型检查。

### Changed · 变更

- The part declares its own dependencies (`three`) and development tools in `package.json`, with the Node.js version (22 or later) and repository links, and is now an npm workspace of the repository: `npm ci` at the root, then `npm run <script> -w StoreX`. · 依赖（`three`）和开发工具都在 `package.json` 里声明，并写明 Node.js 版本（22 以上）和仓库链接；本部分成为仓库根目录的 npm 工作区：先在根目录 `npm ci`，再 `npm run <脚本> -w StoreX`。
- CI runs type checking, the unit tests and the production build of this part on every push and pull request. · CI 在每次推送和 pull request 时跑本部分的类型检查、单元测试和生产构建。
- A Prettier configuration (`.prettierrc.json`) and a `format:check` script; existing files are not reformatted yet. A draft ESLint configuration (`eslint.config.mjs`) is in place but not enabled, because its packages are not installed yet. · 加了 Prettier 配置（`.prettierrc.json`）和 `format:check` 脚本，现有文件还没有统一格式化；ESLint 配置草案（`eslint.config.mjs`）已经放好，但相关的包还没安装，所以还没启用。
