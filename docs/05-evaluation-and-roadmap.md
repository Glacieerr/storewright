## 第一部分：如何「诚实地」证明效率与收益提升

本项目需要给出详细的效率提升和收益提升对比。这里有一个必须先讲清楚的原则：

> **不能编造数字，也不能使用任何零售商的非公开数据。**
> 一份「效率提升 37%」却说不出来源的报告，在懂行的人（招聘方、门店管理者、投资人）面前会立刻失去可信度。

因此，效益对比由三部分组成，每一个数字都能追溯来源。

### 1. 证据来源分级

| 等级 | 来源 | 用途 | 示例 |
|---|---|---|---|
| A | 公开学术文献、权威行业报告 | 设定参数范围、作为外部对照 | 拣货路径优化的典型节省比例；缺货导致的销售损失比例 |
| B | 仿真实验（本项目自建） | 在同一条件下对比两种策略 | 相同订单流下，按容量分框与按订单数分框的推车数量差异 |
| C | 作者的观察与合理推测 | 只用于判断参数是否合理（「这个步行速度像不像真的」），并明确标注为推测 | — |

报告中的每个结论都会标注它属于 A、B 还是 C。

### 2. 仿真对比实验设计

核心方法是**离散事件仿真（Discrete-Event Simulation）**：把门店建模为一系列事件（订单到达、拣货员走到货位、扫描、放入暂存位、顾客到达……），在计算机里「运行」一整天甚至一个月。

**对比方式**：同一个门店配置、同一组订单流，分别使用两套策略运行。

| 环节 | 基线策略（现状通用做法的抽象） | 优化策略（本系统） |
|---|---|---|
| 分批 | 按订单数平均分到推车，不考虑体积和重量 | 按温区 + 体积 + 重量单遍分箱；批次按通道 / 区域重叠度全局划分 |
| 拣货路径 | 按商品类别顺序 | 基于平面图的路径优化 |
| 缺货处理 | 拣货员原地处理或直接标记缺货 | 异步 Exception + 自动补货任务 |
| 暂存 | 员工自选位置，无记录 | 员工自选 + 扫描确认（位置可查询），布局稳定时显示推荐格位 |
| 交付准备 | 顾客到达后才开始 Prep | 顾客「即将到达」（固定阈值）时提前取出已暂存的框 |
| 人员分配 | 班前固定分配 | 按预测工作量动态调配 |
| 补货 | 定时巡检 | 预计售罄时间驱动 |

**实验规范**：

- **公共随机数**：两种策略使用完全相同的订单、顾客到达时间和缺货事件，排除运气因素；
- **重复运行**：每个场景至少运行 30 次，报告均值和 95% 置信区间；
- **预热期**：剔除开店前段的非稳态数据；
- **场景矩阵**：平日 / 周末 / 节假日高峰 × 中型店 / 大型店 × 缺货率高 / 低；
- **消融实验**：逐一关闭某项优化，测出**每项优化各自的贡献**，而不是只给一个总数。消融实验最能说服懂行的人。

### 3. 指标体系

| 区块 | 指标 | 定义 |
|---|---|---|
| Picking | UPH | 每人每小时拣货件数 |
| | 每件行走距离 | 总步行距离 ÷ 拣货件数 |
| | 推车装载率 | 实际装载体积 ÷ 推车总容积 |
| | INF 率 | 未找到商品行 ÷ 总商品行 |
| | 替代接受率 | 顾客接受的替代 ÷ 全部替代 |
| Staging | 入位时间 | 回到暂存区到全部框入位的时间 |
| | 找框时间 | Prep 时找到全部框所需的时间 |
| | 峰值占用率 | 各温区暂存位占用率的峰值 |
| Dispensing | 平均等待时间 | 顾客到达 → 交付完成 |
| | 超时率 | 等待 ≥ 8 分钟的订单比例 |
| | 准时率 | 在时段结束前就绪的订单比例 |
| 库存与补货 | 货架缺货率 | 货位处于空置状态的时间占比 |
| | 补货响应时间 | 补货需求产生 → 补货完成 |
| | 库存准确率 | 系统数量与实际数量一致的货位比例 |
| 人员 | 人均处理件数 | 总件数 ÷ 总工时 |
| | 调动次数 | 每班次人员调动次数 |
| | 空闲率 | 无任务时间 ÷ 在岗时间 |
| 财务 | 单均履约人工成本 | 履约总工时 × 时薪 ÷ 订单数 |
| | 缺货销售损失 | 缺货期间的预计未实现销售 |

### 4. 财务模型

```
人工节约（年）  = Σ 各环节节约工时 × 时薪 × 营业天数
缺货挽回（年）  = 基线缺货损失 × 缺货率降幅 × 毛利率
硬件投入        = 传感器数量 × (单价 + 安装) + 网关 + 年维护
投资回收期      = 硬件投入 ÷ (人工节约 + 缺货挽回)
```

- 所有输入参数（时薪、订单量、毛利率、传感器单价等）都可以在模拟器中调整，结果实时重算；
- 用**龙卷风图**做敏感性分析，显示哪个参数对结论影响最大；
- 对「等待时间缩短 → 复购率提升」这类缺少可靠数据的因果关系，**只做定性说明，不给数字**。

### 5. 可以声称的结论与不能声称的结论

| 可以说 | 不能说 |
|---|---|
| 「在仿真条件 X 下，策略 B 比策略 A 减少 Y% 的步行距离（95% 置信区间 [a, b]）」 | 「本系统能让某零售商效率提升 Y%」 |
| 「根据文献 Z，缺货损失约占销售额 W%，据此推算……」 | 任何无来源的百分比 |
| 「投资回收期对传感器单价最敏感」 | 「部署传感器一定能回本」 |

## 第三部分：主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 范围失控 | 十二个模块都做成半成品 | 严格执行分层（核心 / 扩展 / 前瞻），核心未达标前不开始扩展 |
| 知识产权问题 | 无法公开或无法商业化 | 信息边界、中性命名、专利规避设计（见 G-02、G-11） |
| 商品主数据缺失 | 容量分配、替代推荐无法运行 | 使用合成数据集，并明确标注；预留真实数据导入接口 |
| 性能目标过高 | 模拟器卡顿 | 实例化渲染、仿真放在 Web Worker、性能预算从 Phase 2 开始测量 |
| 效益数字被质疑 | 作品集可信度下降 | 证据分级、置信区间、消融实验、敏感性分析 |
| 单人开发精力有限 | 进度停滞 | 每个阶段结束都有可展示的成果，随时可以停在一个完整的状态 |
| 3D 与多楼层增加工作量 | Phase 2 拖延 | 先完成等距 2.5D 单层，再加 3D 视角和多楼层；三种视角共享同一套场景数据 |
