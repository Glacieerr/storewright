## 1. 能做什么

### 1.1 场景

| 能力 | 说明 |
|---|---|
| **三种视角** | 等距 2.5D（默认，从门店右前方看，停车场和交付门口在近处）、自由 3D（透视，可环绕）、俯视 2D；右下角按钮缩放和复位，窗口或分屏比例变化时自动适配 |
| **多楼层** | 单独查看某一层，或在 3D 视角中同时显示所有楼层（上层楼板半透明）；顾客和员工乘电梯上下楼 |
| **周边道路** | 按随机种子生成三种风格：郊区社区（独栋住宅、行道树）、城市街区（高楼）、城郊干道（双向六车道、中央绿化带、加油站和大型商铺）；含支路、信号灯、人行横道、路灯、后勤通道和卸货区；后勤通道和停车场出入口接主路处是喇叭口（路缘半径 15 米 / 6 米，人行道在那里断开），停车场出入口一进一出、中间有隔离岛和进出箭头。路面细节：沥青（骨料、细裂缝）、人行道方砖、花岗岩路缘石、车道线与路边线、停止线、导向箭头、井盖和雨水篦子；带横臂的信号灯（灯箱有背板和遮光檐）、弯臂路灯、公交候车亭、消防栓、垃圾桶、限速牌 |
| **水系** | 主路对面的湖（港池，起伏的岸线、沙岸、芦苇、石头），南岸接**出海水道**通到场地前沿的海湾，水道口两侧是抛石**防波堤**和航标灯（进港方向右红左绿），环湖步道上的**人行开启桥**在帆船经过时抬起；河从门店后方沿进场道路外侧流过来，穿过主路下的**两孔石拱桥**（拱券石、分水尖桥墩、花瓶形栏杆、四角灯笼）进入石砌渠道，漫过三级跌水堰流进湖里；湖的北岸有**木栈桥码头**（坡道、T 形平台、木桩、绳栏、随水波起伏的小船）、石板小广场（长椅、花坛、租船小亭）和环湖步道，堰上游有拱形人行木桥；**船只按时刻表进出港**：快艇、小帆船早上出海、下午回港，浮筒船在湖里兜圈。水面是卡通水：离岸越远越深、水纹流动、岸边泡沫和浪线、太阳高光、下雨时的涟漪；周边环境里可以选没有水面 |
| **背景车流** | 每条车道上的车按跟车模型行驶，红灯停车、黄灯来不及停的直接通过；车流随时段和拥堵强度变化，高峰时路口排起长队；多车道路上会变道（要转弯的车提前并线，前车慢时借道，空了回外侧车道）；主路有**左转保护箭头**，对向没有来车时也可以在绿灯下左转 |
| **路边行人** | 沿人行道走，在路口等行人绿灯、剩余时间够才过马路；有人在人行横道上时，转弯车辆在横道前停下让行；城市街区人多，夜里人少；部分行人带着孩子 |
| **停车场** | 两侧出入口一进一出（靠右行驶，环形车道和车道也靠右）、门前消防车道、带编号立柱的**线上取货专用车位**（立牌顶上的状态灯跟着车位的实时情况变色：空闲绿、有车在等蓝、等太久红色闪烁、正在交付琥珀色；仿真和数字孪生都一样）、双排停车位与车道、端部绿化岛、两侧出入口、**购物车回收栏**；购物顾客和员工的私家车按时段进出，傍晚最满，越靠近门口越容易停满；约 12% 的车**倒车入位**、约 8% **穿过对面空车位**停进来（车头朝外）；**房车和拖着拖车的车**平行于车道停在最远一排端头的几个车位前沿（房车占 6 个，带拖车的占 7–8 个），还有在停车场过夜的房车；驶出时在路边停下让行；行驶中的车离别的车或推购物车的人太近时向右让一点 |
| **购物车回收** | 推车购物的顾客把购物车放进最近的回收栏；穿反光背心的回收员大约每 25 分钟出去一趟，把车多的回收栏清空，套成一串推回门口（一串最多 20 辆） |
| **车辆** | 按常见车型的公开外形和尺寸放样（通用外形，没有品牌标志）：轿车、两厢车、SUV、皮卡、高顶厢式车、平头厢式货车、长头带卧铺的半挂牵引车与 53 英尺厢式 / 冷藏挂车、A 型房车，以及拖挂式房车、船拖车（带快艇）、小平板拖车；车窗、门缝、风挡、护板、彩条按位置分出，乘用车五辐轮毂、货车钢圈与双胎；颜色按常见乘用车颜色分布抽取；**驾驶姿态**：刹车点头、加速下坐、转弯外倾（车轮贴地），半挂车铰接、拖车按挂钩运动学跟随；路上有少量过境的长途半挂车和房车 |
| **人物** | 简化成基础轮廓（上身、下身、头三段，按身高缩放），推着网格车筐的购物车；员工按岗位着色，拣货员推拣货车；交付员从门口走到车尾交付再走回；到店购物的顾客从停好的车走进门店、逛几条通道、推着购物车回到车上；肤色和身高各不相同，约六分之一的顾客带着孩子 |
| **汽车服务中心** | 门店一侧的换机油 / 换轮胎车间：车辆排队等候、开进工位、换轮胎时被举升；技师在工位旁作业；顾客休息室、轮胎货架 |
| **昼夜** | 太阳方向与颜色随时间变化，日出日落偏暖；程序生成的天空（云、太阳光晕、夜里的月亮和星星）；场景只到周边一圈，是一块四边有土层断面的**沙盘**（海湾、河在边缘处露出水体断面）；夜里店内灯火通明、周边楼房一半左右的窗户亮灯、路灯和桥上灯笼亮起（高画质下有光晕）、车辆开大灯和尾灯 |
| **画质** | 高（描边、实时阴影、泛光、草丛和野花）/ 中（描边和天空，无阴影）/ 低（不做后期处理，最简画面）；触屏设备默认「中」，没有显卡加速（浏览器在 CPU 上软件渲染 WebGL）时默认「低」 |
| **建筑查看方式** | 内部（剖切掉屋顶和外墙，默认）/ 半剖（一个可拖动的竖直剖切面，一半看外观、一半看店内）/ 外观（石材勒脚、金属板外墙与壁柱、高窗带、品牌色檐口带、入口两侧的通高玻璃幕墙和高出屋面的门头墙与店招、女儿墙压顶、屋顶空调机组与采光天窗、卸货雨棚与门封）；选中某一层时只显示到这一层 |
| **两层门店** | 电梯 1–3 部（左前、左后、右前）与自动扶梯 0–2 组（前走廊，上下行各一条），上层楼板在扶梯处开洞；员工推车只能乘电梯，顾客优先乘扶梯；二楼有**收银区**（最后逛二楼的顾客在二楼结账）、**货梯**（一楼收货区旁）、货梯口的**卸货区**和后面的**补货区**：搬运车把二楼货架的托盘经货梯送上去，夜班从二楼补货区补货；二楼通道数填 0 时按货梯位置自动铺满二楼（一楼其余部分是单层） |
| **到货、仓储与夜班** | 按星期、季节和门店规模排班：清晨配送中心的冷藏半挂车，上午一家接一家的供应商直送（面包、乳品、饮料、零食、啤酒……厢式货车和面包车，准点有起伏），下午快递和（每周几次）百货半挂车，关门后几辆长途半挂车陆续到达；卸货门 1–10 个，卸货场的进场道路（门店左侧或右侧、专用通道或经支路）、待命车位和甩挂车位可以设置；**卸货场**：在待命车道上先到先进地排队，轮到时绕到靠台车道、驶过卸货门车头外摆、司机开挂车门，**从司机一侧倒车**、挂车在离墙 24 米外摆正再笔直退进门里，卸完笔直拉出、绕场驶离；场地同一时间只有一辆车行驶；**叉车和手动搬运车**把托盘从车厢卸到收货区（一个车厢同时只进一台），叉车再把托盘放进**库存仓库的托盘货架**（货叉升到对应层，一条通道同时只有一台叉车，作业完驶出通道、停回充电位）；夜班取货前叉车把高层托盘取到地面，补货员装车、推上货架，托盘上的纸箱随之变少；线上订单暂存仓单独划出；时间轴延伸到次日开门 |
| **突发状况** | 小状况（标签丢失重打、商品破损重拣、找不到框、打印机卡纸）随机发生；大事件（火警、警情、停电、系统故障）可随机或手动触发：火警时全员疏散到停车场集合点、消防车到场，警情时警车停在取货区，停电时店内变暗只剩出口指示灯 |
| **天气与季节** | 晴、多云、雨、雪、雾（雨丝、雪花、积雪、湿路面、雾），以及**多变**：按季节和种子生成一天的天气（清晨起雾、午后阵雨、冬天下雪），雨慢慢下大、慢慢停，雨停后路面约一小时才干；数据面板显示全天天气条和下一次变化；季节改变日出日落时间和树木颜色 |
| **店内陈设** | 货架朝通道的一面画出层板、价签条和一排排商品（叠加层颜色在顶面和端面）；塑胶地砖；收银通道（传送带、收银机、通道号灯柱）与自助收银机，顾客结账后才离开；通道吊牌；冷冻柜玻璃门；药房柜台；通道两端的**促销端架**；靠墙的**熟食服务柜台**（玻璃柜和店员）；冷藏、冷冻柜的灯光；夜里天花板灯在地面上的光斑、招牌光晕和门口洒出的暖光 |
| **更多附属设施** | 园艺中心（门店一侧的露天围栏卖场）、店内药房（柜台排队）、汽车服务中心 |
| **周边的问题** | 可以打开**学校**（教学楼、操场、旗杆；上学放学时护导员拦车，路上更堵）和**铁路道口**（火车按时刻表经过，栏杆放下、闪灯，背景车流排队），到店时间随之推后 |
| **周边地块** | 临主路、街角（侧面也临街）、商业街（旁边连着几家小店）；随机公园和水池；周边楼房的立面有按楼层画出的窗户，住宅是出檐的彩色坡屋顶和烟囱；主路施工路段（锥桶、限速）；背景车流在路口右转，并给进出停车场的车让行 |
| **环境音** | 车流、雨声、扫码提示音、清晨鸟鸣、火警警报，全部实时合成；默认关闭 |

### 1.2 数据与操作

| 能力 | 说明 |
|---|---|
| **分屏** | 同一页面左侧场景、右侧数据（或互换）；拖动中间的分隔条调整比例，双击复位；切换数据标签不会中断播放 |
| **实时数据** | 当前时刻的指标卡片；全天曲线（交付进度、等待车辆、平均等待、暂存占用、岗位利用率、累计拣货、汽车服务中心排队与作业），播放到哪里实线画到哪里 |
| **策略对比** | 后台 Worker 用同一门店、同一订单流、同一排班跑三种策略，表格列出差值（好 / 坏着色），叠加曲线对比；一键切换播放的策略 |
| **方案与报告** | 把当前的全部设置（布局、策略、排班、订单量、环境、突发状况、夜班）连同全天结果和场景缩略图**保存为方案**（存在本机浏览器）；任选两个方案 A / B 并排对比指标和经营账；**连续模拟 7 / 14 / 30 天**（订单量按星期几浮动），看平均、P10、中位数、P90；**经营账**（线上订单业务、汽车服务、后仓收货与补货三部分，单价可调）；导出**单文件 HTML 报告**或 Markdown，截图 PNG |
| **事件** | 等待过久、未按时就绪、冷链超时、暂存占用过高、道路进入高峰、汽车服务排队过长等；可筛选，点击定位；警报还会在场景右上角弹出 |
| **点选查看** | 场景上的浮动卡片：员工、货架通道、车辆（含路上堵车耽误的时间）、暂存区、汽车服务中心（工位状态、营收）；◎ 按钮把镜头移到对象 |
| **现场调度** | 改派员工、调整各岗位从当前小时起的人数；情景注入（订单高峰、请假、道路拥堵关闭 / 一般 / 严重） |
| **货架存量**（Phase 4） | 「货架存量模型」默认开启：店内销售和线上拣货消耗每个商品的货架存量，拣货员遇到空货架时转后仓补取，后仓补取员（含营业时间内的白天补货员）去后仓取箱补货；叠加层「货架存量」按填充率给货架段着色，空商品占两成以上为红色；货架存量曲线（空货架商品数、累计补货）；事件提醒「货架空了 / 补货完成」可点击定位；点击通道显示空着的商品与补货任务，可以手动请求补货。关闭后恢复 Phase 1 的概率模型。详见 [后仓库存、Exception 与补货](09-backroom-replenishment.md) |
| **数字孪生**（原「门店实况」） | 连接 Storewright 后端（见 [实时作业](08-live-operations.md)）：孪生健康度、设备与传感器、设备告警和影响、从现在出发的推演（可以试调整人手）；今日订单、等待中的顾客、平均等待、正在拣货的批次与进度、暂存占用、交付看板、实时事件。场景只显示实时数据：员工显示在最近一次扫描的位置，暂存格位里的框来自实时状态，到店顾客显示在签到的取货车位上，设备牌显示读数、告警的区域闪红；底部的孪生时间轴可以回放过去、推演未来 3 小时（见 [14 数字孪生](14-digital-twin.md)） |
| **门店定制** | 见第 5 节：实时生效的布局编辑（画通道、旋转、多选、复制粘贴、按楼层编辑）、门店生成器、周边环境设置、拖拽摆放、后仓与暂存仓大小 |
| **镜头** | 默认正对门店右前方完整取景；滚轮朝光标缩放；键盘 WASD / 方向键平移、Q / E 旋转、R / F 俯仰；90° 旋转按钮；3D 预设机位（正面、侧面、鸟瞰、街景）；跟随选中的员工或车辆；小地图（点击移动镜头）；平移范围限制在场地内 |

## 2. 架构

```mermaid
flowchart LR
  subgraph Main[主线程]
    UI[界面与分屏<br/>React + Zustand]
    SC[三维场景<br/>React Three Fiber]
    CL[播放时钟<br/>不进入 React 状态]
    ENV[周边环境与车流<br/>按种子生成 · 只用于画面]
  end
  subgraph W1[主 Worker]
    SIM[simulateDay + 轨迹<br/>道路拥堵 · 汽车服务中心]
  end
  subgraph W2[对比 Worker]
    CMP[三种策略各跑一遍<br/>连续多天模拟]
  end
  UI -- 门店配置 · 策略 · 排班 · 需求 · 拥堵 · 天气 --> SIM
  UI -- 同样的输入 --> CMP
  SIM -- Timeline --> UI & SC
  CMP -- 指标与曲线 --> UI
  CL -- 每帧读取 --> SC & ENV
```

1. **两个 Web Worker**：主 Worker 负责当前策略（用户操作触发，约 0.1–0.25 秒）；对比 Worker 在每次重新仿真后 0.4 秒开始跑三种策略，连续多天模拟也在这里逐天运行并回报进度，不拖慢主仿真，也不打断播放；
2. **画面里的东西分两类**：订单、员工、取货车辆、汽车服务中心的车辆、到货卡车、叉车与托盘全部来自仿真结果；周边道路、背景车流、路边行人、购物顾客的私家车和人、购物车回收只用于画面，由随机种子生成，不影响任何指标；「多变」天气的计划由同一个函数生成，画面和仿真用的是同一份；
3. **背景车流按画面时间运行**：最多按 8 倍速推进（再快就看不清），取货车辆的驶入 / 驶出动画按同样比例拉长，高倍速播放时不会「瞬移」；
4. **编辑时人和车仍按仿真时的布局移动**：编辑器预览的是草稿布局，时间轴始终与生成它的门店模型配对，新结果算出后再切换，避免员工走到不存在的节点；
5. **渲染**（v5，决策记录 0017）：全部用程序生成的几何体和画布贴图（不下载任何模型或图片素材）。所有卡通材质共用一个着色补丁（柔和的两段明暗 + 朝天一侧的轮廓光），参数每帧按昼夜和天气统一更新；后期处理按深度找出外沿和棱角描深色线，再做调色、泛光（高画质）和抗锯齿；天空、水面、地形与草地、建筑立面、货架商品都是专门的着色器；货架、车辆、人物、树木、草丛、建筑、标线都用 InstancedMesh，同一种材质的静态构件合并成一个几何体；夜间效果用自发光和泛光实现，不增加实时光源；截图走同一条后期流水线；
6. **按需加载**：首屏只加载界面、状态和仿真 Worker；三维场景（含 Three.js、React Three Fiber）、策略对比 / 方案与报告 / 门店定制三个数据标签、环境音、英文字典都在用到时才下载。场景和界面共用的小模块（卡通材质渐变、车型列表、对象位置表、镜头状态、截图）单独拆出，不引用 Three.js，保证首屏不把 Three.js 带进来；
7. **界面语言**：中文原文就是翻译的键，`t('已选中 {0} 条通道', n)`；仿真引擎和配置校验产生的中文在显示时再翻译——先查原文，再把数字换成占位符查一次，最后试正则模板（含名称的句子）。测试扫描模拟器和引擎的全部源码，保证每一段会显示的中文都有英文译文。

## 3. 仿真中的外部因素

### 3.1 道路拥堵

拥堵不只是画面：仿真引擎新增 `traffic` 参数（`packages/sim-engine/src/traffic.ts`）。

- 每小时有一个拥堵指数（假设的工作日曲线：早高峰 7–9 点，晚高峰 16–18 点最堵），乘以强度（0 关闭 / 1 一般 / 2 严重）；
- 顾客**按原计划出发**，点击「我在路上」的时刻不变；堵车让实际到店推后，延误 = 自由流行驶时间 × 0.6 × 拥堵程度 × 个体系数；
- 基于位置的 ETA 信号跟着实际到店时间走，「我在路上」信号不会；
- 强度为 0 时与接入拥堵模型之前逐位相同（有测试保证），Phase 1 的结果不受影响。

**一个直接的发现**（小型店和中型店各 3 个种子，结果一致）：严重拥堵时，按「我在路上」备货的基线策略，订单在门口的停留从约 10–13 分钟升到 20–24 分钟；按 ETA 备货的默认档位基本不变（约 2–3 分钟）。也就是说，路况越差，ETA 触发的冷链优势越大。

### 3.2 到货与仓储、夜班补货、突发状况、天气、经营账、药房与门店规模

- **到货、仓储与夜班补货**（`packages/sim-engine/src/inbound.ts`，后仓布局在 `packages/store-config/src/backroom.ts`）：后仓按配置推导出托盘货架（排数、段数、层数）、收货区和卸货门；开门前冷藏半挂车、白天供应商厢式货车（中型及以上门店还有一辆整车直送半挂车）、关门后长途半挂车（约 18 托一车，几车间隔 4–18 分钟陆续到达）按时到达；卸货场先到先进、同一时间只让一辆车行驶、驶离优先（决策记录 0018）；卸货要用叉车或手动搬运车（叉车优先，派最近的空闲设备，两台以上叉车时一台主卸货、一台主上架；一个车厢同时只进一台设备，一条货架通道同时只有一台叉车），托盘先放在收货区，再由叉车放进货架（放得越高越慢）；开门时货架约五成满。夜班需补箱数 = 当天线上件数 ÷ 线上占比（假设 15%）÷ 每箱 12 件 × 当晚需补比例（65%），夜间半挂车按各通道的补货需要配货；取货时优先用当晚到的直送托盘，再用货架底层的托盘，高层托盘先由叉车取到地面。没有叉车时只能用搬运车卸货，货进不了高层货架。开门时没上架的箱数即开店缺货风险。
- **多变天气**（`apps/simulator/src/sim/weatherPlan.ts`）：按季节和种子逐小时生成天气；下雨 / 下雪的时段变成车边交付变慢的窗口，这些小时的路况系数提高，全天订单量按雨雪时长略增（下雨全天 +8%，下雪 +15% 的比例折算）。
- **经营账**（`packages/sim-engine/src/economics.ts`）：线上订单毛利 − 拣货 / 暂存 / 交付人工 − 迟到补偿 − 长等待流失 − 缺货毛利；汽车服务毛利；后仓的收货与夜班人工、叉车与搬运车、开门未上架损失。模拟器不计算店内销售收入，而后仓补货服务的是整个门店，所以合计通常为负；比较方案时看差值。
- **突发状况**（`incidents.ts`）：小状况按对象键控随机发生（不同策略面对同样的状况），只增加对应作业的时间；大事件在时间窗口内暂停或放慢相关岗位：暂停期间不开始新作业，进行中的作业顺延。没有突发状况时结果与之前逐位相同。
- **天气**（假设）：雨、雪、雾分别让路上更慢（拥堵程度 ×1.3 / ×1.8 / ×1.2）；雨、雪天车边装车更慢（×1.15 / ×1.3），线上订单增加（+8% / +15%），到店购物的人减少。
- **药房**（`pharmacy.ts`）：按小时到店，取药 3–8 分钟、咨询 8–15 分钟（约 25%），柜台数即同时服务人数。
- **门店规模**：自定义门店的日订单量和排班倍数按货架通道总数在三个模板之间连续插值；营业时间改变时，排班随之平移伸缩，线上订单的取货时段、到店客流、夜班开工时间都跟着变。

## 5. 门店定制

### 5.1 实时生效的布局编辑

1. 点「编辑布局」或「门店定制」标签进入编辑，**仿真不暂停**；任何视角都可以编辑；在面板上选择要编辑的楼层（也可以修改楼层的宽和深）；
2. 点击通道附近选中通道，**Shift / ⌘ 点选多选**，按住选中的通道拖动一起移动（全是竖向通道时只左右移动，全是横向时只前后移动），拖动中按吸附后的位置预览；方向键按屏幕方向微调 0.1 米（Shift 1 米）；
3. **画通道**（N）：在地面上拖出一条通道，两端吸附到附近的走廊或通道上（绿点接上、红点没接上）；只点一下则在该处放一条竖向通道并延伸到前后走廊；新通道沿用当前选中通道的温区和层数；
4. **旋转 90°**（T）、**复制粘贴**（⌘C / ⌘V 粘贴到指针位置，切换楼层后粘贴即跨楼层复制）、复制到旁边（⌘D）、**等距排列**、全选本层（⌘A）、删除；多选时可批量修改温区和层数；
5. 修改温区、段数、层数、商品类别，修改暂存格位编码规则；
6. 每次修改先校验（结构、类别、可达性、货架重叠、**横竖货架交叉**、**超出楼层**、**暂存区压在货架上**、格位编码），**通过后约 0.4 秒自动应用**，仿真从当前时刻继续播放；有问题时保留最后一次通过校验的布局；
7. 撤销 / 重做（⌘Z / ⇧⌘Z，最多 50 步）；「完成编辑」保留当前布局，「撤销全部修改」回到进入编辑前；
8. 配置可以导出为 JSON 保存或导入（旧版配置没有附属设施、后仓设置时按默认值处理）。

几何操作都在 `packages/store-config/src/editing.ts`（纯函数，有测试），模拟器只负责交互。

### 5.2 门店生成器

- 预设：小型 / 中型 / 大型 / 大型店 + 汽车服务（三个模板就是三组预设参数，用模板参数生成与模板完全相同，有测试保证）；
- 逐项调整：常温 / 冷冻 / 一楼百货通道数、货架段数与层数、暂存区规模、周边墙柜、**二楼百货区**（电梯、扶梯数量）、**汽车服务中心**（左侧或右侧，机油 / 轮胎工位数；汽车用品通道自动放在一楼靠近它的一侧）、**园艺中心**、**药房**（柜台数）、**营业时间**、**停车场排数与取货车位数**、**人员倍数**；
- 🎲 随机门店：按种子生成一组相互协调的参数（规模、层数、附属设施），60 个种子全部通过校验；
- 生成会替换当前布局，作为一次可撤销的编辑实时应用；需求量和默认排班按门店规模自动匹配。

### 5.3 周边环境

道路风格、地块（临主路 / 街角 / 商业街 / 随机）、水系（湖与出海口 / 没有水面）、施工路段、学校、铁路道口、随机种子和拥堵强度，可以一键全部随机。风格、地块、水系、施工和种子只改变画面；拥堵强度、天气、季节、学校和铁路道口会改变到店时间或到货排班并重新仿真。「实时数据」里可以选星期几（到货车辆按星期排班）。

另外，「门店定制」里可以直接修改营业时间、停车场，增删附属设施，不必重新生成整个门店。

### 5.4 拖拽摆放

编辑时场景中会出现彩色把手：顾客入口、交付门口、电梯和扶梯可以沿前走廊左右拖动；汽车服务中心、园艺中心拖到门店另一侧即换边（另一侧已有设施时两者互换）；**线上订单暂存区**可以在一楼自由拖动，松开时吸附到最近的走廊或通道上（拣货车存放点一起移动）。拖动时只预览，松开后作为一次可撤销的修改实时应用。

### 5.6 后仓与暂存仓

「门店定制」和门店生成器里可以设置后仓加深（米）、托盘货架排数（0 表示按深度放满）和层数、卸货门数量（1–10）、叉车和搬运车数量，以及线上订单暂存仓的规模（0.5–3 倍）；面板实时显示托盘位数量。**卸货场**：进场道路在门店哪一侧、接主路还是经侧面的支路、离停车场多远，待命车位和甩挂车位数（`ui/YardFields.tsx`）。线上订单区默认有常温暂存货架、**线上订单冷藏库和冷冻库**、通到收货区的**连通通道**和通道旁的**溢流位**：后仓放满或收货区快堆满时，搬运车把托盘经通道送到溢流位，夜班也从那里取货；仍放不下时托盘留在收货区，数据面板和事件里会提醒。

### 5.5 汽车服务中心

独立的离散事件仿真（`packages/sim-engine/src/autoService.ts`）：按小时到店权重随机到达，换轮胎约占 40%；每个作业需要对应类型的工位和一名在岗技师，先到先服务；排队超过工位数的 2 倍时新到顾客离开；打烊后不再接车，技师把已排队的车做完。输出完成数、流失数、等待、工位利用率和营收。收入与工时是公开常识级的假设参数，界面上注明。

npm install

## 7b. Phase 8：车辆拟真、区域、取货车位与「你的商店」（决策记录 0013）

**车辆**
- 路径（`scene/lot.ts` 的 `TimedPath`）：长线段切成 3 米的小段，每个顶点的速度受限速、转弯侧向加速度（v ≤ √(a·R)）、加速度和减速度约束（正向、反向各扫一遍），段内匀加速；车头朝向在顶点之间连续过渡；输出速度、加速度、前轮转角（δ = atan(轴距 × 曲率)）和行驶距离。所有车辆（顾客、汽车服务、货车、应急车辆）共用，按车型给动力学参数（小车起步 2.2 m/s²、货车 0.8 m/s²）。
- 车轮单独实例化：按行驶距离转动、前轮随转角转向；车灯：减速或停车时刹车灯、倒车时倒车灯、转弯时转向灯、倒车靠台和在门前等候时双闪；夜间车灯按车型的位置。
- 铰接半挂车（`scene/rig.ts`）：牵引车与 53 英尺挂车分开建模（冷藏挂车有冷机）；前进时挂车航向按 dθ挂/ds = sin(θ牵 − θ挂)/L 积分（内轮差、出弯摆正），倒车时挂车后轴沿半径 10 米的圆弧退入卸货口、由挂车姿态反推牵引车；测试检查交接连续、铰接角不超过约 63°、停靠时挂车垂直于后墙且车尾离墙约 0.6 米。
- 卸货门（`scene/DockDoors.tsx`）：门框、卷帘门、防撞块、调节板、信号灯；有车靠台卸货时卷帘门升起、信号灯变红；冷藏门的门头是蓝色。仿真引擎的到货模型改为按门调度：同一个门同时只停一辆车，冷藏车优先用冷藏门，没有空门时在场地里等（`Truck.dockAt`），车卸完 8 分钟后驶离让出门；叉车叉着托盘从车厢里倒出来（`PolySegment.reverseLegs`），不再在车厢里掉头。
- 运营孪生（`scene/LiveFleet.tsx`）：顾客签到后按填写的车型和颜色开进取货车位，交付完成后倒出驶离；配送司机开白色面包车；已到达、还没收完的到货车停在卸货口，卷帘门升起；路上有背景车流。

**区域与车位**
- `scene/Areas.tsx` 画出每个区域（按类型着色、描边、名称；冷藏库和冷冻库是步入式冷库），叠加层「区域占用」按占用着色；编辑器的「区域与卸货门」可以把自动生成的区域写进配置后逐个编辑（类型、温区、容量、预警线、位置），场景里拖动选中区域的移动把手和改大小把手；卸货门可以增删、沿后墙拖动、设为冷藏门或地面门；「线上取货车位」可以改为手动摆放后逐个编辑编号、位置、朝向，拖动车位，按离交付门的距离重新编号。

**你的商店**
- 「你的商店」（决策记录 0013；2026-10-28 起并入本仓库，所有功能公开，见决策记录 0027）：项目页有门店列表和新建门店向导，按占地、行业、楼层、暂存规模、卸货门、取货车位、营业时间和附属设施找到最接近的生成参数（`fitParams`：通道数决定宽度，货架段数决定深度）；打开门店时顶栏下方是项目栏：门店名称、自动保存、搭建步骤（直达编辑器的对应部分）、开业检查、全天仿真、实时沙盒。门店可以复制，也可以导出成 `.storewright.json` 文件再导入（带格式标记，导入时检查）。
- 代码在 `src/yourStore/`，打开时才下载（`App.tsx` 按需加载项目页和项目栏）。门店保存在浏览器的 IndexedDB（`storewright-projects`，不可用时退回 localStorage），模拟器和展示页共用；状态仓库里的 `project`、`openProject`、`closeProject` 打开和关闭门店项目。
- 地址参数：`?yours` 打开项目页，`?project=<编号>` 打开门店项目（`&edit=1` 进入搭建）；展示页的 `?project=<编号>` 是这家门店的实时沙盒，浏览器里的门店中枢按这份配置建店（门店编号 `my-<配置哈希>`）。
- 和模板门店共用的通用能力：自定义配置建店、区域与卸货门编辑、取货车位编辑、开业检查（`goLiveCheck`）。

**手机宽度（600 像素以下）**
- 顶栏只留一行：品牌、「你的商店」和「设置」开关（编辑布局时还有「完成编辑」，品牌只留图标）；门店、策略、AI、视角、楼层、建筑、叠加层、画质、导览、语言、编辑布局都在「设置」里（`ui/TopBar.tsx` 的 `.tb-more`）。嵌在展示页里时不用这个开关。
- 场景高度约为屏幕的 2/3（`66svh`）；不显示没有用处的快捷键和小地图按钮。
- 场景标签缩小字号，只标注主要区域：小于 60 平方米的区域、托盘位和车位数、「后仓」、熟食柜台不标注（编辑和看「区域占用」时小区域照常标注）。

**标签去重叠（所有屏幕，决策记录 0015）**：镜头远的时候区域标签会互相压住。每 250 毫秒按屏幕位置检查一次，重要的先放（取货车位牌、楼层、主要区域、冷库和柜台、通道号），和已经放好的重叠的暂时隐藏（`scene/declutter.ts`）。
