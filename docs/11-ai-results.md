## 1. 一页结论

| 问题 | AI 做了什么 | 对照 | 结果 |
|---|---|---|---|
| 接下来几个小时会来多少单？ | 已知因素回归（节假日、促销、风暴预警、天气预报 + 局部水平） | 季节性指数平滑 | 按小时误差 19.4% → **18.5%**（下限 16.8%）；节假日、风暴预警这些日子 32.8% → **19.1%** |
| 顾客几点到？ | 导航用时 + 高峰与天气 + 顾客习惯（分层收缩） | 只信导航 | 平均误差 5.45 → **3.80 分钟（−30%）** |
| 系统说有货，架上真有吗？ | 「该卖没卖」的沉默证据 + 逻辑回归 | 系统估算 / 朴素贝叶斯 | AUC 0.50 / 0.87 → **0.93–0.94**；提醒精确率 **83%–89%** |
| 先盘哪条后仓记录？ | 按记录不准的概率排序 | ABC 周期 + 可疑优先 | 平均不准的记录数 **−1% 到 −26%**（因种子而异） |
| 缺货时换哪件？ | 学习排序（顾客接受概率） | 名称规则 | 第一名的期望接受率 65%–66% → **70%–71%**（上限 71%–72%） |
| 人该放在哪个小时？ | 按预测工作量重新分配，总工时不变 | 手工排班 | 平均等待 −0.44 分钟，迟到订单 2.41% → 0.69% |
| 现在要不要调一个人？ | 短时排队估算 + 固定名单 + 负荷均衡 | — | 在线建议，仿真里通过排班开关间接体现 |
| 店长怎么问？ | 9 个查询工具 + 规则与本地意图分类器（或本地语言模型） | 只用规则 | 没见过的说法：53.6% → **67.9%**（留出集 B，只运行一次） |

**合在一起**（默认档位，20 天，公共随机数，总工时不变）：平均等待 5.05 → 4.41 分钟（**−13%**），90 分位等待 8.07 → 6.21 分钟（**−23%**），迟到订单 2.41% → 0.69%，满足率 +0.09 个百分点（每天多保住约 8 行替代）；代价是门口停留增加 0.86 分钟（到店时间修正提前准备，可以调，见第 4 节）。

## 2. 模型的离线评估

### 2.1 订单量预测

中型店、4 个种子、两年合成历史（含隐藏因素与一次需求下降），最后 365 天按周滚动回测：

| 预测器 | 按小时 WAPE | 80% 区间覆盖率 | 事先知道的特殊日子 ¹ |
|---|---|---|---|
| 同时段上周值 | 25.9% | 83.4% | 37.7% |
| 近 4 周同时段平均 | 20.6% | 81.7% | 31.7% |
| 季节性指数平滑 | 19.4% | 81.1% | 32.8% |
| **已知因素回归** | **18.5%** | 79.2% | **19.1%** |
| 理论下限（真实期望值） | 16.8% | — | — |

¹ 节假日、节前一天、明天有风暴预警的日子。

### 2.2 到店时间修正

4 个种子、120 天合成到店记录，按时间先后前 70% 训练：

| 版本 | 平均绝对误差 | 偏差 | 80% 区间覆盖率 |
|---|---|---|---|
| 只信导航 | 5.45 分钟 | −2.68 分钟 | 80.3% |
| 导航 + 高峰与天气 | 5.03 分钟 | +0.08 分钟 | 79.6% |
| **再加顾客习惯** | **3.80 分钟** | +0.09 分钟 | 81.8% |

### 2.3 可售概率与幽灵库存

3 个种子、200 个商品、60 天，按天切分前 70% 训练；P(幽灵) ≥ 0.5 时提醒：

| 版本 | Brier | AUC | 校准误差 | 提醒精确率 | 提醒召回率 |
|---|---|---|---|---|---|
| 系统估算 | 0.0145–0.0163 | 0.50 | 1.5%–1.6% | — | 0 |
| 朴素贝叶斯 | 0.0120–0.0122 | 0.872–0.877 | 1.5%–3.1% | 62%–68% | 35%–45% |
| **逻辑回归** | **0.0095–0.0110** | **0.926–0.944** | **0.1%–0.4%** | **83%–89%** | 29%–35% |

### 2.4 按风险盘点

400 条记录、每天 12 次盘点；前 120 天按 ABC 周期盘点积累训练数据，后 120 天比较（公共随机数）：

| 种子 | 平均不准的记录数（ABC → 按风险） | 变化 | 发现错误的平均天数 |
|---|---|---|---|
| 107 | 46.2 → 45.7 | −1% | 5.3 → 5.3 |
| 1 | 45.5 → 42.3 | −7% | 5.7 → 5.4 |
| 2 | 48.4 → 35.9 | −26% | 6.0 → 4.5 |

改进因种子差别很大：可疑记录（补取或补货没找到）在两种策略里都优先盘点，差别只来自其余记录的排序；某些门店（种子）里可疑记录本来就占了大部分盘点。结论是「不会更差、有时明显更好」，不能写成固定比例。

## 3. 运营上的 AI 开 / 关对比

中型店，20 天，公共随机数。差值为「打开 − 不打开」的配对差值，括号里是 95% 置信区间的半宽。效果大小取自第 2 节的离线评估（`AI_EFFECTS`）。

### 3.2 以基线为基础

| 指标 | 不打开 AI | AI 排班 | AI 到店时间 | AI 替代 | 全部打开 |
|---|---|---|---|---|---|
| 平均等待（分钟） | 5.88 | −0.83（±0.34） | +0.99（±0.11） | −0.04（±0.02） | +0.09（±0.33） |
| 90 分位等待（分钟） | 11.15 | −3.56（±1.64） | +2.67（±0.66） | −0.21（±0.26） | −0.35（±1.77） |
| 迟到订单（%） | 4.19 | −2.91（±1.44） | 0 | −0.07（±0.22） | −2.88（±1.39） |
| 门口停留（分钟） | 10.52 | +0.19（±0.10） | **−5.57（±0.20）** | 0 | **−5.72（±0.20）** |
| 满足率 | 97.93% | 0 | 0 | +0.16 pp | +0.16 pp |

### 3.3 解读

- **AI 排班贡献最大**，在两种基础策略上都显著降低等待和迟到，且不增加工时：同样的人手按预测放到对的小时（拣货在高峰前 2 小时、交付在高峰时段）。
- **AI 到店时间的作用取决于原来的做法**：默认档位原来对没开位置共享的顾客要等到人到了才准备，AI 让准备提前，等待变短、门口停留变长；基线原来顾客一点「我在路上」就准备（太早），AI 把准备推迟到预计到达前，门口停留（冷链风险）减少 5.6 分钟，等待略增。两种情况都是同一条取舍曲线上的不同位置（第 4 节）。
- **AI 替代**主要提高满足率（每天多保住约 8 行），对等待几乎没有影响。
- 在基线上「全部打开」的等待差值不显著，是因为排班的改善和到店时间的推迟互相抵消；门店可以通过第 4 节的参数换一个位置。

## 4. 到店时间修正的取舍曲线

按修正后的到达时间开始准备，再提前 k 个误差标准差（每组 10 天）：

| 基础策略 | k | 平均等待的变化（分钟） | 门口停留的变化（分钟） |
|---|---|---|---|
| 基线 | 0 | +2.47 | −7.82 |
| 基线 | 0.5 | +1.61 | −6.81 |
| 基线 | **1（默认）** | +0.98 | −5.51 |
| 基线 | 1.5 | +0.57 | −4.20 |
| 基线 | 2 | +0.35 | −3.00 |
| 默认档位 | 0 | −0.18 | +0.35 |
| 默认档位 | 0.5 | −0.20 | +0.62 |
| 默认档位 | **1（默认）** | −0.22 | +0.92 |
| 默认档位 | 1.5 | −0.23 | +1.19 |
| 默认档位 | 2 | −0.23 | +1.43 |

和 Phase 1 的「服务与安全优先 / 效率优先」一样，这是一个门店按自己的优先级选择的参数：重视冷链就选小的 k，重视等待就选大的 k。默认档位上 k 超过 0.5 之后等待几乎不再改善、门口停留继续增加，所以对默认档位来说 k = 0.5 更划算；基线上 k 越大等待越接近原来的水平。

## 5. 敏感性：效果大小打折扣后结论还在吗

默认档位、全部打开（每组 10 天，所以与第 3 节的 20 天结果略有差别）：

| 效果大小 | 平均等待 | 90 分位等待 | 迟到订单（%） | 满足率 |
|---|---|---|---|---|
| 默认（离线评估的数值） | −0.68（±0.23） | −1.99（±1.22） | −1.64（±1.49） | +0.08 pp |
| 保守：预测误差 ×2、到店误差 ×1.5、替代提升 1.03、挑选时间只缩短 10% | −0.67（±0.23） | −1.97（±1.12） | −1.64（±1.49） | +0.04 pp |
| 乐观：预测误差 ×0.5、到店误差 ×0.75、替代提升 1.10 | −0.68（±0.23） | −2.07（±1.19） | −1.64（±1.49） | +0.10 pp |

等待和迟到的改善几乎不受预测误差影响：排班的收益主要来自「工作量在一天里的形状」，日总量预测差 10% 或 20% 不改变高峰在哪里。满足率的改善随替代推荐的效果大小线性变化。

## 6. 模型卡片

### 6.1 订单量预测（orders-hourly）

| 项目 | 内容 |
|---|---|
| 用途 | 预测接下来几个营业小时按取货时段的订单量，给出 80% 区间、按温区的商品行数和理由；排班建议的输入 |
| 算法 | 日订单量 ~ 泊松( 局部水平 × exp(已知因素) )，局部水平用指数平滑更新；小时 = 日量 × 最近 8 个普通日子的小时占比。候选还有 3 个基线 |
| 输入 | 历史订单（按取货时段开始时间）；事先可以知道的日特征：星期、节假日（含具体节日）、节前 / 节后、促销覆盖的需求比例、风暴预警（今天、明天）、大雨 / 高温 / 严寒预报 |
| 训练数据 | 仿真预训练：本店配置生成的两年合成历史；真实营业日接管合成数据（订单量达到平时一半以上才用），合成数据权重 28 / (28 + 真实天数) |
| 评估 | 最后 12 周滚动回测（门店服务）；第 2.1 节为一年回测、4 个种子 |
| 上线门槛 | WAPE 至少改善 1%；偏差绝对值、覆盖率偏离 80% 不明显变差；在同一份数据上与当前版本比较 |
| 运行模式 | 只显示（信息类） |
| 局限 | 温区拆分按最近占比分摊；促销对品类结构的影响未建模；本地活动等突发因素只能通过局部水平滞后反映 |

### 6.2 到店时间修正（eta-arrival）

| 项目 | 内容 |
|---|---|
| 用途 | 顾客点「我在路上」后修正预计到达，交付看板按修正时间提醒「即将到达」 |
| 算法 | 线性模型（导航用时、高峰 × 用时、大雨预报 × 用时、周末）+ 顾客习惯的经验贝叶斯收缩；区间为滚动残差的 10% / 90% 分位数 |
| 训练数据 | 仿真预训练（合成到店记录）；上线后用本店真实到店记录更新顾客习惯（演示中按姓名归并） |
| 上线门槛 | 平均绝对误差至少改善 1% |
| 运行模式 | 自动执行（只改变看板提醒时间，风险低、频率高） |
| 隐私 | 只保存每位顾客的到店残差统计，不保存位置轨迹 |
| 局限 | 演示数据没有顾客编号；没有接入实时路况 |

### 6.3 可售概率（shelf-availability）

| 项目 | 内容 |
|---|---|
| 用途 | 发现「系统显示有货、但货架上可能找不到」的商品，生成「核对货架」任务 |
| 算法 | 逻辑回归：本应卖出件数（封顶 20）、估算件数（封顶 12）、是否只剩 1–2 件、距上次员工确认、销量（封顶 6）；线上使用时本应卖出件数按销售比例估计、按负二项分布折算 |
| 训练数据 | 合成货架真实存量（含整批丢失、放错位置、零星损耗） |
| 上线门槛 | Brier 至少改善 1%，校准误差不明显变差 |
| 运行模式 | 需确认；收银流水中断超过 30 分钟时不判断；提醒阈值「找得到的概率」< 35% |
| 局限 | 依赖收银流水；装了传感器的货位由传感器直接确认，不需要这个模型 |

### 6.4 按风险盘点（count-risk）

| 项目 | 内容 |
|---|---|
| 用途 | 每天建议盘点最可能不准的后仓记录 |
| 算法 | 逻辑回归：距上次盘点天数、之后的进出次数、收货差异、可疑、损坏箱数、周转 |
| 训练数据 | 过去的盘点结果（演示中由仿真的前半段提供） |
| 上线门槛 | 同样盘点数量下平均不准的记录数至少减少 1% |
| 运行模式 | 需确认 |
| 局限 | 进出次数由收货 / 补货 / 补取记录近似；效果因门店差别大（第 2.4 节） |

### 6.5 替代推荐（substitution）

| 项目 | 内容 |
|---|---|
| 用途 | 拣货员找不到商品时，按顾客接受的概率排序替代候选，并给出理由 |
| 算法 | 逻辑回归（同品名、同品牌、口味 / 规格一致或不同、有机降级、涨价、降价、受欢迎程度）；硬约束（类别、温区、年龄限制、价格范围）在候选生成时保证 |
| 训练数据 | 合成替代记录（顾客偏好类型看不到）；上线后的信号是拣货员选了第几名 |
| 上线门槛 | 第一名的期望接受率至少提高 1%，NDCG@3 不明显变差 |
| 运行模式 | 排序展示，拣货员自己选；选第一名计为采纳 |
| 局限 | 没有按顾客个人偏好做个性化；顾客交付时拒绝替代品的反馈还没接入 |

### 6.6 排班建议与实时调度（staffing）

| 项目 | 内容 |
|---|---|
| 用途 | 每天的排班建议（各岗位每小时人数）；营业中「要不要从 A 岗位调一个人到 B 岗位」 |
| 算法 | 工作量模型（标准作业时间）+ 最大余数法分配，总工时不变；短时排队估算（先到先服务）+ 待拣工作量与截止时间 + 待暂存框数 |
| 约束 | 固定名单（锁定的员工不调）、只调手上没有任务的人、同岗位里调今天完成任务最少的人 |
| 运行模式 | 排班建议只显示；调动需确认 |
| 伦理 | 不对个人效率排名；不预测个人离职；负荷均衡只看任务数 |
| 局限 | 演示门店没有班表；拣货时长预测（P1）还没做 |

### 6.7 本地助手（assistant）

| 项目 | 内容 |
|---|---|
| 用途 | 店长和员工用一句话提问，回答附数据出处 |
| 组成 | 9 个只读查询工具；本地语言模型（OpenAI 兼容接口）或规则 + 本地意图分类器（朴素贝叶斯）；本地 TF-IDF 检索操作规范与门店经验 |
| 数据 | 只读门店事件流、陈列表、操作规范和门店经验；不发到外部服务 |
| 评估 | 自动生成的评测集与两个留出集（第 2.6 节） |
| 局限 | 真实本地语言模型待下载后对比；问答记录与「有用 / 没用」反馈还没有进入事件流 |

### 6.8 熟食制作时长（mto-prep，Phase 6）

| 项目 | 内容 |
|---|---|
| 用途 | 预测一张现做单的制作时长，调整熟食看板上的建议开始时间 |
| 算法 | 每道菜的本店系数（向 1 收缩的估计）× 标准时长 + 厨房负荷效应（同时段在做的单数） |
| 训练数据 | 合成制作记录（每道菜的真实系数和负荷影响看不到） |
| 评估 | 前 70% 训练：按标准时长的平均误差 6.4–7.3 分钟 → **1.8 分钟**（3 个种子，见 [扩展业务模块](12-business-modules.md) 第 3.1 节） |
| 运行模式 | 默认自动执行（只改变提醒时间；看板同时显示标准时间） |
| 局限 | 没有食材库存和配方；负荷只按单数计 |

### 6.9 退货去向（returns-disposition，Phase 6）

| 项目 | 内容 |
|---|---|
| 用途 | 每件退货建议去向（回架 / 报废 / 危险品回收 / 退供应商），给出能再售的概率和理由 |
| 算法 | 逻辑回归（状态、易腐、离开冷链的时长、化学品）+ 规则（开封的化学品 → 危险品回收；高价损坏的非易腐品 → 退供应商） |
| 上线门槛 | 判断正确率至少提高 0.2 个百分点，误判回架不能明显变差 |
| 结果 | 超市：82.3% → **83.4%**（可售却报废 −1.5 个百分点）；建材店与规则相同，门槛保留规则 |
| 运行模式 | 只显示建议；硬性规则（决策 RT-02：冷链食品不回架、散件开封不回架、损坏不回架、化学品不进普通垃圾）先过滤，建议和员工的选择都只能在允许的去向里；与建议相同计为采纳 |
| 局限 | 没有原订单时交付时长按 24 小时估计（理由里注明）；合成数据里的再售因素与规则重合较多 |

## 7. 怎样读这些数字

- **都是相对比较**：同一份合成数据、同一套随机事件下，比较「有 AI」和「没有 AI」或不同方法；绝对值取决于合成数据的参数，不能当作真实门店的预期。
- **离线评估和运营仿真是两层**：第 2 节量模型本身准不准；第 3–5 节把离线评估得到的效果大小放进运营仿真，量对等待、迟到、冷链和满足率的影响，并用敏感性分析检查效果大小打折扣后结论是否还在。
- **真实上线前要做的**：用门店自己的数据重新回测（门店服务每晚可以做），影子模式运行一段时间，比较建议和员工实际决策，再决定每个模块用什么运行模式。
