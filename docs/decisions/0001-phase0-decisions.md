## 2. 委托决定：开源边界与许可证（G-08）

依据三个标准：**作品集说服力**、**招聘方视角**、**商业化打包出售**。

### 2.1 方案比较

| 方案 | 作品集说服力 | 招聘方视角 | 商业化 | 是否算「开源」 |
|---|---|---|---|---|
| 全部公开，Apache-2.0 | 高 | 高 | **低**：任何人都可以拿去商用 | 是 |
| 只公开文档，代码全部私有 | 低 | **低**：招聘方看不到真实代码 | 高 | 否 |
| 源码可见许可证（BSL、PolyForm 等） | 中高 | 中高 | 高 | **否**：不符合开源定义 |
| **开放核心 + 双许可** | **高** | **高** | **高** | **是** |

### 2.2 决定：开放核心 + 双许可

| 部分 | 内容 | 许可 |
|---|---|---|
| **公开仓库** | 领域核心、算法、仿真引擎、门店配置 schema 与模板、标签生成、界面组件、模拟器 | **AGPL-3.0**，并提供商业许可（双许可） |
| | 文档、伪代码、效益分析报告 | **CC BY 4.0** |
| **私有仓库** | 生产后端、员工作业端、MTO 看板、外部系统适配器（POS / 订单 / 配送 / 地图）、AI 服务、企业功能（多店管理、单点登录、高级分析） | 专有 |

**理由**：
1. 招聘方能看到真实、可运行、有测试的核心代码，而不只是文档；
2. AGPL-3.0 是开源许可证，「开源参考实现」的说法成立；它要求通过网络提供服务的修改版也必须开源，因此竞争对手很难直接拿去做闭源商业服务；
3. 想闭源使用核心代码的企业可以购买商业许可；生产后端、适配器、AI 服务和企业功能本身就是可以打包出售的部分；
4. 双许可要求作者持有全部版权：接受外部贡献时，需要贡献者签署贡献者许可协议（CLA）。

### 2.3 商业化前的准备清单

- 产品名完成商标检索并注册；
- 完成专利自由实施（FTO）分析和法律复核；
- 准备商业许可协议模板；
- 外部贡献全部有 CLA。

## 4. 由决议引起的设计变更

相对于 v0.1 文档的变化：

| 模块 | 变更 | 依据 |
|---|---|---|
| 时段 | 时段长度可配置为 60 / 120 分钟 | O-01 |
| 订单 | 锁单后不得修改交付方式；司机取消或退回后由门店重选 | S-08 |
| 拣货 | 冷链时限：从第一件冷藏 / 冷冻商品放入拣货框开始计时，上限 60 分钟，按待拣件数动态调整 | P-12 |
| 拣货 | 称重商品按「实际重量 × 单价」计价 | P-05 |
| 拣货 | 补货上架时扫描货位，作为商品位置的主要来源 | P-06 |
| 拣货 | 订单中途取消：暂存扫描时提示「已取消」，放入回收专区 | P-13 |
| 拣货 | 推车满时结束本批次，剩余商品重新分批 | P-14 |
| 大件 | 员工输入可装载件数，系统把剩余件数派给其他员工 | P-07 |
| GM | GM 与其他订单分开配送；单量过少时与后续时段 GM 订单合并 | GM-02 |
| 暂存 | 员工自选格位为主，系统推荐为辅；编码规则管理员可自定义；并框提示；回收专区按温区划分 | S-01、S-02、S-07 |
| 交付 | 新增**行程**：2–4 单一个行程，一个验证码；车内位置为副驾、后排左、后排右、尾箱 | D-01、D-07 |
| 交付 | 不做当场拒收替代品；下单时告知替代品按实际价格计费、只能收货后退货 | D-02、AS-04 |
| 交付 | ETA：GPS + 路线服务（Google Routes 或 OSRM）+ 本地修正模型 | D-03 |
| 交付 | 车位编号缺失时用车型 + 颜色；顾客早到时告知等待时间和原因 | D-08、D-09 |
| 交付 | 状态机只保留主状态 | D-06 |
| 交付 | 服务目标同时考虑员工负荷 | D-11 |
| 标签 | 顾客姓名显示「名 + 姓」，过长时「名 + 姓首字母」；重打不改版本号；统一用冷冻级标签纸 | L-02、L-04、L-05 |
| 后仓 | 每箱打印本地数据库主导的标签；可售区和报废区按温区再分区 | I-02、I-05 |
| 补货 | 交易量低的品类不部署传感器；硬件原型只写指南不做实物 | R-01、R-06 |
| 授权 | 只有永久授权 | X-01 |
| 定制化 | 商品类别字典完全可配置（新增汽车用品等）；定制化范围扩大到商品字典 | C-01 |
| 模拟器 | 模拟经营式交互；2.5D / 3D / 俯视三种视角；多楼层；场景内直接点击补货、拖动改派 | V-01、V-02、V-03 |
| 算法与交互 | 新增 10 条工程约束（EC-1 至 EC-10，见工作流设计 4.14 节）：分箱单遍完成、批次全局划分、不做框间交换优化、拣货顺序即路线顺序、ETA 只触发取出已暂存的框、交付队列先到先服务等 | G-11 |
| MTO | 制作开始时间改为按**时段**和菜品标准制作时长排程，不随顾客实时位置变化；ETA 只用于提醒从保温区取出 | G-11（调整 M-02 默认值） |

## 5. 补充说明

| 决议 | 说明 |
|---|---|
| D-02 + AS-04 | 替代品按实际价格计费且不能当场拒收，因此**下单时的告知必须清晰**；推荐时默认加上价格区间过滤（±50%），避免顾客收到明显更贵的替代品。「允许当场拒收」保留为门店可选配置，默认关闭 |
| D-01 | 行程以 2–4 单为目标；Express 订单或无法合并时允许单单行程 |
| L-02 | 显示全名比只显示姓 + 首字母暴露更多个人信息；显示格式保留为可配置项，其他门店可以改为更保守的格式 |
| L-04 | 丢失的标签之后被找到时，会出现两张相同的标签；系统按标签 ID 做幂等处理，重复扫描视为同一个框 |
| I-02 | 每箱打印标签会增加收货人工。效益报告中会如实计入这部分成本；为降低成本，标签在收货工位按托盘批量打印 |
| P-12 | 冷链时限公式：`clamp(基础 20 分钟 + 0.5 分钟 × 待拣件数, 下限, 60 分钟)`，参数全部可配置；60 分钟仍在 USDA 建议的 2 小时之内 |
| C-01 | 汽车用品中，轮胎通常走 Oversized，铅酸电池、机油属于 Hazmat，按处理方式自动走对应流程 |
| V-02 | 视觉风格参考《原神》《城市：天际线》的氛围（简约卡通渲染），不使用其任何素材、角色或界面元素 |
