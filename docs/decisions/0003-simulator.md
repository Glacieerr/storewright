# 决策记录 0003 · 模拟器工程决策

> 日期：2026-10-20 · 状态：已采纳

## 1. 仿真引擎输出可选的轨迹

- **决定**：`simulateDay` 新增 `trace` 选项，输出员工移动与作业片段、顾客 / 司机会话、暂存占用变化；默认关闭。
- **理由**：动画需要知道每个人在每一刻的位置；由仿真引擎记录比在前端重新推算更可靠，也保证动画与指标来自同一次仿真。
- **约束**：打开轨迹不得改变任何结果；同一员工的片段按时间排序、互不重叠、都在在岗时间内；暂存的每次取出都对应之前的放入。三条均有测试。

## 2. 任何改动都重新仿真整天

- **决定**：改派、调整人数、情景注入、布局修改都从头重新仿真这一天，再回到当前时刻继续播放。
- **理由**：仿真是确定性的，并且足够快（中型店约 0.1 秒）；增量仿真会显著增加复杂度，却没有可感知的收益。

## 3. 播放时钟不进入 React 状态

- **决定**：时钟是一个普通对象，三维场景每帧读取，界面以较低频率订阅。
- **理由**：播放时每帧更新 React 状态会让所有订阅组件以 60 Hz 重渲染。

## 4. 每种视角各自拥有相机和控制器

- **发现**：在同一组件里切换相机时，控制器会在新相机注册之前被创建，拿到空相机导致崩溃。
- **决定**：每种视角是一个独立子树，切换时整体重新挂载；控制器在相机创建之后才创建。三维场景外层加错误边界，场景出错不会让整个界面消失。

## 5. 编辑器在地面上点选最近的通道

- **发现**：俯视图中货架只有约 1 米宽，很难点中。
- **决定**：编辑模式下由一个透明地面统一处理点击和拖拽：选中离点击位置最近的通道中线（2.6 米以内）；拖拽期间暂停镜头平移。

## 6. 配置校验增加「货架重叠」

- **决定**：同一楼层平行的通道，中线间距小于两侧货架所需宽度（每侧 1.5 米）时，校验失败。
- **理由**：拖动通道很容易把它放到另一条通道上；这条规则放在共享的配置校验中，命令行和模拟器都受益。

## 7. 改派以排班调整的形式实现

- **决定**：改派一个员工 = 本岗位从当前小时起排班减 1、目标岗位加 1，然后重新仿真。
- **理由**：与决策 W-03 / W-04 一致——管理员的调整优先于系统建议、按小时生效；也与 Phase 5 的人员调配接口保持一致。

## 8. 界面本地化放在界面层

- **决定**：门店配置中的名称保持为数据（例如模板中的英文通道名），界面显示时再转换为中文。
- **理由**：配置是可以导入导出的数据，不应与界面语言绑定。
