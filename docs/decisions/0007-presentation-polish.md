# 决策记录 0007 · 模拟器展示打磨

> 日期：2026-10-20 · 状态：已采纳

## 1. 按需加载：首屏不带 Three.js

- **决定**：三维场景（`Scene`）、三个较重的数据标签（策略对比、方案与报告、门店定制）用 `React.lazy` 拆成单独的包；环境音只在打开声音时加载；第三方库按 react / three / r3f 分包，Vite 的预加载辅助代码单独成包。
- **理由**：v4.0 的主包约 400 KB（gzip），打开页面后要等全部下载、解析完才有画面。拆分后首屏约 130 KB，界面和数据先出现，场景随后加载。
- **约束**：界面代码不能引用任何会带上 Three.js 的模块。原来混在场景文件里、界面也要用的小东西（卡通材质的渐变色、车型列表、对象位置表、镜头状态、截图）拆成单独的文件，只引用类型。Vite 曾把预加载辅助代码打进 r3f 包，导致主包间接引用 Three.js，因此给它单独分包。

## 2. 英文界面：中文原文就是键

- **决定**：`t('中文原文 {0}', 参数)`；英文界面下查 `EN` 字典，查不到时原样显示。仿真引擎、配置校验产生的中文在显示时用 `translate()` 处理：先查原文，再把数字换成 `{0}`、`{1}` 查一次，最后试正则模板（例如带通道名的校验提示）。标签表（温区、岗位）用 `trRecord` 包一层，读取时翻译。
- **理由**：中文是这个项目的主语言，源码里的中文就是最准确的说明；不另造一套键名，改文案时不用两处同步。引擎和配置包保持纯中文、不依赖界面，Phase 1 的结果和命令行输出不变。
- **Worker**：仿真请求带上当前语言，Worker 加载对应字典后生成通知，切换语言时重新仿真，事件列表也跟着变。
- **按需加载**：英文字典约 21 KB（gzip），单独打包；页面启动、切换语言、Worker 收到请求时先确保字典已加载。
- **覆盖测试**：测试扫描模拟器和引擎的全部源码，提取每一段中文字符串（模板字符串的变量换成占位符），逐一翻译，翻译后仍含中文就失败。只在代码里比较、从不显示的少数字符串列在白名单里。

## 3. 引导讲解

- **决定**：12 步导览，每一步可以执行场景动作（移动镜头、跟随某名员工、切换数据标签、调整时间和倍速），并用聚光框圈出界面上的对应区域（用一个大范围 `box-shadow` 压暗其余部分）；没有目标的步骤，说明卡片放在场景右上角，避开左上角的点选卡片和左下角的小地图。
- **第一次打开**：左上角邀请卡片，三个选项（开始导览、自动巡游、不用了），只提示一次。
- **措辞**：说明文字用中性的称呼（「这名员工」）。

## 4. 自动镜头巡游

- **决定**：巡游接管 3D 透视相机，禁用轨道控制器，按镜头表逐帧计算机位：门店全景环绕、推近线上取货车位、跟拍拣货员（从对象位置表读取当前位置）、暂存区摇臂、后仓、最近的路口、俯瞰。镜头之间从上一镜头的实际画面平滑过渡 1.5 秒。
- **所有机位都由门店配置推导**：楼层范围、取货车位标牌、暂存点、后仓布局、路口位置都来自当前门店，因此换门店、用生成器生成的门店也能直接巡游。
- **开始与结束**：开始时记下视角、倍速和播放状态，切到 3D、30 倍速；结束时恢复。巡游期间界面其他部分隐藏，只留黑边、字幕和镜头进度点；Esc 或点击画面退出。
- **调整**：跟拍镜头最初离人物太近（9 米），画面里只看到货架顶，改为 14 米；停车场镜头最初对着门店正面，与「取货车位」的字幕不符，改为推近取货车位标牌。

## 5. 测试中发现并修复的问题

- 自动包裹 JSX 文本时把模板字符串拆成了几段，生成零碎的翻译键：改为手写的单个 `t('…{0}…')`。
- 组件里的局部变量 `t`（时间）遮住了翻译函数：改名。
- 邀请卡片和无目标的导览卡片挡住小地图与点选卡片：分别移到左上角和场景右上角。
- 场景里的 HTML 标签显示在导览层上面：提高导览层的层级。
- 通用浮动卡片样式的 `top` 把导览卡片拉长：导览卡片覆盖 `top` 和 `max-height`。
