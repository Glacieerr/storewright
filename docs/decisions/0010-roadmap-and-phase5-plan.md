## 1. 调整摘要

| 项目 | 原计划 | 调整后 |
|---|---|---|
| 真实设备 | 两台真机现场验收；接入真实扫码设备 | 不做。保留接口契约、虚拟设备和一致性测试；验收改为多浏览器端到端测试（Phase 7） |
| 门店访谈与试点 | 路线图之外的证据工作 | 不做。全部使用仿真数据，结论标注证据等级 B（仿真实验） |
| 重点 | 各阶段权重相同 | AI（Phase 5）是第一重点，业务扩展（Phase 6）是第二重点 |
| AI 运行方式 | 未定；0001 把 AI 服务列为私有 | **本地优先**：每家店各自定制的数值模型 + 本地小语言模型；云端 API 是可选项，默认关闭 |
| 公开边界 | 0001：生产后端、员工作业端、AI 服务放私有仓库 | **整个产品公开**（AGPL-3.0，保留商业许可的双许可安排）；门店接入方法论的模板和商业材料不公开 |
| 公开演示 | 模拟器部署到子域名 | 新增**浏览器内演示模式**：作业核心在浏览器里运行，多个标签页实时同步，只需静态托管 |
| 方法论 | — | 贯穿 Phase 5–6：每个新模块都按同一套流程建设（问题清单 → 流程设计 → 决策记录 → 门店配置 → 仿真评估），模板另行整理 |

公开边界调整的理由：作品集和参考实现的价值主要来自「能看到完整、可运行的系统」；本地部署、按店定制和接入服务才是商业上难以复制的部分，而 AGPL 已经能阻止他人把修改版做成闭源服务。

## 2. AI 的五条原则

1. **统一的建议记录**：每条 AI 建议都写进事件流，包括动作、置信度、主要理由、备选方案和模型版本；之后再记录员工的处理（采纳 / 否决 / 忽略 / 过期 / 自动执行）和实际结果。否决原因会成为下一轮训练的数据。
2. **三种运行模式**：只显示、需要确认、自动执行。管理员可以按模块设置并锁定。
3. **仿真就是评测场**：仿真知道真实值，所以每个模型的准确率和业务效果都能精确计算。生成器里加入模型看不到的因素（突发的本地活动、需求漂移、天气预报误差），并报告模型在这些情况下的表现，避免模型只是「学会了生成器」。
4. **消融实验**：沿用 Phase 1 的对比框架，逐个打开 / 关闭 AI 模块，计算每个模块各自的贡献（路线图的验收标准）。
5. **两层分工**：判断由轻量的数值模型完成（TypeScript，浏览器和服务端都能运行，结果可复现）；语言模型只负责理解问题、调用查询工具、组织回答，不凭空给出数字。没有语言模型时退回模板解释。

## 3. 本地运行与每店定制

| 层 | 内容 | 按店定制 |
|---|---|---|
| 数据层 | 事件流（已有）+ 门店知识库：布局、陈列表、操作规范、门店政策、供应商到货时间、促销日历、员工技能表 | 是 |
| 特征层 | 从事件流按小时 / 天汇总的特征，所有模型共用 | 是 |
| 数值模型组 | 预测、概率、调度；每晚用本店数据重训，几秒到几分钟完成 | **是（核心定制）** |
| 语言层 | 本地小语言模型（15–40 亿参数，4-bit 量化），通过工具查询数据 | 只微调行为（可选） |
| 语音层 | 本地语音识别与合成 | 否 |
| 寻优层 | 用模拟器搜索排班、暂存区和作业策略的更优组合 | 是 |
| 模型管理 | 版本、上线门槛（新模型在回测中胜过当前模型才上线）、影子模式、回滚、漂移监控 | 是 |
| 云端 API | 可选，默认关闭 | — |

- **店铺数据不训练进语言模型的参数**：库存、订单、排班每分钟都在变，小模型记数字容易编造，重训成本高；员工离职后个人数据必须能删除，而写进参数的内容删不掉。语言模型通过工具实时查询，微调只用于门店术语、回答格式和工具调用，训练数据由模拟器生成。
- **定制流程**：接入（门店配置 + 可选的历史数据）→ 仿真预训练（用该店配置生成一到两年的合成历史，第一天就有可用的模型）→ 真实数据接管（每晚增量训练，仿真数据的权重逐步降低）→ 影子模式上线 → 漂移监控。
- **员工数据**：按「岗位 + 任务」建模，不按个人建模；新员工用全店的「入职时长 → 熟练度」学习曲线起步，数据积累后逐步个人化；技能与授权是明确录入的数据，排班时作为硬约束；离职后个人数据按保留期删除或匿名化，只保留岗位层面的汇总。
- **伦理边界**：不预测个人离职风险；个人效率只给本人看，管理者看团队汇总；排班考虑负荷均衡和劳动法约束（休息、最长工时、未成年人）。
- **运行环境**：语言模型通过本地推理服务（llama.cpp / Ollama 一类，提供 OpenAI 兼容接口）调用；行为微调用 MLX 或租用 GPU，放在单独的离线训练目录（Python），不影响主程序。开发机（8 GB 内存）可以运行 15–30 亿参数的量化模型；门店硬件按 16 GB 内存的迷你主机考虑。模型系列优先选择中文能力强、许可证允许商用的开源模型，具体版本到 5d 时按当时的评测确定。

## 5. Phase 5 分解

| # | 内容 | 验收 |
|---|---|---|
| **5a 框架** | AI 公共包（建议格式、指标、回测、模型仓库与上线门槛、基线预测器、特征）；带隐藏因素的合成历史；建议与模式的事件、命令和状态；后端的仿真预训练、模型仓库持久化、预测建议；员工端「AI」页（建议卡片与理由、模式设置、模型版本与回测指标） | 基线模型在合成历史上完成回测；更差的候选模型被上线门槛拒绝，可以回滚；一条建议从发出到被采纳 / 否决（附原因）全程记录在事件流里并显示理由；Phase 1 对比输出不变 |
| **5b 预测** | 订单量预测（按小时、温区；促销 / 天气 / 节假日特征）、到店时间修正、可售概率与幽灵库存、按风险盘点、拣货时长 | 每个模型在回测中胜过基线，并报告漂移和隐藏因素下的表现；概率模型给出校准曲线 |
| **5c 决策** | 替代推荐与接受率、排班建议与实时调度、补货优先级学习；模拟器接入 AI 建议 | 模拟器中 AI 开 / 关的对比结果；每条决策都有可读理由 |
| **5d 语言层** | 本地小语言模型 + 查询工具：运营问答、「如果……会怎样」推演、门店经验库、交接班摘要；无模型时的模板退化；仿真生成的问答评测集 | 本地模型与云端模型在问答评测集上的准确率与成本对比 |
| **5e 报告** | 消融实验、模型卡片、AI 部分的效益报告 | 每个 AI 模块各自的贡献；所有数字注明来自仿真 |

### 5a 细节

- `packages/ai`（公开，纯 TypeScript，浏览器和 Node 通用）：
  - 建议格式：类型、目标、动作、置信度、理由（因素代码 + 数值 + 贡献，界面按语言显示文字）、备选方案、模型版本、运行模式、过期时间；
  - 指标：MAE、RMSE、WAPE、偏差、分位数损失、区间覆盖率、Brier 分数、对数损失、校准分箱；
  - 回测：滚动起点回测，任何「拟合 → 预测」的模型都能接入；
  - 模型仓库：版本、指标、状态（候选 / 当前 / 已退役），上线门槛（主指标改善且护栏指标不退化），回滚；可以序列化保存；
  - 基线预测器：同时段上周值、近几周同时段平均、按星期和小时的季节性指数平滑；它们是 5b 模型必须胜过的对照。
- `packages/synth` 新增合成历史：星期效应、节假日（节前抢购、节日当天下降）、季节与天气（模型只能看到带误差的天气预报）、每周促销（模型知道促销日历，但不知道提升幅度）、缓慢的增长趋势、模型看不到的本地活动和一次结构性变化。默认不启用，Phase 1 结果不受影响。
- `packages/ops`：建议发出 / 处理事件、模块模式事件；采纳、否决（必须选择原因）、忽略、设置模式等命令；Tick 让过期的建议失效。只有带班负责人和控制台可以处理建议、设置模式。
- 后端：启动时用该店配置生成合成历史，完成仿真预训练和回测，把模型版本写入数据库；每小时发出一条未来几小时的订单量预测建议；提供模型列表和重新训练接口。
- 员工端：带班负责人的「AI」页。

## 6. Phase 6 调整：可插拔的流程模块

- 每个模块包括：配置开关（路线图验收标准）、自己的事件与命令、员工端页面、模拟器可视化、文档、一个 AI 接入点（熟食现做 → 出餐时间预测；退货 → 去向判断；大件 → 装载规划；包裹中转 → 格位分配）。
- 顺序：熟食现做 → 退货 → 大件（先扫后打、装载上限）→ 包裹中转。可选：第三方配送员交接、自提柜、药房取药（仿真引擎已有药房柜台排队）。
- 最后用同一套核心做**一个其他行业的模板**（药店、便利店、家居建材或餐饮之一），记录哪些部分改了、哪些直接复用，作为「流程可以迁移到不同行业」的证据。

## 7. Phase 7 调整

- 浏览器内演示模式（作业核心在浏览器里运行，标签页之间同步；展示页同时显示模拟器和两部手机画面）；真实后端继续用于本地运行和自托管。
- 多浏览器端到端测试（店长 + 两名员工，覆盖拣货 → 交付、补货等流程），代替真机验收；持续集成跑类型检查和全部测试。
- 公开演示中的语言模型：预设问题使用预先生成的回答；访客可以选择在浏览器里用 WebGPU 运行小模型（首次需要下载）。不在前端放任何 API 密钥。
- 英文文档、部署、个人网站项目页、演示视频；按阶段整理提交历史后再上传。

## 9. 5a 实施结果与偏差

- **完成**：AI 公共包（建议格式、指标、滚动回测、模型仓库与上线门槛、三个基线预测器、按小时序列）、带隐藏因素的合成需求历史、作业核心的建议与模式（5 个命令、3 个事件、统计、过期、取代、条数上限）、后端门店 AI 服务（启动时仿真预训练、`ai_state` 持久化、每小时预测建议、模型 / 重新训练 / 回滚 / 立即预测接口）、员工端「AI」页（建议、模式与统计、模型，中英文）。新增 17 个测试，全部测试 155 个通过。Phase 1 用到的代码没有改动，对比实验结果不变。
- **结果**（证据等级 B）：中型店、8 个种子的按小时 WAPE：上周值 26.2%、近 4 周平均 21.6%、季节性指数平滑 20.3%，理论下限（已知真实期望值）17.6%；特殊日子上平滑模型为 23.8%，是 5b 的主要改进空间。详见 [门店 AI](../10-store-ai.md) 第 6 节。
- **偏差一：上线门槛比较同一份数据**。重新训练会生成新的合成历史，旧版本的指标来自另一份数据，不可比；改为把当前版本在新数据上重新回测后再比较。
- **偏差二：5a 只允许信息类建议**。自动执行模式下，未实现的动作如果被记为「已自动执行」会误导使用者，所以作业核心拒绝未知动作，等对应模块实现后再加入。
- **偏差三：回滚过的版本不再被自动恢复**。最初连续回滚会在两个版本之间来回切换，改为给回滚掉的版本打标记。
- **发现的问题**：带班负责人多一个标签后底部标签栏在手机宽度下溢出（改为按标签数自动分列）；界面上混排的全角标点没有经过翻译（改为整句模板）。

## 10. 5b 实施结果与偏差（2026-10-22）

- **完成**：订单量的已知因素回归（局部水平 × 节假日 / 具体节日 / 促销 / 风暴预警 / 天气预报，按温区的商品行数）、到店时间修正（固定效应 + 顾客习惯的分层收缩，默认自动应用到交付看板）、可售概率与幽灵库存（逻辑回归，「核对货架」任务闭环）、按风险盘点（逻辑回归 + 同一套随机数下的策略比较，「AI 按风险建议」的盘点）；真实营业日接管合成数据（质量检查 + 合成数据降权）。拣货时长预测（P1）推迟到 5c 与人员调配一起做。全部测试 164 个通过。
- **结果**：见 [门店 AI](../10-store-ai.md) 第 6b 节。订单量按小时 WAPE 18.5%（平滑 19.3%，下限 16.7%），特殊日子 19.1%（平滑 32.8%）；到店时间平均误差 3.8 分钟（只信导航 5.5）；可售概率 AUC 0.93–0.95、校准误差 0.1%–0.4%、提醒精确率 83%–91%；按风险盘点让平均不准的记录数减少 7%–26%。
- **偏差一：可售概率的特征封顶**。演示门店的货架容量比训练数据大得多，逻辑回归在大件数上外推，把整批找不到的商品判成「有货」；估算件数、销量的特征改为封顶。
- **偏差二：本应卖出件数改用销售比例估计**。演示中客流仿真是加速的，按真实时间估计的销量跟不上，沉默证据积累太慢；改为「卖得正常时占全店销量的比例 × 之后全店卖出的件数」，并向计划比例收缩。
- **偏差三：沉默证据按负二项分布折算**。线上销量是估计值，直接套用训练时的泊松假设会把偶然的空档当成幽灵库存（同一时段 2–4 个误报）；折算并把提醒阈值设为 35% 后没有误报。
- **偏差四：到店时间修正默认自动执行**。它只改变交付看板的提醒时间，风险低、频率高，逐条确认会打扰员工。

## 11. 5c 实施结果与偏差（2026-10-22）

- **完成**：替代推荐的学习排序（拣货界面显示预计接受概率与理由，选第几名计入采纳率）、排班建议（总工时不变、按预测工作量分配）、实时调度（短时排队估算、固定名单、负荷均衡，`MOVE_ASSOCIATE` 动作与岗位调动命令）、仿真引擎的 AI 开关（排班、到店时间、替代）、模拟器的「AI」开关与实时面板的 AI 建议。全部测试 171 个通过；Phase 1 对比输出逐字节不变。
- **结果**：替代推荐第一名的期望接受率 69.6%–71.3%（现有规则 64.6%–66.2%，上限 70.5%–72.0%）。仿真开 / 关对比见 [AI 效益报告](../11-ai-results.md)。
- **偏差一：交付等待改用短时排队估算**。稳态排队公式在超载时给出无穷大，截断后「多调一个人」反而看不出改善；改为按现有排队和接下来一刻钟的到达做先到先服务的估算，人数越多等待越短。
- **偏差二：AI 到店时间在仿真里要留余量**。在基线策略（原来顾客一点「我在路上」就开始准备）上直接按修正的到达时间准备，门口停留大幅减少，但平均等待增加 2.4 分钟；按误差的一部分提前开始后变成可调的取舍（见效益报告的取舍曲线），默认留 1 个误差标准差。
- **偏差三：拣货时长预测推迟**。排班工作量先用标准作业时间估算，拣货时长模型留作后续改进。
- **偏差四：替代推荐不单独记建议记录**。拣货时选替代品很频繁，每次都发建议会淹没事件流；改为把「选的是第几名、模型版本」写进替代事件，统计口径不变。

## 12. 5d 实施结果与偏差（2026-10-22）

- **完成**：9 个查询工具、本地语言模型接口（OpenAI 兼容，最多 4 轮工具调用，出错退回模板）、模板模式（规则 + 本地意图分类器）、操作规范（15 条中英文）与门店经验库（事件流记录）、本地 TF-IDF 检索、「如果……会怎样」一句话推演、交接班摘要、问答评测集与两个留出集、员工端「问答」与「门店经验」。
- **结果**：评测集 / 留出集 A / 留出集 B 的工具选择准确率：只用规则 100% / 55.6% / 53.6%；规则 + 本地意图分类器 100% / 74.1% / 67.9%。详见 [门店 AI](../10-store-ai.md) 6d.2。
- **偏差一：真实本地语言模型推迟到获得同意后**。下载推理服务和模型（约 1–2 GB）属于需要使用者确认的操作；先完成接口、评测和模拟测试，模型对比在确认后补上。
- **偏差二：新增本地意图分类器**。留出集显示规则只能答对一半左右，在没有语言模型的情况下用一个几毫秒训练完的朴素贝叶斯分类器补强，既是可用的兜底，也是「本地小模型」的最小版本。
- **偏差三：评测纪律**。第一次写的分类器训练语料里混进了留出集原句，发现后删除，并另写留出集 B 只运行一次；文档同时给出两个留出集的成绩和偏差说明。
- **偏差四：找商品要处理同名商品**。演示目录里有同名的不同规格，助手改为同名商品一起列出，经验也一起显示。

## 13. 5e 实施结果（2026-10-22）

- **完成**：`npm run ai-report` 一次生成五个模型族的离线评估（多个种子）、运营上的 AI 开 / 关对比（公共随机数、配对差值与置信区间）、到店时间修正的取舍曲线和效果大小的敏感性分析（约 25 秒）；[AI 效益报告与模型卡片](../11-ai-results.md)。仿真引擎支持按场景覆盖 AI 效果大小。
- **主要结论**：默认档位上全部打开 AI，总工时不变，平均等待 −13%、90 分位等待 −23%、迟到订单 2.41% → 0.69%、满足率 +0.09 个百分点，代价是门口停留 +0.86 分钟（可调）；AI 排班贡献最大；按风险盘点的效果因门店差别大（−1% 到 −26%）。
