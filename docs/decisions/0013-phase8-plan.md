## 1. 全流程走查与「无法操作」的原因

- 走查 11 个部分、107 步全部通过（2026-10-22 再次运行）。
- **演示控制台在笔记本屏幕上几乎无法操作**：展示页把模拟器和控制台上下叠在左栏，1440×900 时控制台只有约 290 像素高，1280×720 时只剩约 120 像素，「创建」按钮和订单表要在小框里滚动，提示条还会盖住订单表；手机的底部标签栏也被截掉。功能本身是好的（走查用的是程序点击，所以没发现）。
- **修复**：左栏改成可切换的画面：控制台 / 门店实况 / 全天仿真 / 上下并排（屏幕高度 ≥ 980 像素时默认并排，否则默认只显示控制台，选择会被记住），每个画面都可以「在新标签页打开」；控制台和手机至少 560 像素高，不够时整页滚动。走查新增检查：900 像素高的屏幕上控制台高度超过 560 像素。

## 2. 双线并行：你的操作 + 全流程自动模拟

两条线同时运行、互不混在一起：

| | 你的操作（模拟操作） | 自动运营（全流程自动模拟） | 全天仿真 |
|---|---|---|---|
| 在哪里 | 展示页的两部手机 + 控制台 | 控制台「自动运营」卡片 | 展示页左栏「全天仿真」 |
| 谁来做 | 你 | 虚拟顾客、虚拟拣货员 / 暂存员 / 交付员 / 司机（V-P1、V-S1、V-H1、V-D1……） | 模拟器的离散事件仿真（虚拟顾客、员工、车辆、货车） |
| 时间 | 真实时间 | 真实时间（作业速度可调 1–4 倍） | 仿真时间（1–900 倍速，可拖动时间轴） |
| 门店 | 浏览器里的同一家门店（同一个中枢、同一个事件日志） | 同上 | 模拟器自己的门店副本 |
| 互相影响 | 共用暂存区、货架库存、门店 AI | 同上 | 无 |

**设计要点**：
- 订单带 `track: 'AUTO'`；作业核心对自动运营的订单**单独分批、单独组行程**，员工手机的批次列表和交付看板不显示它们，控制台默认也不列出（可以勾选显示）。两条线共用同一个暂存区和货架，暂存占用、缺货、AI 建议会相互影响——这正是双线并行要展示的东西。
- 虚拟员工用和手机完全相同的命令完成作业（领取批次、绑定标签、逐站拣货、暂存、开始准备、逐框扫描、核验取货码、完成交付；配送行程由虚拟司机接单、到店交接），不走任何捷径；每一步按「大概要多久」排队。取货码和司机验证码由门店的盐和编号算出，中枢重启后虚拟员工仍然知道。
- 门店实况里能看到虚拟员工的位置（V-P1、V-S1……）、自动运营顾客的车和暂存占用。
- 全天仿真是模拟器自己的离散事件仿真，按策略跑完一整天，和门店实况同时运行，互不影响；用来看完整一天的节奏、车辆和指标。

## 3. 车辆拟真

现状（详见调查记录）：所有车辆是合并成两块网格的简单几何体，车轮不转、不转向；40 多米长的半挂车是一整块刚体绕中心转；路径是折线，航向逐段跳变，速度逐段突变，没有加减速；倒车只是把航向反过来；没有刹车灯、转向灯、倒车灯；卸货门、车厢门、后备箱都不会打开；同一个卸货门可能同时停两辆货车；配送没有出车和回程；门店实况里只有半透明方块。

设计：

1. **统一的运动学**（`scene/kinematics.ts`，纯函数、可测试、按仿真时间确定）
   - 路径 = 一串机动段（前进 / 倒车 / 停靠等待），前进段用圆弧平滑转角，按弧长参数化；
   - 速度剖面：按车型的最大加速度、减速度和转弯的最大侧向加速度（v ≤ √(a·R)）生成梯形速度曲线，起步、刹车、过弯都有加减速；
   - 后轴参考点 + 自行车模型：车身航向沿路径切线，前轮转角 δ = atan(轴距 × 曲率)，车轮按行驶距离转动；
   - **铰接半挂车**：牵引车沿路径行驶，挂车航向按 θ′挂 = (v / L挂) · sin(θ牵 − θ挂) 沿路径积分（内轮差、甩尾都会出现）；倒车进卸货口时规划挂车后轴的路径（先拉直、再沿缓弯退入），由挂车姿态反推牵引车姿态；
   - 灯光：减速时刹车灯、倒车时倒车灯、转弯前 15 米打转向灯、停靠卸货时双闪；夜间车灯位置按车型。
2. **车型与模型**：长途半挂车（牵引车 + 53 英尺厢式挂车，冷藏挂车带冷机）、厢式货车（箱货）、门店配送面包车、各类顾客车辆、出租 / 网约车、校车 / 公交（背景交通）、叉车和地牛；车身、车轮分开实例化（车轮能转、能转向），保持每种车 2–3 次绘制调用。
3. **场景动效**：卸货门（卷帘门）随停靠升降，卸货平台和防撞块；挂车尾门打开，车厢里能看到托盘，卸一托少一托；叉车倒出挂车（不再在车厢里原地掉头）；配送车尾门、顾客车后备箱在交付时打开。
4. **调度**：卸货门占用——同一个门同一时间只停一辆车，其他车在场地排队等门；取货车位满时顾客的车在排队车道等待，不再画到同一个车位里。
5. **配送车队**：门店配送车装车后出发，沿道路驶离，按行程时长在外配送，再回到门店（视觉层，不改变仿真指标）。
6. **门店实况里的车辆**：顾客到店的车（按顾客上报的车型和颜色）、配送行程的司机车、到货的货车都按真实模型显示，并有背景交通。

**约束**：Phase 1 的对比实验结果必须逐行一致（车辆拟真只在模拟器的显示层和可选的仿真模块里）；60 帧（大型门店高峰时段）。

## 4. 区域划分与管理

现状：只有暂存货架是存储的数据；后仓、收货区、停车场都由几个数字按固定公式算出来；待检、退供应商、报废、冷藏库、冷冻库、大件、包裹区是代码里的固定列表，没有位置。

设计：

- 门店配置新增**区域**（`areas`，可选；不设置时由现有公式生成默认区域，旧配置和模板不变）：每个区域有类型、所在楼层、矩形位置和尺寸、温区、容量（托盘 / 箱 / 框 / 件 / 包裹）和预警阈值。类型包括：
  - 收货：卸货门（单独的 `docks`：所在墙、位置、高台或地面、是否冷藏）、卸货区、收货暂放区、待检区（QA）、退供应商区（RTV）、顾客退货处理区、空托盘区、纸箱打包 / 回收区；
  - 后仓存储：常温货架区、冷藏库、冷冻库、高位 / 过量库存区、大件区（含室外堆场）、贵重 / 年龄限制商品笼、化学品隔离区、设备充电区；
  - 暂存：自取暂存道、配送暂存道、大件暂存区、熟食保温区、包裹区、回收专区。
- 作业核心的库位、暂存格位、包裹格位、保温格位、大件区都从区域生成并带上区域编号（不再是代码里的固定列表）；库位建议按区域和温区。
- **管理**：控制台和后仓页面有「区域」视图（每个区域的占用、容量、预警）；模拟器新增「区域占用」图层，按占用给区域着色，点击区域查看明细；超过阈值时提醒。
- **编辑器**：区域图层——画矩形、移动、调整大小、设置类型 / 温区 / 容量；卸货门沿墙增减和移动；校验（区域重叠、超出建筑、卸货区要靠着卸货门、暂存区要靠近交付门、必需的区域类型都有）。

## 5. 线上取货车位

- 场地配置新增**车位**：停车行（位置、长度、方向、类型：普通 / 线上取货 / 混合）和**线上取货车位列表**（编号、位置、朝向）；不设置时按现有规则生成（第一排靠近交付门的车位）。
- 编辑器：设置数量、拖动每个车位或整排、自动编号；
- 作业核心：顾客到店时的车位必须是配置里的编号；看板和门店实况按编号显示；
- 仿真（可选）：取货车位满时顾客在排队车道等待，计入等待时间（只在配置了明确车位时生效，模板不受影响）。

## 6. 「你的商店」（产品设计；商业与付费方案见作者私人文档）

**定位**：访客在网站上从零搭建自己的门店，在线进行全流程模拟经营和区域管理。

**流程**：
1. **新建门店**：选择行业（超市 / 建材 / 自定义）、规模、场地大小（或从模板开始）；
2. **搭建**（分图层编辑，全部可改）：场地与道路、停车与取货车位 → 建筑外轮廓、楼层、出入口、交付门 → 卖场货架排布（通道、靠墙货架、端架、促销台）、品类分布 → 后仓区域、货架、冷库 → 收货区与卸货门 → 暂存区与暂存道 → 设施（汽车服务、园艺、药房、熟食）；
3. **运营设置**：营业时间、员工名单与排班、需求水平与品类结构、作业规则（时段长度、锁单提前量、冷链时限、暂存阈值……）；
4. **开业检查**：校验全部规则（重叠、可达性、必需区域、容量与需求是否匹配），给出修改建议；
5. **运行**：全天仿真（策略对比、报告、AI）+ 实时沙盒（你的操作 + 自动运营，跑在你自己的门店上）；
6. **管理与改进**：区域占用、瓶颈分析、改布局后同一批订单再跑一次对比。

**技术方案**：
- 全部在浏览器里运行（模拟器、门店中枢、AI 都已经能在浏览器里跑），服务器不承担计算；
- 门店项目 = 门店配置（含区域、卸货门、车位、场地）+ 运营设置 + 方案，带版本号，保存在浏览器的 IndexedDB，可以导出 / 导入文件；
- 门店中枢支持从自定义配置建店（现在只能用模板）；
- 付费：付费部分（项目页、项目栏、门店项目的保存、授权码）放在线上版的私有模块里，本仓库只保留接入点（第 9 节）。

## 8. 结果（2026-10-22）

- **展示页**：1280×720 的屏幕上控制台从约 120 像素高变成整个左栏（走查检查 900 像素高时超过 560 像素）。
- **双线并行**：每小时 160 单、作业速度 4 倍时，自动运营的订单从下单到交付大约几分钟完成；批次和行程从不混在一起；员工手机上看不到自动运营的批次（单元测试、端到端测试、走查都检查）。
- **区域**：默认区域与原来的布局一致（中型店的托盘位因为分出冷藏库和冷冻库从 51 个变为 36 个）；默认区域写进配置后结果不变（测试）；Phase 1 对比实验、AI 效益报告、行业迁移报告与之前逐行一致。
- **车辆**：所有车辆起步、刹车、过弯都有加减速，车轮转动和转向，车灯随状态变化；半挂车倒车靠台时铰接角最大约 61°；同一个卸货门不会同时停两辆车。
- **你的商店**：在浏览器里从想要的占地生成门店（想要 60 × 36 米时生成 61.2 × 36.1 米），编辑、开业检查、全天仿真、自动保存；专业版用测试授权码激活后，实时沙盒在浏览器里的门店中枢按这家门店的配置建店（门店编号 `my-<配置哈希>`，改过布局就是新的门店）。

## 9. 作者的决定（2026-10-22）

| 事项 | 决定 |
|---|---|
| 免费与付费 | 免费搭建并运行一家门店（编辑、开业检查、全天仿真）；保存多家门店、导出 / 导入、在自己的门店上开实时沙盒、完整报告与多日推演属于专业版 |
| 收费方式 | 一次性购买，授权码不过期，适用于购买时的大版本 |
| 账号 | 不需要；授权码在浏览器里用公钥离线验证 |
| 收款 | 通过代收税费的平台销售 |
| 代码 | 付费部分放在私有仓库，本仓库不包含 |

**本仓库因此：**
- 只保留接入点 `apps/simulator/src/extensions.ts`：`loadYourStore()` 通过 Vite 别名 `virtual:your-store` 加载私有模块，不存在时指向 `yourStoreStub.ts`（导出 `undefined`），网站上不出现「你的商店」按钮和项目栏，其他功能不变；
- 通用能力留在本仓库：自定义配置建店（门店中枢 `POST /api/custom-stores`，门店编号 `my-<配置哈希>`）、区域与卸货门编辑、取货车位编辑、开业检查（`goLiveCheck`）；
- 报告面板在打开门店项目时通过接入点检查付费功能（`request('fullReport')`）；没有门店项目时（模板门店）一切照旧免费；
- 端到端测试的「你的商店」场景和走查第 15 部分在私有模块不存在时跳过。
