## 1. 所有平台都能用

**测试矩阵**（`npm run e2e:browsers`，持续集成里也跑）：

| 项目 | 浏览器 | 场景 |
|---|---|---|
| live / demo / a11y | 本机 Chrome（持续集成里是 Playwright 的 Chromium） | 真实后端 4 个、浏览器内演示 8 个、无障碍 3 个 |
| live-webkit / demo-webkit | WebKit（Safari 内核） | 同上 12 个 |
| live-firefox / demo-firefox | Firefox | 同上 12 个 |
| demo-no-sharedworker | Chromium，去掉 SharedWorker（较旧的安卓浏览器、部分 App 内置浏览器） | 浏览器内演示 8 个 |
| iphone | WebKit + iPhone 14 设备参数 | 窄屏展示页、手机宽度的模拟器 |
| android | Chromium + Pixel 7 设备参数，去掉 SharedWorker | 同上 |

合计 51 个，全部通过。另外在三个内核里截图检查了三维场景（WebGL 正常、没有控制台错误）。

**发现并修复的问题**

1. **不支持 SharedWorker 时，展示页里的模拟器连不上同一家店**：iframe 只向直接的上层窗口要端口，而模拟器里还嵌着一层桥接页面，问到的是模拟器（不提供端口），于是另开了一家店。现在先问最上层的窗口，再问直接的上层窗口。
2. **不支持 SharedWorker 时数据不保存**：专用 Worker 现在用 Web Locks 拿写入锁，拿到了（通常是唯一的标签页或展示页）就保存到 IndexedDB；拿不到说明另一个标签页在用，这个标签页的门店是单独的、只放内存，页面上显示说明（多设备同步请用展示页）。
3. **测试配置**：本机 Chrome 的 channel 设置被 WebKit、Firefox 项目继承，浏览器根本启动不了；改为只给 Chromium 项目。
4. 交付员手机上扫描框的提示文字被截断：改短为「扫码或输入」。

安卓 Chrome 从 148 版（2026 年）起重新支持 SharedWorker，较新的安卓手机走正常路径；退路保证旧版本和 App 内置浏览器也能用。

## 2. 演示更稳、更轻

- **模拟器的桥接连接失败后能恢复**：连接层原来会缓存「拿端口失败」的结果，之后只能刷新页面；现在失败不缓存，模拟器自动重试 3 次（1.5、4、8 秒），每次重新建桥接页面。
- **浏览器里的门店中枢从 461 KB 减到 323 KB**（−30%）：标签生成（含二维码库）只在打印标签时加载；门店配置的完整校验（含 zod）拆成 `@storewright/store-config/validate`，只在访客提交自己的门店时加载；助手推演用的仿真引擎只在问「如果……会怎样」时加载。
- **门店客流仿真按门店时间走**：原来按墙上时钟的钟点决定客流，深夜打开演示时客流只有白天的三成，测试也会在深夜失败（全套测试时发现）。现在仿真有自己的门店时间：营业时间内从现在的钟点开始，否则从早上 9 点开始，跟着加速走；控制台显示门店时间。
- **场景标签去重叠**：镜头远的时候区域标签互相压住（冷藏库压冷冻库、通道号挤在一起）。每 250 毫秒按屏幕位置检查一次，重要的先放（取货车位、楼层、主要区域、冷库和柜台、通道号），重叠的暂时隐藏。

## 3. 补齐小缺口

- 模拟器的策略对比、方案对比和导出的报告里，建材店不再显示「化学品与食品混装」（商品都不是食品，永远为 0），门口停留去掉「冷链风险」字样。命令行的研究报告保持原样，结果文档要能逐行复现。
- 「配送车出车后回到车队」不做：仿真里的配送是外部司机接单取货，门店没有自己的车，画回程会和仿真对不上；以后做「自有配送车队」模块时一起做。

## 4. 无障碍

自动检查（`e2e/a11y.spec.ts`，登录、拣货员、交付员、带班负责人、控制台、展示页、模拟器，浅色和深色主题）：

- 所有按钮、链接、输入框都有可读的名称（原来就没有问题）；
- 文字对比度达到 WCAG AA。修复：模拟器的绿色按钮（白字 3.15 → 加深为 #2b7d52，5.05；深色主题改深色字）、取货车位牌（2.5 → 5.2）、次要文字灰色、图表图例（文字用正文颜色，颜色只留在色块上）；员工端深色主题的红色角标（深色字）、冷藏冷冻标签（用主题里的温区颜色）、自动运营的状态标签；展示页深色主题的品牌绿；
- 模拟器和展示页加了清楚的键盘焦点样式；
- 只用键盘可以登录（Tab 到员工、回车）。
