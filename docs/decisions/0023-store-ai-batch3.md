## 1. 冷链分批与转交（B3）

作业核心 `packages/ops/src/coldchain.ts`，服务端 `OpsAiService.coldSplit` / `coldWatch`。

- **领取前拆批**：冷藏 / 冷冻批次生成时，用拣货时长模型估计「从第一件放进框到送回暂存」要多久；超过冷链时限的 95% 时，按订单在路线上的先后切成两个批次（路线顺序不变、框不重不漏），拆出来的批次各自再估一次（`SPLIT_WALK`，拣货模块自动执行）；已经领取的批次不拆；
- **拣货中预警**：每 30 秒按剩余货位和这一批到现在的快慢估计还要多久（`remainingPickSec`），预计会超时 60 秒以上时，拣货页出现横幅和「剩下的转给别人，先送回暂存」；提醒提前发给正在拣的人（`COLDRISK:`，比超时告警早）；
- **转交**（`HandOverLines`）：没拣的行进一个新批次（补新框、打印新标签，优先领取），原批次只留拣了的、马上可以完成；一件都没拣的框作废；只有拣这个批次的人能转交。

## 2. 分框学习（B7）

- 拣货中框装满了：「框 1/3 装满了？加一个框」（`AddTote`）——同一订单补一个框、打印标签，这个框里还没拣的商品挪进新框；
- AI 从加框记录学分框系数：按这一单各类商品的体积占比调高这些类别的系数（没加框的慢慢回到 1，限制在 0.8–1.6），写进作业核心（`UpdateToteFactors`）；锁单分框（`assignTotes` 的体积系数，锁单的两条路径都用）按系数算，以后少分错。

## 3. 按到店时间暂存，未取订单（B5）

- **暂存格位**：建议格位时看顾客多久到（≤ 30 分钟的放离交付区近的格位，≥ 90 分钟的放远的；格位距离来自布局）；
- **未取的风险**：合成数据 `packages/synth/src/noShows.ts`（1000 位顾客、240 天，有模型看不到的个人习惯），模型 `packages/ai/src/noShow.ts`：规则（没报预计到达）和逻辑回归（提前几小时下单、取货时段、星期、下雨、有没有报预计到达、以前下单和爽约的次数）两个版本，上线门槛 `NOSHOW_GATE`。服务端按顾客以前的爽约（取消原因「未取」）算风险；

| 合成数据（爽约率 6.9% / 7.4%，种子 3 / 4） | 规则 | **逻辑回归** |
|---|---|---|
| Brier 分数 | 0.0742 / 0.0788 | **0.0497 / 0.0534** |
| AUC | 0.727 / 0.742 | **0.831 / 0.856** |
| 风险最高的一成抓到的爽约 | 42.5% / 44.8% | **51.4% / 49.1%** |
| 校准误差（ECE） | 0.092 / 0.097 | **0.007 / 0.009** |

- 风险 ≥ 30% 的订单，冷冻商品晚点拣（到取货前 20 分钟，顾客来了再拣也来得及）；关门前 90 分钟还没来取的订单列出联系清单（打电话或发消息问问），确认不来的由门店管理员取消，记为「未取」（之后的风险会算上）；
- 模型不按姓名之外的个人信息建模；顾客要求删除记录时一并删除（见第 5 节）。

## 4. 时段产能（B6）

作业核心 `capacity.ts`（`CloseSlot` / `ReopenSlot`，停止接单的时段再下单会被拒绝 `SLOT_CLOSED`），模型 `packages/ai/src/capacity.ts`。

- 接下来每个取货时段还能接多少单：拣货（时段开始前一个时段长度里在岗的拣货员 × 可用时间八五折 ÷ 每单拣货用时）和交付（在岗交付员 × 时段长度 × 八五折 ÷ 每单 4 分钟）取小的，减去已经接的单；`GET /ai/capacity` 给订单平台决定还能不能接单；
- 快接满时 AI 建议这个时段停止接新单（已经接的照常做），并告诉后面哪个时段还能接；带班负责人也可以在「模型」页手动停止 / 重新开放；
- **取舍曲线**：同一天按不同的接单上限各仿真一遍（流体排队），看接的单和迟到的关系（`POST /ai/capacity/curve`）。

| 测试日（10 个时段，每时段 3 名拣货员，每单 7 分钟，两个高峰时段各 40 单） | 接的单 | 迟到 |
|---|---|---|
| 上限 = 产能估计 × 0.8 | 154 | 0 |
| 上限 = 产能估计 | 182 | 0 |
| 上限 = 产能估计 × 1.2 | 191 | 0 |
| 不设上限 | 224 | 37.5（16.7%） |

产能估计留了余量（八五折、只算时段前的拣货时间），放宽到 1.2 倍也没有迟到；演示门店人手充足（没发布排班时名单上的人都算在岗）时曲线是平的。

## 5. 替代推荐 2.0（B4）

- **真实标签**：交付时记下顾客对替代品的反应（交付页每个替代行的「顾客满意 / 不太满意」，`RateSubstitution`），不改计费和退货规则；作业核心统计，AI 服务存成训练标签；
- **隐私**：顾客要求删除个人记录时（`POST /ai/customers/forget`），他的替代品标签删掉，以后不用他的到店习惯和替代偏好；
- **商品属性补充**（`packages/ai/src/attributes.ts`）：规则从商品名里抽口味、规格、有机、无麸质，可以插入别的补充器（例如本地语言模型离线补充，AS-01：在线排序不用大模型）。合成目录上：口味精确率 0.74、召回率 1.0；规格 0.12 / 0.34；有机和无麸质 0（合成商品名里没写，规则抽不出来——这正是需要补充器的地方）；
- **个性化**（`evaluatePersonalization`，残差经验贝叶斯：用顾客自己以前的反应调整全店模型）：第一名的期望接受率 0.711 → 0.710（种子 5），0.695 → 0.693（种子 6），上限（知道每位顾客的真实偏好）0.722 / 0.706。**结论：暂不做个性化**，收益在噪声以内；以后有了真实标签再评估。

## 6. 负荷与安全（D5）

作业核心 `packages/ops/src/safety.ts`。

- 冷冻区累计 45 分钟以上：提醒本人出来暖和一下，可领取的冷冻批次排到后面；
- 连续工作 4 小时以上：提醒休息 15 分钟；
- 大件（需两人搬运）：请空闲的同事去帮忙；
- 只做提醒和排序，不记个人效率。
