## 2. 门店设置（新）

- 命令 `SetStoreSettings`（控制台和带班负责人），事件 `StoreSettingsChanged`，状态 `settings`：`requireScan`（要求扫码）、`prepGate`（`ANY` / `ARRIVED`）；
- 「要求扫码」打开后，所有**点选代替扫码**的操作（命令带 `tap: true`）被拒绝 `SCAN_REQUIRED`；拣货必须扫到商品条码（服务端核对，扫错拒绝 `WRONG_ITEM`）；框、格位、货位、库位、回收专区、保温位、大件区、包裹格位都要扫；界面上点选的按钮变灰，写明「扫……标签」；
- 控制台和带班负责人的「更多」里有「门店设置」卡片，所有设备马上生效。

## 3. 按流程：改了什么

### 3.1 拣货（O-06、O-08、O-15、O-17、O-18、O-19，X1）
- 绑定：第一次往框里放东西时扫框顺便绑定（`PickItem.labelId`）；「贴标签：已扫 x / n 个框」可以折叠，开拣不用等全部扫完；
- 扫商品时服务端核对条码（统一成 14 位比较）；
- **跳过这一行**（排到最后再拣，只记在这台手机上）；
- **中途交接**：任何时候都可以「剩下的转给别人（休息、下班）」，不只冷链风险时（`HandOverLines`）；
- 替代品列表写货位；AI 排好的**首选替代一下选定**；
- **放弃批次时解除绑定**，下一个人重新扫框；
- 冷链计时到**框放进暂存为止**（暂存页显示每个冷链框还剩多少时间）；
- 批次里的订单被取消时**马上告诉拣货员**，已拣的商品跟着框走，暂存时放进回收专区；
- 拣货前补货：**领取批次时按领取的时刻重算**走到每个货位的时间；补完后拣货员那边写「已补上」；
- 摄像头**连续扫**：扫完不关，点「完成」再关（同一个码连续读到两次去重）。

### 3.2 暂存（X1、X2）
- 扫到还没拣完、或正在交付准备的框时**马上提示**；
- **自取区、配送区**：自己选格位时也检查（`SLOT_AREA_MISMATCH`）；
- **回收专区**：每个温区一个标签（`RECOVERY-AMB / CHL / FRZ / HOT`，在「打印暂存格位标签」里），移过去时扫一下（门店要求扫码时必须扫，温区不对拒绝）；
- 交付准备退出、改派时放回的框：门店要求扫码时不自动记成已放回，到暂存页扫框、扫格位。

### 3.3 交付（O-01、O-12、O-13、O-14、O-16、O-22）
- **扫框即开始准备**：订单都暂存好、门店允许现在开始时，在看板上扫框 = 打开 + 开始准备 + 记下这一框（每单少扫 1 次）；
- **店员代签到**：顾客没在手机上签到、走到柜台时，「顾客已到（店员签到）」；
- **先核验、再取框**：顾客到了随时可以核验，框取完直接进入交付；门店设成「顾客到了才能开始」时到店前不能开始准备；
- **退出交付准备**：「放回暂存，结束准备」（`AbandonPrep`，事件 `PrepAbandoned`）；
- **开始准备时就提前说**：有 21+ 商品（含替代品）、召回商品、后仓补取中、熟食、大件；会核验年龄的人（名单上的 `AGE_CHECK` 技能）写出名字；
- 移除 21+ 商品时列出是哪几件、在哪个框；
- **召回商品已经拣进框里**：完成交付前要取出并勾选（`removeRecalled`，拒绝 `RECALL_ITEMS_PRESENT`）；
- **熟食、大件接进交付**：交付准备里列出「熟食在保温位 H-02」「大件 2 件在 BULK-1」；熟食做好了没取出拒绝 `MTO_NOT_PULLED`，还在做拒绝 `MTO_NOT_READY`；
- 后仓补取中：完成交付时按缺货算，没找到的补取作废；
- **到店提醒**：顾客签到时提醒在岗、手上没在交付的交付员（几位同时到合成一条，等太久标紧急）；
- 看板太长时：已到、快到的在上面，还没到的收起来。

### 3.4 配送行程（O-11）
- 带班负责人手机上有「司机没来，改派」；
- 改派后可能赶不上送达时段：**直接通知带班负责人和开始准备的人**（提醒 `TRIP_AT_RISK`），不用转告。

### 3.5 补货、核对货架、盘点（O-02、O-03、O-04、O-05、X3）
- **整批取货**：领取一批后先给出按库位排好的取箱清单，扫到哪个商品的箱子就记到哪个任务上，取齐后按货位顺序逐个上架；一个任务、整批都能放回队列；
- 补取时已经拿在手上的那一箱优先（`fromCaseId`）；箱里剩下的放回库位要点「已放回」；
- **数量直接输入**（核对货架、盘点、上架件数、收货箱数）：加减按钮旁边是数字框，点进去全选；
- 核对货架：扫货位（门店要求扫码时必须扫，服务端核对 `locationId`）；
- **核对和盘点默认自动执行**（可售概率、盘点两个模块默认「自动执行」）：只给补货员和后仓派任务，风险低；
- 「后仓找不到」：说了找过哪个库位时**只盘这个库位**，别的库位的箱子照样能补货、补取（`usableCases`）；
- 盘点：开始数之前扫库位标签；可以记下数的时候发现的、记录里没有的商品；**可以放回队列**（`ReleaseCount`）；
- 提醒的「去处理」和「下一步」**直达那一条**：补货批次、盘点、后仓补取直接领取并打开；核对、交付打开那一个；
- 库存、扩展的子页记住上次的；已扫的箱子、「已到货位」切页不丢。

### 3.6 后仓（O-09、O-16，X3、X5）
- 后仓补取：**可以放回队列**（`ReleaseException`）；框放进暂存时**提醒补取的人现在可以送了**；**箱里剩下的我顺手上架**（默认打开，`alsoRestock`），不用别人再跑一趟；
- 收货：**第一次扫箱就算卡车到了**；按实际点到的收（默认送货单上的数，可以改），破损的单独记、进待检区；到货通知里没有的商品也列出来；「收货并打印」只打刚收的这几箱；箱标签上印批号和保质期；**关闭收货单前确认**；保质期写错说明正确写法（`DATE_INVALID`）；
- 上架：**整托上架**（先扫几箱，再扫一个库位）；检验合格放回可售：**选一个库位、扫库位标签**放进去（以前自动选库位）；召回中的箱子不能放回可售。

### 3.7 保质期（O-25）
- 采纳**降价**后给补货员一个「贴折扣签」任务（哪一批、打几折、大约几件）；采纳**捐赠**后是「拿下来捐赠」任务，按实际拿下来的件数记；
- **过期的批次**生成「下架」任务，做完记为已下架，不再反复提醒；
- 退货「可售回架」生成「退货放回货架」任务，放回、确认件数后货架估算才增加。

### 3.8 扩展模块（O-22）
- **熟食**：保温位一个位放一份（`SLOT_FULL`）；门店要求扫码时热食要扫保温位标签；**制作中也能丢弃**；交付准备里列出、完成交付前检查（第 3.3 节）；
- **退货**：退的件数不能比订单里交出去的多（`RETURN_QTY_EXCEEDED`）；**扫错的可以删**（`RemoveReturnLine`）；扫完一件状况回到「未开封」；
- **大件**：**打印了这一件的标签才能放**（`PrintOversizedLabel`，事件 `OversizedLabelPrinted`，拒绝 `LABEL_NOT_PRINTED`）；放好后扫大件区标签；
- **包裹**：到货通知里没有的编码**先问一句**（扫错了 / 登记为多出，`extra: true`），扫错的不再直接变成「多出」；入站后直接扫格位标签放进去；**多出和损坏的包裹**选「退回快递」或「放异常区等认领」（`ResolveParcel`，状态 `RETURNED` / `HELD`）；**员工手机也能按行程交给司机**。

### 3.9 带班负责人（O-07、O-10、O-20、O-23、O-24）
- **AI 建议按紧急程度排**（标了紧急的、要执行的、设备和运营预警在前，同样急的先到期的在前，`recsByUrgency`）；**动作已经做不了的建议在节拍里自动收起**（记为过期），页面上只留「收起」；
- **涉及人、钱、顾客的动作点两下**：「采纳」后显示「确认执行：……（执行后撤不回）」；
- **「只显示」的建议**：「有用」不执行动作（要执行请把模块改成需确认），也不发提醒（紧急的除外）；
- 停止接单：建议页上有精简的「时段产能」卡片，**停止接单要再确认一次**；
- **排班草稿能改**：点格子改时间、岗位，删掉或加一个班；
- **补班邀请**：「其他人选」可以直接点「改发给 X」（`SendShiftOffer`，这条建议算采纳）；默认勾着「**被拒后自动问下一个人**」：拒绝后 AI 的下一条邀请直接发出，不用再采纳（作业核心按 `followUpOf` 判断带班负责人同意过）；
- **召回**：卡片列出要拿出来的框（订单、在哪个格位、哪些商品，`recallTotes`）；开启时已经做了的步骤直接打勾（后仓的箱子转待检；没有框、订单、顾客的那一步）；**五步都做完才能关**（`RECALL_STEPS_OPEN`）；**只召回部分批号**的，货架下架打勾后别的批号可以照常拣（`pickBlockedItems`），交付时只拦货架下架之前拣的（`lineRecalled`，按每行最后一次拣到的时间）；货架上没有批次记录时不知道拿走了几件：存量不动、把握降低；
- 突发状况**开启前再确认一次**；
- **设备告警**：负责这台设备的岗位也能确认（后仓员工确认冷库告警，`responsibleFor`）；带班负责人在告警条上**报修**（暂停这台设备管着的格位）、在告警条里**关报修单**；
- **调配**：手上有任务的人默认「做完这一单再去」（`ChangeRole.whenFree`，事件 `AssociateMoveQueued` / `AssociateMoveCancelled`，状态 `pendingMoves`）：任务做完后节拍调过去，本人做完后的下一个操作之前也会先调过去；在岗人员里写「做完后去……」，可以「取消排队」；AI 的调人建议采纳时这个人手上有任务也是排队（以前算过时）；**熟食也可以调**；调到后仓时提示这个人有没有后仓补取的授权。

### 3.10 控制台
- 批量建订单遇到被拒的单**跳过、接着建**，提示「已创建 N 张，M 张被拒：原因」；
- 自取订单才有「我在路上」「到店」；门店设置卡片；实时事件里每种新事件都有中文名称。

## 7. 讨论后加的三处（D5–D7，2026-10-26）

**D5 补货推车的容量**
- 陈列表（`PlanogramEntry`）多了每箱大约的重量和体积（`caseKg`、`caseL`）：按商品的单件重量、尺寸和每箱件数算，纸箱和空隙多算一成；
- 补货的批次除了每批最多 8 个任务，还按推车的装载上限分：一批的箱子加起来不超过推车的重量和体积（默认约 150 千克、600 升，`DEFAULT_CART`；门店的补货规则里可以改 `cartKg`、`cartL`），装不下的另起一批，一箱就超的单独一批（`batchByArea` 的装载参数、`replBatches(s, st)`）；
- 补货页每批写「约 X 千克 · Y 升（推车上限 …）」（`batchLoad`），列出这一批的全部商品；「下一步」领取的也是推车装得下的这一批。

**D6 货架上没有批次记录时的召回**
- 只召回部分批号、货架上又没有这个商品的批次记录时，货架下架打勾不知道拿走了几件：同时给补货员派一个「召回下架后数一下」的核对任务（新的核对原因 `RECALL`），数完货架估算按数到的算；在这之前把握降低（0.3）；
- 有批次记录的（知道拿走了几件）、整个商品召回的（货架清零就是对的）、已经有核对任务的，不再派。

**D7 排班草稿改过之后的指标**
- 排班模块新增 `scoreSchedule`：给一份班表，按生成草稿同一套算法算覆盖、缺口、多排、工时和规则检查；名单到排班员工的转换（`scheduleAssociates`）由服务端和手机共用，草稿里带上生成时的可排班范围（`rules`）；
- 手机上每改一个班就重新打分：缺口按新的覆盖重新找连续缺人的时段，和 AI 草稿的缺口重叠的沿用原来的原因，其余标「改草稿后空出来的」；改出来的问题写成人话（例如「Sam：周二的班太短」「两个班之间休息不够」）。

测试：`packages/ops/src/inventory.test.ts`（按重量、体积分批，一箱超重单独一批；陈列表有每箱重量和体积）、`fieldops.test.ts`（召回下架后派「数一下」任务、数完按数到的算、整个商品召回不派）、`packages/ai/src/store-ai.test.ts`（不改时和草稿一样、删掉一个班工时变少、改出来的问题能查出来）；走查 20 新增一步：生成下周草稿，把一个班提前 2 小时下班，缺口和工时重算。

## 8. 写操作指南时发现并修好的问题（2026-10-27）

写 [操作指南](../guide/operation-guide.zh-CN.md) 时逐个核对界面文字，发现几处和设计不一致，作者要求「一并解决」：

| 问题 | 以前 | 现在 |
|---|---|---|
| 报修单关不了 | 手机上的「报修单」只在告警条里；告警解除以后（或者 AI 没有告警就开了报修单），只能去控制台关 | 带班负责人手机顶部显示「报修单（N）」，点开就能关（`TwinCard.tsx` 的 `AlertBanner`） |
| 调人被拒的提示 | 「只能在拣货、暂存、交付、补货、后仓之间调动」，漏了熟食 | 加上熟食，和 `MOVABLE_ROLES` 一致 |
| 暂存页的标签 | 交付准备时取出、要放回的框标「放回」，英文和大件的按钮共用 "Release" | 改成「待放回」（"Put back"） |

16 号文档里收货按钮的写法也改成了现在的「收货 N 箱」+「打印刚收的 N 张箱标签」。
