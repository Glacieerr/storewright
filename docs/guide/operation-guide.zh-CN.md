## 1. 开始之前

### 1.1 系统是什么

Storewright 是给超市用的门店数字孪生和作业系统。线上订单在员工手机上走完拣货、暂存、交付，后仓收货、货架补货、排班调人和门店 AI 也在同一套系统里。三维孪生和现场同步，可以回放当天任意时刻、推演未来 3 小时；整个系统也能直接在浏览器里运行，不需要后端。

### 1.2 三种运行方式

都需要 Node.js 20 或更高版本。第一次先在项目目录运行一次 `npm install`。

| 方式 | 命令（依次运行） | 打开 | 适合 |
|---|---|---|---|
| 浏览器内演示 | `npm run build:site`，然后 `npm run demo:site` | http://127.0.0.1:4177/ | 第一次看。门店中枢跑在浏览器里，数据存在本机浏览器 |
| 规划孪生（模拟器） | `npm run dev` | http://localhost:5173 | 只看三维门店和全天仿真；连上后端后是运营孪生 |
| 真实后端 | `npm run build:associate`，然后 `npm run server` | http://localhost:8787 | 几部真手机一起作业。手机和电脑连同一个 Wi-Fi，手机打开 `http://电脑的局域网 IP:8787` |

浏览器内演示：
- http://127.0.0.1:4177/ 会跳到展示页（`/app/showcase.html`）。`/app/` 是员工端，`/sim/` 是模拟器。
- 地址后面加 `?store=hardware` 换成家居建材店，加 `?lang=en` 用英文界面。
- 同一个网站打开的标签页共用一家门店，实时同步。数据只存在这个浏览器里，12 小时没有操作时自动清空作业数据。

真实后端：
- 不用另外安装数据库。
- `STORES=demo,hardware,large npm run server` 同时运行中型超市、家居建材店和 300 人的大型店，登录时在「门店」里填 `demo`、`hardware` 或 `large`。
- 手机摄像头扫码需要 HTTPS 或 localhost。要用手机摄像头时改用 `HTTPS=1 npm run server`，手机打开 `https://电脑的局域网 IP:8787`，第一次按浏览器的提示继续访问（证书是本机生成的）。用蓝牙或 USB 扫码枪、或手动输入时不需要 HTTPS。
- 模拟器怎么连这个后端，见 [6.8 运营孪生](#68-运营孪生)。

### 1.3 第一次用先走一遍展示页

展示页把整套系统放在一个页面里。左栏可以切换「控制台」「数字孪生」「全天仿真」「上下并排」，「在新标签页打开 ↗」单独打开当前画面。右边是两部员工手机，每部手机上方有选择框，可以换成「拣货员 Avery」「暂存员 Riley」「交付员 Morgan」「带班负责人 Taylor」「后仓 Drew」。窄屏上用顶部的「控制台」「手机 1」「手机 2」「数字孪生」切换。

页面上方的「跟着做一遍（约 3 分钟）」有 7 步，按门店的实时状态自动打勾：

1. **下单**：在控制台点「创建」，下一张自取订单（默认立即锁单并生成拣货批次）。
2. **拣货**：手机 1（拣货员）领取批次，点框绑定标签，逐行点「已拣到 N 件」，最后点「完成拣货，去暂存」。
3. **暂存**：把手机 1 换成「暂存员 Riley」，逐框点选，放进建议的格位。
4. **到店**：在控制台点这张订单的「我在路上」和「到店」，交付看板变色；左栏切到「数字孪生」可以看到顾客的车。
5. **交付**：手机 2（交付员）打开这张订单，开始准备、逐框取出，输入控制台显示的验证码，完成交付。
6. **AI**：把一部手机换成「带班负责人 Taylor」，打开「AI」页，处理一条建议。
7. **孪生**：在控制台的「设备与告警」点「暂存冷藏柜故障」。孪生里温度升高变红，告警推到 Taylor 的手机上，点「确认，我来处理」。再拖动孪生底部的时间轴：往左回放，往右看未来 3 小时的推演。

「换成家居建材店」切换门店；「重置演示门店」清空订单和作业记录，AI 模型保留。

### 1.4 怎么读这份指南

- 「扫」指用扫码枪、手机摄像头或手动输入。每个扫码框右边有 ⌨（「手动输入」）和 ◎（「摄像头扫码」）。摄像头读到一个码后不关，可以接着扫，点「完成」再关。
- 门店没有打开「要求扫码」时（演示、培训），扫码的步骤都可以点列表里的那一行代替。打开后点选会被拒绝，见 [2.4 门店设置](#24-门店设置)。
- 操作被拒绝时，手机上会弹出原因，例如「这个批次已被 Avery 领取」。断网时的操作先存在手机里，顶栏显示「N 待提交」，恢复连接后按顺序提交。
- 文中的 N、HH:MM 代表界面上的数字和时间。

## 2. 登录和角色

### 2.1 选一个身份

演示版本故意不设密码，身份只用来记录是谁做的操作。

1. 打开员工端：真实后端是 http://localhost:8787 ，浏览器内演示是 `/app/`。
2. 在「门店」里填门店编号：`demo` 是中型超市，`hardware` 是家居建材店。
3. 在「选择你的身份」里点一个名字。名单超过 24 人时上面有搜索框和按岗位筛选；输入员工编号后按回车直接登录。
4. 要用演示控制台，点最下面的「演示控制台（订单平台 / 顾客 / 司机）」。

- 登录页名单上的「后仓收货」就是本指南说的后仓。
- 换人：「更多 → 我 → 退出登录」，或顶栏的「退出」。展示页里用手机上方的选择框切换。展示页只列 5 个人；要用别的身份（例如补货、熟食），在新标签页打开 `/app/` 登录，和展示页共用同一家演示门店。
- 语言：登录页右上角的「EN」/「中文」，或「更多 → 语言」。
- 演示门店（`demo`）常用的身份：Avery（拣货）、Riley（暂存）、Morgan 和 Quinn（交付，Quinn 会年龄核验）、Robin（补货）、Drew（后仓，有后仓补取的永久授权）、Jamie（熟食；家居建材店没有熟食，这个人在后仓）、Taylor（带班负责人，有后仓补取的永久授权）。

### 2.2 手机上的布局

- **底部标签栏**：「拣货」「暂存」「交付」「库存」「扩展」（门店开了扩展模块才有）「AI」（只有带班负责人）「更多」。角标：「拣货」上的 ● 表示你手上有批次；「暂存」是待暂存的框数；「交付」是已到店、还没人开始准备的顾客数；「库存」是还没人领的补货、补取和核对任务数；「AI」是待处理的建议数。
- **顶栏**：名字和门店、连接状态（「在线」「连接中」「离线」）、👥 在岗人员（旁边是在岗人数）、🔔 提醒、「退出」。
- **页面顶部的横幅**：设备告警、突发状况清单、「下一步」（手上没活时）。
- **「更多」**：「我」（「退出登录」）、「我的班次」、「现场操作提示」、「门店设置」（带班负责人）、「问助手」（其他人）、「语言」、「连接」、「标签」里的「打印暂存格位标签」。「现场操作提示」入职两周内默认打开：第一次遇到某种情况（第一次拣冷链批次、第一次输错取货码、暂存快满等）时弹出操作要点。

### 2.3 每个岗位看到什么

| 岗位 | 登录后默认在 | 主要的事 | 本指南 |
|---|---|---|---|
| 拣货 | 拣货 | 领取批次、逐行拣货 | [3.1](#31-拣货) |
| 暂存 | 暂存 | 把框放进格位、移到回收专区 | [3.2](#32-暂存) |
| 交付 | 交付 | 顾客到店交付、配送交接 | [3.3](#33-交付)、[3.4](#34-配送行程和司机) |
| 补货 | 库存 → 补货 | 补货批次、核对货架、批次任务 | [3.5](#35-补货)、[3.6](#36-核对货架和批次任务) |
| 后仓 | 库存 → 收货 | 收货、上架、盘点、后仓补取 | [3.7](#37-后仓补取) 到 [3.10](#310-盘点) |
| 熟食 | 扩展 → 熟食现做 | 现做单 | [3.11](#311-熟食现做) |
| 带班负责人 | 交付，另有「AI」页 | AI 建议、调人、排班、现场、门店设置 | [第 4 节](#4-带班负责人) |

- 默认页按**此刻的岗位**：临时调动 > 当天排班的岗位 > 名单上的岗位。被调到别的岗位时手机自动切页并提示；手上有任务时先不切页。
- 标签页谁都能打开，大部分任务谁都能做，例如拣货员也可以帮忙暂存。例外：「AI」页只有带班负责人有；后仓补取只有有永久授权的人能领；调人和门店设置只有带班负责人和控制台能改。
- 「库存」和「扩展」的子页记住上次打开的那个。第一次打开扩展页时按岗位默认：熟食看熟食现做，后仓看包裹，交付看退货，暂存看大件。

### 2.4 门店设置

带班负责人在「更多 → 门店设置」里改，控制台在控制台页的「门店设置」卡片里改。改了所有设备马上生效。

- **「要求扫码」**（默认关）：打开后拣货必须扫到商品条码，框、格位、货位、库位、回收专区、保温位、大件区、包裹格位都要扫。点选的按钮变灰或不显示，点选的操作被拒绝：「门店要求扫码：请扫描标签或条码，不能点选代替」。服务端会核对扫到的条码和位置。演示和培训时关掉。
- **「交付准备什么时候能开始」**：
  - 「顾客到店前也可以开始（常温先取，冷藏冷冻最后取）；顾客到了可以先核验取货码」（默认）；
  - 「顾客到了才能开始（冷链框不提前离开暂存区）」。

为什么这样设计见 [决策记录 0026](../decisions/0026-flow-fixes.md)。

## 3. 员工手机上的一线岗位

### 3.1 拣货

系统在锁单（取货时段开始前 120 分钟）后定时生成拣货批次，演示里每分钟一轮。每个框的标签已经对应好。

1. 在「拣货」页的「可以领取的批次（N）」里选一张卡片。卡片写温区、「优先」、「截止 HH:MM」、框数、货位数、件数、预计分钟、路程，以及 AI 的缺货提示和冷链时限。点「领取这个批次」。一个人一次只能领一个批次，领了之后别人的列表里就没有了。
2. 贴标签。在「贴标签：已扫 x / n 个框」下面的「扫描框上的标签」里逐个扫框；也可以直接开拣，第一次往某个框里放东西时再扫那个框（门店没有要求扫码时自动绑定）。「打印本批标签」在新标签页打开这批的标签。
3. 按顺序逐行拣货。卡片写通道、货架段和层，商品名，「×N」，「放进框 i/n · 订单 XXXX」，以及「21+」「不允许替代」等标记。在「扫描商品条码」里扫商品，扫错会提示「不是这件商品：请找 …」。
   - 只差一件的直接记下；差几件时弹出「还需要 N 件，这次放进框里几件？」，输入数字后点「确认」。
   - 不扫码时点「已拣到 N 件」，记下这一行剩下的全部数量。门店要求扫码时没有这个按钮。
4. 所有行处理完后出现「这一车拣完了」。点「完成拣货，去暂存」，手机跳到暂存页，框出现在大家的「待暂存」里。

拣货中常用的操作：

| 情况 | 怎么做 |
|---|---|
| 想先拣别的 | 「跳过这一行，最后再拣」（只记在这台手机上） |
| 货架上找不到 | 点「找不到」，选货架上的情况（「空架」「不在原位」「损坏」「价签不对」「其他」），再选一种处理：「换成 AI 首选：…」；「查看替代商品」后点一个（列表写货位和预计顾客接受率）；「后仓有 N 箱：转后仓补取」；或「标记缺货」 |
| 只拣到一部分 | 在数量弹窗里填实际件数，剩下的再按「找不到」处理 |
| 框装满了 | 「框 i/n 装满了？加一个框」：这个框里没拣的行移到新框，再点「打印本批标签」给新框打标签 |
| AI 请你顺路数一下 | 「顺手数一下」卡片：输入货架上有几件，点「提交 N 件」，或点「跳过」 |
| 休息、下班 | 「剩下的转给别人（休息、下班）」→「确认转出」：没拣的行进一个新的优先批次，你把拣好的框送去暂存 |
| 冷链快超时或已超时 | 横幅里点「剩下的转给别人，先送回暂存」；一件没拣的框会提示取下来不用 |
| 还没拣第一件，不想做了 | 「放弃这个批次」：框解除绑定，下一个人重新扫 |
| 召回商品 | 卡片上有红色横幅「召回商品：不要拣，按「找不到」处理（替代或缺货）」，「已拣到 N 件」不能点 |
| 批次里有订单被取消 | 马上提示。已经拣的商品跟着框走，送到暂存时放进回收专区 |

- **冷链计时**：第一件冷藏或冷冻商品放进框时开始，到框放进暂存区为止。拣货页顶部显示还剩多少时间，暂存页的列表里也写着。
- **不允许替代**的商品只能「标记缺货」或转后仓补取。
- **语音命令**：点「语音命令」，在输入框里打字，或用手机键盘自带的听写说「下一个」「找不到」「数量 3」「记一下：……」，点「执行」。别的问题交给门店助手回答。门店的本地语音识别还没有接上。

### 3.2 暂存

1. 打开「暂存」页。最上面是各温区的占用率。「待暂存（N）」列出拣完的框，冷链框写还剩多少时间；交付准备中取出、要放回暂存区的框标「待放回」。
2. 在「扫描框标签」里扫框，门店没有要求扫码时也可以点列表里的一行。还没拣完或正在交付准备的框会马上提示。
3. 卡片写顾客、短号、「框 i/n · 自取」或「配送」、现在在哪个格位。下面是最多 4 个建议格位：同一订单已经用的格位优先，其次最空的；顾客半小时内到的建议放近一点，一个半小时以后才到的放远一点。
4. 扫格位标签，或点一个建议格位，提示「已放进 {格位}」。
5. 整单的框都放好后，交付看板上这单变成「未开始」，配送订单可以组行程了。

- 自取订单只能放自取区的格位，配送订单只能放配送区的格位。温区不对、格位满了、格位所在的冷柜在报修，都会被拒绝并说明原因。
- 换格位：扫这个框，再扫新的格位。选错了框点「换一个框」。

**回收专区**：订单取消后，框要放进对应温区的回收专区。
- 扫到取消订单的框时提示「订单已取消：把这个框放进{温区}回收专区」。「需要移到回收专区（N）」也会列出要移的框（格位里的，和交付准备时已经取出的）。
- 门店没有要求扫码时，扫到这个框或点一下列表里的那一行就记下了。要求扫码时，把框放过去后再扫回收专区的标签（每个温区一个，在「更多 → 打印暂存格位标签」里打印）。

### 3.3 交付

**交付看板**：「交付」页上面是「扫描任意一个框，或输入订单短号」，下面是「交付看板（N）」。每一行的颜色：

| 颜色 | 状态 | 意思 |
|---|---|---|
| 灰 | 「未到达」 | 还没到。写取货时段；顾客报了预计到达时写几分钟后到 |
| 黄 | 「即将到达」 | 5 分钟内到，写「N 分钟后到」；AI 修正过的另写「AI 修正 · 顾客报 N 分钟」 |
| 蓝 | 「已到达」 | 顾客签到了，写等待时间和车位 |
| 红 | 「等待过久」 | 等了 8 分钟以上 |

- 已到达的排在最前面，先到先服务。订单多于 10 张时，还没到的收在「还没到的订单（N）」里。
- 每行右边写进度：「拣货 / 暂存中 x/n」「未开始」「准备中（谁）」「待装车」「交付中」。
- 顾客签到时，在岗、手上没在交付的交付员会收到到店提醒。

**一张自取订单的交付**：

1. **打开订单并开始准备**：扫这单的任意一个框。订单都暂存好、门店允许现在开始时，这一扫就打开订单、开始准备、记下这一框。也可以输入 4 位短号，或点看板上的一行，再点「开始准备」。订单锁定给你；别人打开时看到「{谁} 正在准备这个订单」，可以点「加入协助」。
2. **看提前提示**：页面上方写出 21+ 商品和会核验年龄的人、召回商品、「后仓补取中」的商品、熟食在哪个保温位、大件在哪个区，以及冷链告警。
3. **顾客直接走到柜台**：顾客没在手机上签到时，点「顾客已到（店员签到）」。等待时间从这时算起。
4. **核验取货码**：在「核验验证码」里输入顾客的码（4 到 8 位），点「核验」。顾客在柜台时可以先核验，再去取框。输错时提示「验证码不正确（已错 N 次），请顾客再核对一遍」，不限次数、不会锁住；错 3 次后多一个「已人工核验」。
5. **逐框取出**：「从暂存区取出（k / n）」按常温、冷藏、冷冻、热食的顺序列出每个框和格位。在「逐框扫描」里扫，门店没有要求扫码时也可以点一行。标签丢了点「标签丢失？重打」。
6. **熟食和大件**：「熟食现做」一栏里点「取出」，顾客不要了点「顾客不要了」。大件交给顾客后勾「大件已经取出、交给顾客」。
7. **交给顾客**：框都取出、码也核验过以后出现「交付」一栏。
   - 有 21+ 商品：看到「含年龄限制商品（21+）：请核验证件」，核验后点「已核验证件」；核验不了就勾「无法核验：移除年龄限制商品」，页面列出要拿出来的是哪几件、在哪个框。替代品是 21+ 的也要核验。
   - 有召回商品：按列出的框把商品拿出来，勾「召回商品已经从框里取出」。
   - 看缺货和替代，告诉顾客。替代品可以记「顾客满意」或「不太满意」。
   - 点「完成交付」，提示「交付完成」，回到看板。

- **开始不了**：订单没全部暂存时提示「订单还没有全部暂存，请告诉顾客预计等待时间和原因。」；门店设成顾客到了才能开始、顾客又没到时提示「门店设置：顾客到了才能开始准备。」；配送订单要按行程一起准备（见 [3.4](#34-配送行程和司机)）。
- **退出准备**：扫错了、顾客一直不来时，点「放回暂存，结束准备」→「确认结束」。取出的框回原格位。门店要求扫码时不会自动记成已放回，要到暂存页扫框、扫格位（列表里标「待放回」）。
- **订单被取消**：只有控制台能取消。准备中被取消时，页面列出已经取出的框，放进对应温区的回收专区后逐个点一下。
- **后仓补取中**：可以等补取的人送来，也可以先交。完成交付时没送到的按缺货算。

### 3.4 配送行程和司机

**行程怎么来**：系统定时把已暂存的配送订单组成行程，一趟最多 4 单，按车的容量装（默认 12 框、300 千克）。不满 4 单时会再等一等，比如离必须出发还早，或者同一时段还有订单在拣货。看板上写「行程 TRxxx（n 单）」。

**司机**：演示里由控制台代替，依次点「司机接单」（生成司机的验证码）、「预计 15 分钟后到店」、「司机到店」，见 [5.2](#52-代替顾客和司机)。

**交接**（交付员）：
1. 整趟的订单都暂存好以后才能开始。在看板上扫行程里的任意一个框，或点行程那一行再点「开始准备」。
2. 司机没在 App 上报到店时，点「司机已到（店员签到）」。
3. 输入司机的验证码，点「核验」。一个码交整趟。司机没有验证码时，核对证件和订单信息后点「已人工核验」。
4. 逐框取出。
5. 每单选车内位置：「副驾」「后排左」「后排右」「尾箱」。
6. 点「完成交付」，行程里的每一单和行程本身都完成。

**司机取消和改派**：
- 「司机取消接单」（控制台）：预计到店前 10 分钟以外可以取消；到店后等满 10 分钟也可以；其余时间会被拒绝。
- 「司机没来，改派」：控制台和带班负责人手机的行程页上都有，预计到店后 10 分钟、或接单 60 分钟后才出现。
- 取消或改派以后：行程回到待接单，交付准备结束；已经取出的框放回原格位或同温区的空格位（门店要求扫码时，到暂存页扫框、扫格位放回）；顾客收到延后通知；时段快结束时，带班负责人和开始准备的人会收到「行程 … 改派后可能赶不上送达时段：请安排人跟进」。

### 3.5 补货

**任务从哪来**：货架估算低于阈值或可能断货、拣货员报告缺货或选了替代、AI 安排的拣货前补货、手动请求。同一商品已经有任务、或后仓没有能用的箱子时不生成。同一通道的任务合成一批，每批最多 8 个，而且一辆推车装得下（默认约 150 千克、600 升，门店可以改）。补货谁都可以做，不限岗位。

1. 打开「库存 → 补货」。「补货批次（N）」每批一张卡片，写「N 通道」、「约 X 千克 · Y 升（推车上限 …）」和每个商品的原因，例如「货架空了」「库存偏低」「拣货前补上」「可能断货」。拣货前补货写「拣货员约 HH:MM 走到，之前补上」。点「领取这一批」。
2. 去后仓取箱。「取箱清单：已取 x / n 箱」按库位排好。在「扫描箱子或货位标签」里扫箱子，扫到哪个商品的箱子就记到哪个商品上。门店没有要求扫码时，点一行就算取到建议的那一箱。
3. 取齐后去货架。到货位扫货位标签（门店没有要求扫码时可以点「没有货位标签？手动确认已到货位（演示）」）。卡片写「上架件数（货架约 x / y 件，还能放 z 件；箱里 n 件）」，件数可以直接输入，点「完成上架」。
4. 箱里还剩东西时，页面上方提示「把箱子 … 放回库位 …（还剩 N 件）」，放好后点「已放回」。

- 某个库位没有箱子：点这一行的「{库位} 找不到」，系统只盘这个库位。
- 不想做某一个：「放回队列」；整批不做：「整批放回队列」。
- 已经扫过的箱子和已到货位的确认记在这台手机上，切到别的页面再回来还在。

### 3.6 核对货架和批次任务

**核对货架**：AI 觉得某件商品系统里有货、货架上可能没有时，直接给补货员派任务（可售概率模块默认「自动执行」）。拣货员报告找不到、AI 判断多半放错了地方时，任务会请你在附近找一找。

1. 「库存 → 补货」最上面的「核对货架（N）」里点「去核对」。
2. 到货位扫货位标签。门店没有要求扫码时可以手动确认。
3. 「AI：可能放错了地方」的任务会问「在哪里找到的？」：「就在原货位」「在附近找到，已放回」「附近也没有」。
4. 输入货架上实际有几件（包括后面和旁边被挡住的），点「提交数量」。数到 0 时系统会安排补货。

- 拣货员的「顺手数一下」也会顺带关掉这件商品的核对任务。
- 手上有补货批次时，核对任务列在批次下面。

**批次任务**也在这个列表里。点「去做」，扫货位，输入实际做了几件，点「做好了，提交 N 件」。

| 任务 | 从哪来 |
|---|---|
| 「贴折扣签」 | 带班负责人采纳了临期降价建议（写哪一批、打几折、大约几件） |
| 「拿下来捐赠」 | 带班负责人采纳了捐赠建议 |
| 「下架过期」 | 有批次已经过期；做完记为已下架，不再反复提醒 |
| 「退货放回」 | 退货选了「可售回架」；放回后货架存量才增加 |
| 「召回下架后数一下」 | 只召回部分批号、货架上又没有批次记录时，数一下货架上还剩几件（这一种用「去核对」和「提交数量」） |

### 3.7 后仓补取

拣货员在「找不到」里点「后仓有 N 箱：转后仓补取」时生成。只有有永久授权的人能做（演示门店里是带班负责人和后仓员工，例如 Taylor、Drew），没有授权的人打开会看到「需要永久授权」。在岗的授权人员（带班负责人除外）会收到「有后仓补取任务」。

1. 「库存 → 补取」的「待补取（N）」里点「领取」。
2. 「后仓里有这个商品的箱子」列出库位和箱子。在「扫描箱子标签（= 确认找到）」里扫箱子，门店没有要求扫码时也可以点一箱。
3. 「取出 N 件后，这个库位里这个商品：」点「还有」或「已空」。箱子里比要的多时，默认勾着「箱里剩下的 N 件我顺手上架（补货任务交给我）」，剩下的不用别人再跑一趟。
4. 送到暂存区：按「送到暂存格位 X，放进框 i/n」，到格位扫格位标签（或「没有格位标签？手动确认（演示）」）。订单这一行从缺货变成已拣到。

- 框还没放进暂存区时提示稍后再送；框放进暂存时你会收到「订单的框已经放进暂存 …：可以把补取的商品送过去了」。
- 箱子里不够：页面写「箱子里只有 N 件：送这些，其余按缺货。」
- 后仓也没有：点「{库位} 也找不到」（或「后仓也找不到」），系统只盘你找过的那个库位，别的库位的箱子照样能用。
- 订单已经交付或取消：页面提示把取出的件数放回货架，放好后点「已放回货架」。
- 不做了：点「放回队列」。

### 3.8 收货

1. 供应商的到货通知（ASN）到了以后（演示里由控制台发），「库存 → 收货」的「收货单（N）」里出现一行：「在途 · N 箱 · 预计 HH:MM」；晚到时写「晚 N 分钟」，卸货门要排队时写「卸货门：HH:MM 开始卸，要等 N 分钟」。点开这一行。
2. 卡车到了直接扫箱。第一次扫箱就算卡车到了，「卡车已到（扫第一箱时也会自动记下）」可以不点。
3. 在「扫描箱上原有条码，或送货单上的二维码」里扫箱上的条码。卡片有「收几箱」（可以直接输入）、「有破损（进入待检区）」、「批号（可选）」和保质期；箱上的条码带批号和保质期时，扫码后自动填好。点「收货 N 箱」，再点「打印刚收的 N 张箱标签」。箱标签上印批号和保质期。
4. 送货单上有二维码时可以扫它（演示里点「演示：读取这车的送货单」）。出现「送货单比对」表：「商品」「应到」「送货单」「批号 / 保质期」「实收」「破损」，到货通知里没有的商品也列出来。「实收」默认是送货单上的数，按实际点到的改，破损的单独填，点「按送货单收货」。
5. 收完点「关闭收货单」，看一眼短少、多出、破损的小结，点「确认关闭」。关了就不能再收这张单，差异会记下来。

- 「打印本单箱标签」打印这张收货单的全部箱标签。
- 送货单上的商品已经收过一部分时，不能再按送货单收，要逐箱扫描补收。
- 保质期写错时提示正确写法（年-月-日）。

### 3.9 上架和待检

1. 打开「库存 → 上架」，在「扫描箱标签」里扫一箱，或点「待上架 / 待检（N）」里的一行。
2. 卡片下面是「建议库位」（最多 3 个）。扫库位标签，门店没有要求扫码时也可以点建议库位。
3. 整托上架：勾「整托上架：先扫这一托的几箱，再扫一个库位」，先扫这一托的几箱，最后扫一个库位，一起放进去。放不下时停下来，剩下的换一个库位。

待检的箱子（收货时标了破损的）有三个按钮：
- 「检验合格：可售」：再选一个库位，扫库位标签放进去（「放回可售：选一个库位，扫库位标签放进去」）。召回中的商品不能放回可售。
- 「退供应商」。
- 「报废」。

温区不对、化学品和食品放在一起、库存状态不符、库位已满都会被拒绝。

### 3.10 盘点

盘点任务来自定时（A 类每周、B 类每月、C 类每季度）、补取或补货的「找不到」（只盘找过的那个库位）、AI 按风险建议（默认自动执行）。

1. 「库存 → 盘点」的「盘点任务（N）」里点「领取」。
2. 到库位扫库位标签（「到库位 X，扫描库位标签开始」）。门店没有要求扫码时可以点「没有库位标签？手动确认已到库位（演示）」。
3. 逐个商品输入有几箱。这是盲盘，不显示系统数量。数的时候发现记录里没有的商品，在「扫描记录里没有的商品（可选）」里扫一下加一行。
4. 点「提交盘点」。少了的箱子记为丢失，多出来的建新箱。

- 不做了：点「放回队列」。
- 「库存 → 区域」显示各区域的占用和预警线，超过预警的标红。

### 3.11 熟食现做

门店开了熟食模块才有。现做单由订单平台建，演示里控制台下单时勾「每单加一份熟食现做」。建议开工时间 = 取货时段开始 − 制作时长 − 10 分钟；AI 按菜品和厨房忙闲调整过的标「AI 调整」。

1. 「扩展 → 熟食现做」的「排队中（N）」里，卡片写「建议 HH:MM 开始」（晚了写「应在 HH:MM 开始，已晚」）。点「开始制作」。
2. 做好后在「制作中（N）」里选一个空的保温位，点「完成，放入 X」。门店要求扫码时点「扫保温位放入」，扫保温位的标签。一个保温位放一份。
3. 「保温中（N）」写「N 分钟后丢弃」，保温超时系统自动丢弃。交付员在交付准备里取出（这里也有「取出（交付准备）」）。

做坏了或顾客不要了：点「丢弃」，排队中、制作中、保温中都可以。

### 3.12 退货

1. 「扩展 → 退货」的「新退货」里选「顾客退货」或「配送退回」，在「原订单」里选一张订单，或选「没有订单（无小票退货）」，点「开始退货」。
2. 每一件先选状态「未开封」「已开封」「损坏」和数量，再在「扫描退回的商品」里扫。扫完状态回到「未开封」。演示里可以展开「原订单商品（演示：点选代替扫描）」点选。
3. 每件选去向：「可售回架」「报废」「危险品回收」「退供应商」。规则不允许的按钮不能点，并写出原因。AI 建议的去向会标出来，附能再售的概率和理由。
4. 扫错了点「扫错了，删掉这一行」。
5. 每件都有去向后点「完成退货」。退款由外部系统处理。

退货的硬性规则：
- 冷藏、冷冻、热食退回后一律不能回架。
- 食品、日用品和个护只有未开封才能回架；损坏的不能回架。
- 化学品不能按普通垃圾报废，开封或损坏的化学品只能走危险品回收。
- 退的件数不能比订单里交出去的多。
- 「可售回架」不会马上加货架存量：系统给补货员一个「退货放回」任务，放回以后才加。

### 3.13 大件

锁单时，单件过重、放不进框的商品按件生成大件任务。需要两人搬的标「需两人搬运」。打印了这一件的标签才能放。

1. 「扩展 → 大件」里每单一张卡片，写「装载建议：分 N 趟」。点「领取第 1 趟（N 件）」。
2. 在「我领取的大件（N）」里扫商品条码（门店没有要求扫码时可以点「点选代替扫描」）。
3. 点「打印标签 i/n」，贴好。
4. 点「放到 X」；或者放好后扫大件区的标签。门店要求扫码时只能扫。

- 不做了：点「放回」。
- 有人在搬需要两人搬的大件时，系统会提醒一位空闲的同事去帮忙。
- 交付准备里会列出这单的大件在哪个区。

### 3.14 包裹中转

1. 承运商的到货通知先到（演示里控制台点「包裹到货通知（8 件 / 2 个行程）」）。
2. 「扩展 → 包裹」：在「扫描包裹编码入站」里扫包裹。
3. 到货通知里没有的编码，先提示看清编码再扫。确实是多出来的点「登记为多出（放待核实区）」，扫错了点「扫错了」。
4. 入站后扫格位标签放进去，或点建议格位（「放到 X」）。包裹坏了点「登记损坏」。
5. 「多出和损坏（N）」里每件选「退回快递」或「放异常区等认领」。
6. 司机来取时，在「按行程（N）」的行程卡片上点「交给司机（N 件）」。行程里还有没放进格位的包裹时不能交。

超过预计到货时间 30 分钟还没入站的包裹，系统标为短少。

### 3.15 下一步

手上没活、最该做的事又不在当前页面时，页面顶部出现「下一步」卡片。带班负责人不显示。
- 卡片写是什么事（「拣货批次」「暂存」「交付」「补货」「后仓补取」「核对货架」「盘点」）、截止时间，以及为什么推荐它，例如「顾客在等」「快到截止」「你的岗位」「就在附近」「快断货了」。
- 点「领取并开始」（拣货批次、补货批次、盘点、后仓补取直接领取并打开）或「去做」（交付、核对货架打开那一个）。
- 「换一个」看下一条，「收起」先不显示。卡片只是推荐，做别的事也可以。

### 3.16 提醒

顶栏的 🔔 显示未读数，新提醒弹出一次，紧急的标红。点开是提醒列表：
- 「去处理」：标为已读，并直接打开那一条：建议、任务、订单或行程、告警条、「我的班次」。
- 「知道了」：只标为已读。

常见的提醒：「顾客到店：订单 …」、「有后仓补取任务」、「核对货架：N 通道」、「拣货前补货：N 通道，拣货员快到了」、「设备告警：…」、「冷链超时：请立即把冷藏 / 冷冻框送回暂存区」、「补班邀请：…」、「AI 建议：…」（带班负责人）。

发送规则：紧急的马上发；每人每小时最多 3 条非紧急提醒（到店提醒不算）；正在交付时和夜里先不打扰；同一通道、同一台设备、同一个模块的合成一条；事情处理完自动关掉。

### 3.17 在岗人员

点顶栏的 👥 打开「在岗人员」，每台设备都能看。按 Esc、点面板外面或「关闭」都能关。
- 按此刻的岗位分组，每组写人数和这个岗位排着的活：「待领批次 N」「待暂存 N 框」「到店等候 N」「补货任务 N」「后仓补取 N」。有活没人的岗位标红。
- 每个人写在做什么：「拣货中 · …」「交付中 · …」「后仓补取中」「补货中」「盘点中」，没有任务时是「空闲」。临时调动的写「临时 · HH:MM 回…」，排着队的写「做完后去…」，固定名单里的写「固定」。自己那一行标「你」。
- 不在岗的人收在「不在岗（N）」里，点开能看到几点上班、已下班、请假。
- 普通员工只能看，面板上写「调配由带班负责人操作。」。带班负责人怎么调人见 [4.3](#43-调配在岗员工)。
- 被调走时，你的手机提示「你已被调到…，HH:MM 回原岗位」；排着队的调动提示「带班负责人安排你做完手上的就去…」。

### 3.18 设备告警

手机顶部的告警条写「设备告警 · {设备} · {种类}」，种类有「温度过高」「温度过低」「卸货门长时间打开」「传感器离线」。谁能看到：
- 带班负责人看到全部；
- 后仓、补货看到冷藏库、冷冻库和卸货门；
- 熟食看到熟食保温柜；
- 暂存、交付只在暂存冷柜里有框时看到。

点开告警条，看读数、从几点开始、影响（哪些订单和框、后仓几箱、同温区哪些格位还空着）和处理建议。带班负责人和负责这台设备的岗位可以点「确认，我来处理」。严重告警 5 分钟没人确认，控制台会收到提醒。读数恢复以后告警自动解除。

交付员打开受影响的订单时会看到冷链告警提示：交付前检查商品温度，必要时联系带班负责人。

### 3.19 突发状况清单

带班负责人开启突发状况（停电、火警、系统故障、暴雨）后，每台手机顶部出现红色横幅「突发状况：… · HH:MM 开始，已经 N 分钟」和「清单（x / n）」。
- 每个人看到自己岗位和所有人要做的步骤，做完就勾上。打勾后不能取消。
- 员工的清单默认展开；带班负责人的默认收起，点标题展开（完整清单在「AI → 现场」里）。

## 4. 带班负责人

带班负责人的手机多一个「AI」页，里面有「建议」「排班」「现场」「问答」「模式与统计」「模型」。控制台在顶部切到「AI」，内容相同。

### 4.1 AI 建议

「AI → 建议」最上面是简报（用「早上」「中午」「傍晚」切换「开店简报」「午间简报」「傍晚简报」）、「打烊复盘」、「周报」和「订单量展望」，下面是待处理的建议。建议**按紧急程度排**：标了紧急的、要执行的、设备和运营预警在前，同样急的先到期的在前。每张卡片写预测和区间、「置信度」、「主要理由」、其他办法或其他模型的预测，以及模型和运行模式。

处理一条建议：

1. 从最上面一条看起，看理由和预计效果。
2. 同意就点「采纳」。
3. 动作涉及人、钱或顾客时（调人、补班和提前下班的邀请、通知顾客晚到、降价、捐赠、停止接单），会再出现「确认执行：……」和「涉及人、钱或顾客的动作，执行后撤不回」。看清要做什么，点「确认执行」；不做就点「取消」。
4. 不同意就点「否决」，必须选原因（「数据不对」「我知道系统不知道的情况」「人手不够」「顾客要求」「不同意」「其他」），可以写「补充说明（可选）」，点「提交」。
5. 不想处理就点「忽略」。

- 「只显示」的建议按钮是「有用」「不准」「忽略」。「有用」只记下反馈，不执行动作；要执行，到「模式与统计」把这个模块改成「需确认」。只显示的建议也不发提醒（紧急的除外）。
- 情况已经变了、动作做不了的建议（人已经调过去了、订单已经交付了）会被系统自动收起。还没收起时卡片上写「已过时」「情况已经变了，这条建议做不了」，只有「收起」。
- 页面最下面是「最近处理」。
- 补班邀请类的建议另有选项，见 [4.4](#44-排班和补班)。

### 4.2 时段产能和停止接单

「AI → 建议」下面有精简的「时段产能」：接下来几个取货时段已接多少单、能做多少（拣货 / 交付）、还能接多少。快接满时：
1. 在那个时段那一行点「停止接单」。
2. 点「确认停止 HH:MM 接新单」。已经接的单照常做。
3. 要恢复时点「重新开放」。

「AI → 模型」里有完整的时段产能和「仿真：接单上限和迟到的取舍」。

### 4.3 调配在岗员工

1. 点顶栏的 👥 打开「在岗人员」。
2. 在要调的人那一行点「调配」。
3. 选「调多久」：「30 分钟」「1 小时」（默认）「2 小时」「不限时」。
4. 这个人手上有任务时，选「做完这一单再去」（默认，先排队）或「马上调（手上的仍由本人做完）」。
5. 点「调到…」，例如「调到交付」。可以调去拣货、暂存、交付、补货、后仓、熟食；会做的岗位标 ✓。临时调动的人还有「回到…」（原岗位）。
6. 提示「已把 … 调到 …，HH:MM 自动回 …」。到时间系统自动调回原岗位。

- 排着队的调动在这个人做完手上的任务后生效，那一行写「做完后去…」，可以点「取消排队」。
- 「固定」把这个人放进固定名单，AI 不会建议调动这个人；「取消固定」移出。
- 没有后仓补取授权的人调到后仓时，面板上会写明这个人只做收货、上架和盘点。
- 带班负责人自己不能被调动。AI 的调人建议采纳时，这个人手上有任务也是先排队。
- 背景和规则见 [决策记录 0025](../decisions/0025-team-view-dispatch.md)。

### 4.4 排班和补班

**排班草稿**（「AI → 排班」）：
1. 选「本周（… 起）」或「下周（… 起）」。
2. 点「AI 生成这一周的排班草稿」。看总工时、「缺口」「多排」「违反规则」「周末班相差」、每天的覆盖图和「排不上的缺口」。
3. 点表格里的格子改这个人这一天的班：改「上班」「下班」「岗位」后点「保存」，或点「删掉这个班」；没有班的格子可以「加这个班」。每改一处，缺口、多排、工时和规则检查都按改后的班表重新算。改出来的问题写成人话，例如「Sam：周二的班太短」；改出来的缺口标「改草稿后空出来的」。
4. 点「发布这份排班」。已经发布过时，按钮是「用这份草稿替换已发布的排班」。

还没发布排班时，系统按名单判断谁在岗。

**缺勤和补班**：
1. 在「报告缺勤」里选员工和「今天」或「明天」，点「报告缺勤」。
2. AI 在「建议」里给出谁能补这个班。采纳（两步确认）后发出补班邀请。卡片上默认勾着「被拒后自动问下一个人（不用每次再采纳）」：被拒以后，下一条邀请直接发出。
3. 想换人时点「改发给 …」，直接发给其他人选。
4. 被邀请的人在「更多 → 我的班次」里点「接受」或「不方便」。

「我的班次」也显示自己这一周的班，以及「可以提前下班：…（自愿）」这类邀请。

### 4.5 突发状况

1. 「AI → 现场」的「突发状况」里点「开启：停电」「开启：火警」「开启：系统故障」或「开启：暴雨」。
2. 出现「确认开启「…」？每个人的手机上会马上出现清单。」，点「确认开启」。
3. 卡片写影响（暂存里的冷藏框、冷冻框，后仓冷链箱，接下来两小时要取的订单）和完整清单。每个人在自己手机顶部勾自己岗位的步骤。
4. 有顾客通知草稿时可以点「复制」（火警没有草稿）。
5. 处理完点「结束，生成时间线」。上一次的记录可以展开看时间线。

### 4.6 召回

1. 「AI → 现场」的「召回」里，把公开的召回通知粘贴到「召回通知的文字」，点「识别」。演示里可以点「演示：生成一条召回通知」。
2. 看抽出来的商品、条码、批号、日期和原因，勾选匹配到的商品。条码一致、名字全部对上的默认勾上；拿不准时宁可多选。
3. 点「确认 N 件商品，开始召回」。后仓的箱子马上转待检，线上拣货不能再拣这些商品。
4. 按五个步骤处理并打勾：「货架下架」「后仓的箱子转待检」「暂存和推车上的框拿出来」「未完成的订单换替代或标缺货」「通知已经取走的顾客」。开启时已经做了、或没有要做的步骤自动打勾，写「开启时已处理或没有要做的」。
   - 「要拿出来的框（N）」列出订单、在哪个格位或推车上、有哪些商品。
   - 「顾客通知草稿（确认后再发）」可以逐条复制。
5. 五步都做完以后，点「全部处理完，关闭召回」。

只召回部分批号时：「货架下架」打勾后，货架上剩下的别的批号可以照常拣；货架上没有批次记录的商品，系统给补货员派「召回下架后数一下」。交付时只拦货架下架之前拣进框的召回商品。

### 4.7 食品安全记录

「AI → 现场」最下面是「食品安全记录」。选日期，看每台温控设备的最低、平均、最高温度，越线分钟，当天的告警和报修。核对后可以写「说明（可选）」，点「确认这一天的记录」。读数来自数字孪生的遥测，只保留最近一段。

### 4.8 设备报修

1. 在手机顶部的告警条里点「确认，我来处理」。
2. 需要维修时点「报修」。这台设备管着的暂存格位暂停放新框，往里放会被拒绝。
3. 修好后，在「报修单」里选「实际故障」（「压缩机」「门封」「传感器」「除霜」「其他」「没发现问题」），点「修好了，关单」。

告警还在时，「报修单」在告警条里；告警解除以后（或者 AI 没有告警就开了报修单），手机顶部显示「报修单（N）」，点开就能关单。控制台的「设备与告警」里也能关。

### 4.9 运行模式和模型

- **「模式与统计」**：每个 AI 模块可以设成「只显示」「需确认」「自动执行」，并写出发出多少条、采纳率和否决原因。控制台可以「锁定」某个模块，锁定后只有控制台能改。涉及人、钱、顾客的动作即使设成自动执行也要人确认；连续不准的模块会自动降成只显示。核对货架和盘点默认自动执行，只给补货员和后仓派任务。这一页上面还有提醒的统计。
- **「模型」**：每个模型的当前版本、训练数据和回测指标。可以「立即预测」「重新训练」「用较弱的模型测试上线检查」「回滚订单量模型」。

### 4.10 问答和门店经验

带班负责人在「AI → 问答」里用，其他人在「更多 → 问助手 → 打开本地助手与门店经验」里用。
- 在输入框里问门店的情况、商品、人员、操作规范，或「如果……会怎样」，点「提问」。回答写出数据出处，可以标「有用」「没用」。
- 「门店经验」里可以写下现场的做法（例如某个商品其实放在端架），点「记下这条经验」。助手回答问题时会用到。

## 5. 演示控制台

演示控制台代替订单平台、顾客和司机。登录页点「演示控制台（订单平台 / 顾客 / 司机）」进入；展示页左栏的「控制台」就是它。顶部可以在「演示控制台」和「AI」之间切换，上面一排是订单、拣货批次、已暂存、等待中、已完成的数字。控制台页上也有「门店设置」卡片（见 [2.4](#24-门店设置)）。

### 5.1 创建测试订单

1. 在「创建测试订单」里选「类型」（自取或配送）、「张数」、「每单最多商品行」。
2. 「立即锁单并生成拣货批次」默认勾着。门店开了对应模块时还可以勾「每单加一份熟食现做」「每单加一件大件（2 件）」。
3. 点「创建」。取货时段是现在加 40 分钟。被拒的单会跳过，其余接着建，提示「已创建 N 张订单，M 张被拒：原因」。
4. 每张订单的取货码显示在订单表的「验证码」一列，相当于顾客手机上的取货码，只存在这台浏览器里。

### 5.2 代替顾客和司机

**「进行中的订单（N）」**表里每行的按钮：「锁单」（还没锁单的订单）；自取订单才有的「我在路上」（顾客上报 4 分钟后到）和「到店」（顾客到店签到，带车位）；「取消」（没有确认）。表格上方有「生成拣货批次」「排程一次」；有自动运营的订单时可以勾「显示自动运营的订单（N）」。

**「配送行程（N）」**里每个行程依次点「司机接单」（生成司机的验证码，显示为「司机验证码 XXXX」）、「预计 15 分钟后到店」、「司机到店」。「司机取消接单」只在允许的时间里能点，旁边写还要等多久或为什么不能取消。司机超时没来时出现「司机没来，改派」。

### 5.3 设备与告警

「设备与告警」卡片显示孪生健康度、每台设备的读数和状态，以及未解除的告警（可以「确认，我来处理」和「报修」）。

制造故障，看告警怎样传到手机和孪生：

| 按钮 | 读数怎么变 | 结果（演示门店） |
|---|---|---|
| 「暂存冷藏柜故障」「暂存冷冻柜故障」「冷藏库故障」 | 温度一直往上升 | 约 1 分钟到严重线，立即告警 |
| 「卸货门没关」 | 门一直开着 | 2 分钟后提醒 |
| 「传感器断线」 | 不再上报 | 2 分钟后告警 |
| 「暂存冷藏柜制冷慢慢变差」「冷藏库门封漏气」「暂存冷冻柜读数卡住」 | 设备慢慢变坏 | 看 AI 能不能在越线之前发出报修建议 |

「全部修复」后读数慢慢回到设定值，告警自动解除。下面的「报修单」里可以选实际故障后关单。

### 5.4 后仓补货和包裹

**「后仓与补货」**：
- 「发送到货通知（ASN）」：给后仓没货、卖得快的商品发一张到货通知，预计 30 分钟后到。「供应商通知晚到 25 分钟」改最近一张还没到的收货单。
- 选速度（30×、120×、600×）后点「开始顾客购物仿真」：店里开始卖货，货架存量随之减少，配了传感器的货位上报读数。
- 「自动补货：虚拟补货员按优先级处理补货任务（货架核对仍由员工去做）」。
- 「让这个商品的货架变空」选一个商品，可以勾「系统不知道（放错位置 / 损耗），等拣货员或传感器发现」，点「让货架变空」。
- 「打印后仓库位标签」；下面的表格列出真实存量和系统估算差得最多的商品。

**「包裹中转」**：「包裹到货通知（8 件 / 2 个行程）」发一批包裹通知；包裹暂存后，每个行程可以点「司机交接」。

### 5.5 自动运营

「自动运营（双线并行）」让虚拟顾客下单、虚拟员工完成拣货、暂存、交付，虚拟司机接走配送行程。
1. 选「每小时订单」（20、40、80、160）和「作业速度」（正常、2×、4×）。
2. 点「开始自动运营」。卡片显示虚拟员工在做什么、完成了多少单。
3. 点「停止自动运营」结束。

自动运营的订单和你的订单分开批次、分开行程，不在员工手机上显示；两条线共用同一个暂存区、货架和门店 AI。

### 5.6 其他

- 「区域管理」：各区域的占用和预警。
- 「实时事件」：员工端的每个操作实时出现在这里。
- 「门店」卡片：「打印暂存格位标签」，以及「清空门店（演示）」（会先确认，清空全部订单和事件）。

## 6. 三维孪生和模拟器

模拟器有两种用法：不连门店时是**规划孪生**，用离散事件仿真跑完一整天，改布局、排班、策略之前先在这里试；连上门店后是**运营孪生**，场景跟着现场作业走。设计见 [07 · 运营模拟器](../07-simulator.md) 和 [14 · 数字孪生](../14-digital-twin.md)。

### 6.1 在规划孪生里跑一天

打开模拟器（http://localhost:5173 ，或演示站点的 `/sim/`）后，它会按当前的门店和策略先仿真一整天（「正在运行第一次仿真…」），之后每次改设置都在后台重算，画面不中断。

**顶栏**：
- 「门店」：「小型店（单层）」「中型店（单层）」「大型店（两层）」「家居建材店」。「策略」：「基线（无专门系统）」「默认档位（服务与安全优先）」「效率优先档位」。
- 「AI」开关（默认开）：按订单预测排班（总工时不变）、修正顾客到店时间、替代推荐。
- 视角「2.5D」「3D」「俯视」；多层门店可以选楼层；建筑「内部」「半剖」「外观」。
- 「叠加层」：「温区」「拣货热度」「货架存量」「区域占用」「无」。「画质」：「高」「中」「低」。
- 「导览」「巡游」、「中文」/「EN」、「编辑布局」。手机宽度时这些都收在「设置」里。

**底部时间轴**：点 ▶ 播放（空格键也可以），倍速 1×、10×、60×、300×、900×（`[` 和 `]` 也能调），拖动滑块跳到任意时刻。时间轴延伸到第二天开门，可以看到夜班补货。

**镜头和查看**：滚轮朝光标缩放，WASD 或方向键平移，Q / E 旋转，R / F 俯仰；1 / 2 / 3 切换视角，B 切换建筑查看方式，G 跟随选中的员工或车辆，M 小地图，H 复位，? 打开快捷键说明。点场景里的员工、通道、车辆会弹出浮动卡片；右键有常用操作。

### 6.2 实时数据和情景注入

「实时数据」标签：
- 当前时刻的指标卡片（例如平均等待、未按时就绪、满足率、超重框、门口停留、拣货效率），以及全天曲线（交付进度、正在等待的车辆、平均到店等待、暂存占用率、岗位利用率、累计拣货件数），播放到哪里画到哪里。
- 「岗位排班 · HH:00 这一小时」：每个岗位点 − 或 ＋ 调人数，从当前小时生效，后台约 0.1 秒重算这一天。
- 「情景注入」：「订单高峰 +30%」「拣货员请假 1 人」「恢复默认」；还可以选「天气」「季节」「星期」「道路拥堵」。
- 「突发状况」：打开或关闭随机小状况、随机大事件，或者选一个大事件点「现在触发」。
- 「货架存量模型」「夜班补货组」和学生兼职工的开关。

改派某一个员工：点这个员工，在卡片里的「改派（从当前小时起）」里选岗位；或者右键选「改派到…（从当前小时起）」。

### 6.3 策略对比

「策略对比」标签在后台用同一门店、同一订单流、同一排班把三种策略各跑一遍，表格列出差值（好坏用颜色标出），下面是叠加的曲线。点「切换到…」让场景播放那种策略。这是单次仿真；统计显著性见 [06 · Phase 1 成果](../06-phase1-results.md) 的 30 次重复实验。

### 6.4 方案与报告

1. 在「方案与报告」里填「方案名称」，点「保存为方案」。方案保存当前的全部设置、这一天的结果和画面缩略图，存在本机浏览器里。
2. 「已保存的方案（N）」里，「设为 A」「设为 B」两个方案并排对比；「载入」把方案的设置应用到模拟器；「删除」。
3. 「连续多天模拟」：选 7、14 或 30 天，每天换一组订单，看平均、P10、中位数、P90。
4. 经营账：粗略的每天净额，单价可以调。合计不含店内销售，通常是负数，比较方案时看差值。
5. 「导出 HTML 报告」或「导出 Markdown」；「下载当前画面（PNG）」。

### 6.5 门店定制

1. 点顶栏的「编辑布局」或「门店定制」标签进入编辑。仿真不暂停。
2. 「⬚ 选择」：点通道选中，Shift 或 ⌘ 点选多选，按住拖动一起移动。「＋ 画通道」（N）在地面上拖出一条通道。还有「旋转 90°」（T）、「复制」「粘贴」「复制到旁边」「等距排列」「全选本层」「删除」。
3. 每次修改先校验，通过后约 0.4 秒自动应用；有问题时列出来，并保留最后一次通过校验的布局。
4. 「↶ 撤销」「↷ 重做」（⌘Z / ⇧⌘Z，最多 50 步）。「完成编辑」保留当前布局，「撤销全部修改」回到进入编辑前。

同一个标签里还有：「门店生成器」（预设规模、逐项调整，或「🎲 随机门店」，然后「生成并应用」）、「周边环境」、「后仓与暂存仓」、「营业时间与停车场」、「附属设施」、「卸货场」、「区域与卸货门」、「取货车位」，以及「导出 JSON」「导入 JSON」。编辑时场景里的彩色把手可以拖动顾客入口、交付门口、电梯和扶梯、暂存区。

### 6.6 AI 建议

模拟器的「AI 建议」标签按当前方案的仿真结果找问题（到货与卸货场、后仓与补货、线上订单暂存、前场、异常与风险），再换另外几天看会不会反复出现，能执行的办法先在方案上试一遍。
- 每条写做什么、为什么、「预计效果」、「把握」。
- 「采纳」把改动应用到方案上并重新仿真，可以「撤销」；「忽略」时选一个原因；「定位」跳到相关的时刻和地方。
- 上面还有今日计划、交接班小结和「生成 AI 排班」；「采纳 / 不采纳对比」把同一天按采纳和不采纳各跑一遍。
- 方案改了以后点「重新分析」。

### 6.7 导览和巡游

- 「导览」：12 步介绍，每步移动镜头、圈出界面上的对应区域。「上一步」「下一步」「完成」，Esc 退出。第一次打开时左上角出现「第一次来？」，可以选「开始导览」「自动巡游」或「不用了」。
- 「巡游」：切到 3D、30 倍速，镜头在门店全景、取货车位、拣货员、暂存区、后仓、路口、俯瞰之间循环，每个镜头约 10 秒。适合录演示视频。Esc 或点击画面退出。

### 6.8 运营孪生

1. 先用 `npm run server` 启动后端（见 [1.2](#12-三种运行方式)）。
2. 在模拟器的「数字孪生」标签里，「后端地址」填 `http://localhost:8787`（或局域网地址；HTTPS 方式填 https 地址，先在同一个浏览器里打开一次这个地址接受证书），点「连接」。
3. 勾上「场景只显示实时数据（隐藏仿真的员工、顾客和车辆）」。员工显示在最近一次扫描的位置，暂存格位里的框来自实时状态，到店顾客的车停在签到的取货车位上，设备牌显示读数。
4. 面板里有今日订单、等待中的顾客、平均等待、拣货批次、暂存占用、交付看板、货架与补货、在岗人员、AI 建议（在员工端「AI」页处理）和实时事件。点「断开」结束连接。

- 展示页里的数字孪生自动连上浏览器里的门店。那里没有数据面板，点场景右上角的「孪生面板」看同样的内容。
- 场景里的位置按货位和格位编码对应，门店布局要和后端一致（演示后端用中型店模板）。

### 6.9 回放和推演

连上门店后，场景底部是孪生时间轴：左边是过去，中间是现在，右边是未来 3 小时。告警发生的时刻在轨道上标成红点。
- **回放**：往左拖，或点「◀ 回放」。场景回到那一刻（员工、暂存框、到店车辆、卸货门、温度），上方写「回放 HH:MM」和当时的订单数、等待的顾客和设备告警。
- **实时**：点「实时」或「回到实时」。拖回现在附近也会自动回到实时。
- **推演**：往右拖，或点「推演 ▶」。上方写「推演 HH:MM（+N 分钟）」和预计等候的顾客、待交付单数、拣货积压、赶不上时段的单数。
- **试方案**：「数字孪生」面板的「推演」里有「试一试」：「+1 拣货员」「+1 交付员」「交付员调去拣货」「少 1 名拣货员」，和现状并排比较，并列出可能赶不上取货时段的订单。面板写明用的是「今天实测」还是「默认」的速度。

推演回答「照现在的人手和单量，接下来几个小时会怎样」。改布局、策略、排班这种长期的问题，用规划孪生的全天仿真。

### 6.10 孪生里的设备和告警

- 「孪生健康度：孪生和现场对得上多少」：从 100 分开始，按同步、数据源、传感器、账实一致扣分。
- 「设备与传感器」：每台设备的读数和状态；点一行，镜头对准这台设备。
- 「设备告警」：未解除的告警和影响。场景里告警设备脚下一圈红环，所在区域闪红。

试一遍：控制台点「暂存冷藏柜故障」，约 1 分钟后孪生里的设备牌变红，告警带着影响推到带班负责人的手机上；带班负责人点「确认，我来处理」；控制台点「全部修复」，读数恢复后告警自动解除。

### 6.11 你的商店

从一块空地搭建自己门店的孪生，然后像模板门店一样仿真和运营。门店保存在这台电脑的浏览器里，数量不限。

1. 点顶栏的「你的商店」（或者在模拟器地址后面加 `?yours`）进入项目页，点「新建门店」。
2. 填名称，选行业（超市 / 家居建材），拖动建筑宽度和进深（下面显示一楼占地），选楼层和暂存区规模，填卸货门、线上取货车位和营业时间，勾附属设施（汽车快修、园艺中心、药房），点「生成并开始搭建」。系统按占地找最接近的通道数和货架段数，生成一家能运行的门店，直接进入编辑器。
3. 顶栏下方是项目栏：可以改门店名称；「搭建步骤」直达编辑器的对应部分（卖场货架、后仓与收货区域、暂存、设施、停车与营业时间、场地环境）；修改会自动保存。
4. 「开业检查」列出要先解决的问题和建议：缺少的区域、冷藏库和冷冻库、暂存格位和取货车位在高峰时够不够（按日订单量估算）、卸货门和冷藏门、后仓托盘位、营业时间。
5. 「完成搭建，跑全天仿真」：用这家门店跑一整天，数据面板、策略对比、方案与报告都能用。
6. 「实时沙盒」：在新标签页打开展示页，浏览器里的门店中枢按这家门店建店，控制台、两部手机和数字孪生都连到它，可以下单、拣货、交付。
7. 「我的门店」回到项目页。每张门店卡片有「搭建」「全天仿真」「实时沙盒」「导出」（下载 `.storewright.json` 文件）「复制」「删除」（再点「确认删除」）；「导入门店文件」把导出的文件导回来，换电脑或换浏览器时用。

- 门店只保存在这个浏览器里，清除浏览器数据会删掉它们；想留的门店先导出。
- 搭建的门店也是合成的演示数据，仿真结果用来比较方案，不是运营方案。

## 7. 常见问题

**点了按钮被拒，提示「门店要求扫码：请扫描标签或条码，不能点选代替」。**
门店打开了「要求扫码」。用扫码枪、摄像头或手动输入扫标签和条码。演示和培训时，可以请带班负责人在「更多 → 门店设置」里关掉。

**拣货卡片上没有「已拣到 N 件」按钮，或者按钮是灰的。**
门店要求扫码时没有这个按钮，要扫商品条码。按钮是灰的、卡片上有红色横幅时，这件商品在召回，按「找不到」处理。

**列表里没有我要的批次、订单或任务。**
- 自动运营的订单、批次和行程由虚拟员工处理，不在员工手机上显示。
- 别人领走的批次和任务会从列表里消失；你手上已经有一个批次时不能再领（「你还有一个进行中的批次（…）」）。
- 后仓补取只给有永久授权的人（其他人看到「需要永久授权」）；「AI」页只有带班负责人有；「扩展」页要门店开了模块才有，家居建材店没有熟食。
- 「下一步」只在你手上没活、最该做的事不在当前页面时出现，带班负责人不显示。

**交付时开始不了准备。**
看提示：订单还没全部暂存；门店设成顾客到了才能开始，而顾客没到；配送订单要等行程成行后按行程一起准备（「配送订单要等行程成行后一起准备」）；或者别人正在准备，可以点「加入协助」。

**核验验证码时提示顾客还没到。**
核验要先签到。顾客直接走到柜台时，点「顾客已到（店员签到）」（行程是「司机已到（店员签到）」）。

**取货码输错好几次，会不会锁住？**
不会。可以一直重输，错 3 次后多一个「已人工核验」，核对证件和订单信息后点它。

**做错了怎么退回？**

| 情况 | 怎么做 |
|---|---|
| 领了批次还没开始拣 | 「放弃这个批次」 |
| 已经开始拣，做不完 | 「剩下的转给别人（休息、下班）」 |
| 想先拣别的行 | 「跳过这一行，最后再拣」 |
| 框放错格位 | 再扫这个框和正确的格位，就是换格位 |
| 交付准备开始错了 | 「放回暂存，结束准备」→「确认结束」 |
| 补货、补取、盘点、大件不想做 | 「放回队列」「整批放回队列」或「放回」 |
| 退货扫错 | 「扫错了，删掉这一行」 |
| 调错人 | 「回到…」或「取消排队」 |
| 排班草稿改错 | 发布前随便改；发布后重新生成草稿，点「用这份草稿替换已发布的排班」 |
| AI 建议 | 涉及人、钱、顾客的动作执行后撤不回，所以多一步「确认执行」，在那一步点「取消」 |

撤不回的：突发状况清单打勾后不能取消；收货单关闭后不能再收；控制台取消订单没有确认。

**被调到别的岗位，手机却没切页。**
你手上还有任务。调动先排队，提示「带班负责人安排你做完手上的就去…」，做完手上的再去。

**为什么没收到提醒？**
每人每小时最多 3 条非紧急提醒（到店提醒不算），正在交付时和夜里先不打扰，同类的会合成一条。紧急的马上发。「只显示」模式的建议不发提醒（紧急的除外）。

**AI 建议点了「有用」，什么都没发生。**
这个模块是「只显示」，「有用」只记下反馈。要执行，到「模式与统计」改成「需确认」。

**AI 建议卡片写「已过时」。**
情况已经变了（人已经调过去、订单已经交付），动作做不了。点「收起」，或者等系统自动收起。

**框放不进这个格位。**
看提示：温区不对；格位满了；自取订单放到了配送区（或反过来）；格位所在的冷柜在报修，换同温区的其他格位。

**告警解除以后，报修单在哪里关？**
带班负责人的手机顶部会显示「报修单（N）」，点开后选实际故障，点「修好了，关单」。控制台的「设备与告警」里也能关。

**手机摄像头打不开。**
摄像头需要 HTTPS 或 localhost。手机通过局域网 http 地址访问时打不开，用扫码枪或手动输入，或者用 `HTTPS=1 npm run server` 启动后端。

**演示数据去哪了？怎么从头开始？**
浏览器内演示的数据只在这个浏览器里，12 小时没有操作时自动清空作业数据。展示页的「重置演示门店」或控制台的「清空门店（演示）」可以手动清空。

**开了两个标签页，数据不同步。**
有些浏览器不支持 SharedWorker（较旧的手机浏览器、部分 App 内置浏览器），每个页面用自己的门店，页面上会写明。想看多部设备同步，用展示页，它一个页面里同时有控制台、手机和模拟器。

## 8. 术语表

| 术语 | 意思 |
|---|---|
| 批次 | 一次拣货的任务，一辆拣货车同时拣几张订单的几个框 |
| 框 | 装订单商品的取货框，按温区分开；框标签上的二维码对应这个框 |
| 格位 | 暂存区里放框的位置，有格位标签，按温区分；分自取区和配送区 |
| 货位 | 货架上商品的位置：通道、货架段、层 |
| 库位 | 后仓放箱子的位置，有库位标签 |
| 箱 | 后仓的一箱商品，收货时打箱标签 |
| 锁单 | 订单不能再改，系统分框、准备生成批次；默认在取货时段开始前 120 分钟 |
| 取货时段 | 顾客约好来取或送达的时间段，默认 60 分钟 |
| 短号 | 订单的 4 位短编号，交付时可以输入它打开订单 |
| 验证码、取货码 | 顾客或司机出示的码，交付前核验 |
| 冷链计时 | 冷藏、冷冻商品从第一件放进框到框放进暂存区的时限 |
| 暂存 | 拣完的框放进格位，等顾客或司机来 |
| 回收专区 | 放取消订单的框的地方，每个温区一个 |
| 交付准备 | 从开始准备到完成交付的过程，锁定给开始的人，别人可以加入协助 |
| 交付看板 | 交付页上的订单和行程列表，按到店状态变色 |
| 店员签到 | 顾客或司机没在手机上签到时，交付员代为签到 |
| 人工核验 | 取货码错 3 次后，核对证件和订单信息代替取货码 |
| 行程 | 几张配送订单组成的一趟，司机一次接走 |
| 车内位置 | 配送交接时每单放在车里的位置 |
| 后仓补取 | 货架上找不到时，从后仓取货送到订单的框里；要永久授权 |
| 补货 | 从后仓取箱补到货架上；同一通道、一辆推车装得下的任务合成一批 |
| 核对货架 | 到货位数一数实际有几件，修正系统估算 |
| 顺手数一下 | 拣货员路过时顺便核对一件商品 |
| 批次任务 | 按批号做的货架任务：贴折扣签、拿下来捐赠、下架过期、退货放回 |
| 盘点 | 数后仓某个库位里的箱子；盲盘，不显示系统数量 |
| 到货通知（ASN） | 供应商事先发来的到货清单 |
| 送货单 | 卡车带来的单据，有二维码时可以扫码比对 |
| 待检 | 有问题的箱子先放的状态，检验后转可售、退供应商或报废 |
| 整托上架 | 先扫一托的几箱，再扫一个库位，一起放进去 |
| 熟食现做 | 订单里要现做的熟食，做好放进保温位 |
| 保温位 | 熟食做好后放的位置，一个位放一份，超时自动丢弃 |
| 大件 | 太重或放不进框的商品，按件处理，先扫后打标签，放在大件区 |
| 包裹中转 | 承运商的包裹在门店入站、暂存，再交给司机 |
| 去向 | 退货商品的处理方式：可售回架、报废、危险品回收、退供应商 |
| 召回 | 按公开召回通知下架、拦截、通知顾客的处理流程，五步做完才能关闭 |
| 突发状况 | 停电、火警、系统故障、暴雨时按岗位分好的清单 |
| 食品安全记录 | 每台温控设备一天的温度、越线、告警和报修 |
| 报修单 | 设备的维修记录；开着时这台设备管着的格位暂停放新框 |
| 带班负责人 | 当班的负责人，有 AI 页，能调人、改门店设置 |
| 在岗人员 | 顶栏 👥 打开的面板：谁在哪个岗位、在做什么 |
| 临时调动 | 带班负责人把人调到别的岗位一段时间，到时间自动回去 |
| 排队的调动 | 手上有任务的人做完这一单再去新岗位 |
| 固定名单 | AI 不会建议调动的人 |
| 下一步 | 手上没活时系统推荐的下一件事 |
| 提醒 | 顶栏 🔔 里的通知，AI 决定发给谁、什么时候发 |
| 只显示、需确认、自动执行 | AI 模块的三种运行模式 |
| 时段产能 | 每个取货时段还能接多少单 |
| 排班草稿 | AI 生成、可以手动改的一周排班，发布后生效 |
| 补班邀请 | 有人缺勤时发给其他人的邀请，本人接受后生效 |

| 孪生健康度 | 孪生和现场对得上多少的分数 |
